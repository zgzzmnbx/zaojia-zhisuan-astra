# H1 办公室 · 白瓷与七种主题蓝

从 Astra 工作台打开 **多人复核**。左上角的大楼和叠层图标切换整楼与展开九楼，旁边的放大镜调整缩放。打开 **更多操作** 可俯视或重置视角。点左上角齿轮进入 **办公室沙盘设置**。滑杆图标打开右侧 **现场调节**，可以一边调工位、外观，一边查看模型。

工位及人物来自项目的员工配置。当前成果、可发送的复核对象、选人状态和回执由工作台传入。直接打开查看器可以查看项目已保存的员工与工位。离线建模与几何核对使用上游楼层作参照。

右侧 **人员** 页在姓名下显示当前任务，有待办者在前。**任务** 页可展开文件、平台与回执意见，点 **定位同事** 查看工位。两页均可查看其他成果中仍待本人复核的记录，当前成果的已办状态按个人回执显示。旧办公室任务示例和勘察测量限价案例各自保留分配，带有「示例」标签。实际待办与示例分别计数。上方的成果投放卡只操作当前成果。

**人员任务** 管理沙盘待办，人物详情上的 **编辑此人任务** 直接打开该同事。**人员资料** 管理姓名、性别、工种、擅长审核与新同事。**镜头环游** 的空闲等待、速度和加速度保存在此浏览器。

**聊天联动** 默认关闭。填写完整群名或群 ID，打开 **显示聊天气泡** 并点 **保存聊天设置**。WeAct 预填「智算测试」并识别群成员石萌，飞书识别大尾巴。展开九楼后，新发普通文字会显示在石萌头顶。群名留空会停用该来源。两个来源都复用宿主已有平台凭证，独立读取指定群的近期消息。聊天正文仅在内存中短时使用，开关和群名保存在运行副本的 `config/office-chat.json`。

**现场调节 → 建筑外观** 可调整主题蓝、九楼景深、光照和车辆。**现场调节 → 人员工位** 可点选座位、预览人物扮相并保存。

人员任务支持改名、改状态、备注、移除以及从 **已移除** 恢复。点 **收起 N 条** 预览每个项目仅显示最新一条待复核的效果，点 **保存修改** 后才生效。任务配置存放在当前运行副本的 `config/office-task-settings.json`，按人员和复核轮次识别记录。智算任务及平台回执由原业务流程维护。

**更多操作 → 交接预演** 单独打开九楼大会议室。点蓝色资料夹或 **演示交接**，看编制人走到桌边，把资料夹交给复核人。场景使用两个示例角色；真人复核通过主工作台发起。

## 日景白模

屋顶用象牙白，迎光立面用瓷白，背光面用浅蓝白，挑檐底部再压深一档。每个外墙平面只有一个色值，窄窗框与倒角交代厚度。楼脚和屋顶设备沿同一方向投影，重叠部分只取较深的一层。室内隔墙使用单独的明暗范围，展开时仍然能分辨各个房间。

v0.6.0 与 v0.5.0 使用相同相机、曝光与钴蓝主题对比。附楼背光墙面从 RGB(152,157,168) 调为 RGB(206,219,239)，迎光面由 RGB(176,183,197) 调为 RGB(236,242,248)。这两个版本的 2,502 个节点变换和 263,188 个三角形逐项一致。夜间实体沿用原烘焙光照，招牌、窗灯和园区路灯保持各自的设置。

v0.6.0 的主模型为 13.59 MB。本机 Intel Arc B390、Chromium、1440 × 900、DPR 1，车辆行驶时连续拖动约 4.1 秒。整楼与展开九楼的日夜帧率约 60 FPS，四个视角的绘制调用均与 v0.5.0 相同。该版运行包的 `验收/` 中附整楼、屋顶设备的同机位对照图及实测数据。

## 建筑招牌

v0.6.1 的屋顶采用沿正面檐口居中排列的集团徽标与「国家管网」四个立体字。字标厚 0.13 米，五处细金属支脚固定在女儿墙顶。笔画和徽纹之间可见后方屋面，屋面上的阴影取自实际笔画。徽标与字共用一个网格和一种材质，主模型为 14.19 MB。

入口雨棚上方使用原有横向门楣。两处白天显示红标黑字，夜间徽标与字面使用 Astra 品牌灯预设的荧光蓝 #85D0FF。「画面设置」中的「灯光辉光」控制光晕。

## 园区道路

9 盏细杆路灯沿入口与园区步道布置，夜里向路面投下暖白光。一辆白色轿车和一辆蓝色两厢车沿门前的落客车道和回程车道低速循环，转弯、接近斑马线时减速。轮廓和车底阴影跟随车身行进，另外三辆停在侧路和楼后。

在 **现场调节 → 建筑外观 → 园区车辆行驶** 可暂停或恢复，点 **保存参数** 记住选择。首次打开时遵循系统的减少动态效果偏好。标签页、宿主沙盘或画布隐藏后车辆停算，返回时从原地继续。

v0.5.0 的主模型为 12.70 MB。在本机 Intel Arc B390、Chromium、1440 × 900、DPR 1 下，两辆车行驶时连续拖动视角约 4.1 秒，整楼与展开九楼的日夜四个场景均约为 60 FPS。运行包的 `验收/` 内附入口及楼顶日夜对照图、车辆动图和实测数据。

v0.4.0 的五辆车均为停放状态。该版灯杆、车身和灯罩下的发光片合计两个绘制批次，使用一张 256 × 256 双通道照度与接触阴影贴图。该版 GLB 为 13.12 MB，与 v0.3.1 同机位相比整楼每帧增加 2 次绘制和 7,796 个三角形。

v0.4.0 在本机 Intel Arc B390、Chromium、1440 × 900、DPR 1 下持续拖动约 4.1 秒。整楼日景和夜景均为 59.9 FPS，展开九楼并使用默认 45% 虚化时，日景为 59.1 FPS，夜景为 59.8 FPS。

## 园区夜景

园区 23 棵树共用一个植被绘制批次。低饱和的灰绿树冠与灰棕树干接受冷色环境光，暗部沿用模型中烘焙的遮蔽。树木的自发光为零。窗带、标识和办公室屏幕继续使用各自的夜间灯光。

v0.3.1 与 v0.3.0 相比，全场三角形、白天顶点颜色与三张内嵌贴图逐项一致。入口同机位的日景画布像素一致，夜景实测整楼多 1 次绘制。已检查整楼、展开九楼、七种主题蓝，以及景深和辉光开关。v0.3.1 模型为 12.59 MB。

## 展开9楼与背景虚化

九楼的房间、桌椅和人物保持清晰，其余楼层和园区按与九楼的景深距离虚化。打开 **现场调节 → 建筑外观 → 九楼背景虚化** 可实时调整 0–100%，默认 20%。调至 0% 可看清周围建筑，点 **保存参数** 可在此浏览器记住选择。整楼使用清晰全景。

展开时楼体与镜头在 1.05 秒内就位。这段画面保持清晰，停稳 0.24 秒后，背景在 0.9 秒内逐渐虚化到滑块选定的强度。收回时先用最多 0.16 秒淡出已有虚化，再移动楼体。托盘沿原轨迹向前 32 米、抬高 3 米，上方楼层抬高 18 米。背景色和夜间发光在低分辨率下柔化，完整分辨率的深度保留楼层之间的实际遮挡。九楼顶盖在归位时闭合。旧九楼链接、嵌入指令、房间和人员入口统一进入展开视角。

在 1440 × 900 和 1024 × 768 两种窗口下，分别从 v0.2.0 提交 8005f19 加载原查看器，同步采样展开和收回各 6 个时刻。两版托盘四角的屏幕偏差均小于 0.1 像素。另在 8 个过渡画面逐像素比对遮挡，九楼可见区域与直接深度渲染一致。鼠标悬停、离开、点击固定和中途反向均按同一轨迹运行。

v0.3.0 本机 Intel Arc B390、Chromium、1440 × 900、DPR 1，5 名模拟人员。持续拖动 4.1 秒，展开九楼日景测得 53.3 FPS、夜景 59.8 FPS。整楼白天和夜间均约 60 FPS。隐藏后停止绘制，返回整楼或关闭虚化后释放景深缓冲。

## 主题蓝

**现场调节 → 建筑外观 → 主题蓝** 提供钴蓝、冰川蓝、晴空蓝、湖蓝、群青蓝、钢蓝、海军蓝。首次进入使用钴蓝。点选色样或用键盘选择后，当前视角即时换色，刷新后自动恢复。偏好保存在当前浏览器和预览地址，工位配置由“人员工位”单独管理。

窗带、桌椅、树冠和园区蓝色饰件在建模时标记了三档蓝色颜料。每次切换只更新着色器参数，保留白瓷、人物本色和贴图的光影。夜景的窗光与屏幕随主题变色，两块国家管网招牌使用固定的品牌灯色。

浏览器在整楼日景、九楼日景、整楼夜景、九楼夜景分别实测七种配色，共 28 次切换仅加载一次 GLB。每种配色都产生了不同的实际画面，原视角和模型实例全程保留。另用隔离的浏览器验证了点选、键盘选择、刷新记忆、原版对照返回和禁用存储后的当次切色。

## 冻结的平面

以 `models/H1-baked-v0.6.7.glb` 和 `data/office_layout.json` 为依据。生成前校验两份原件的 SHA-256，再逐节点核对九楼结构、家具、元数据、本地及世界变换、顶点、法线和三角索引，并逐层核对 20 层的变换。

| 核对对象 | 结果 |
| --- | --- |
| 九楼几何 | 2,405 个节点，155,460 个三角形，逐项一致 |
| 布局数据 | 82 段墙、29 处门洞、15 根柱、77 个工位锚点 |
| 复核区返岗仿真 | 67 个可分配工位全部到达，428 个复核区出口落点检查通过 |

## 渲染与实测

整楼关闭时跳过被楼板遮挡的九楼家具，展开后恢复其显示和交互。外墙、窗带和设备按层合并。场地和屋顶设备使用离线生成的投影，建筑分面色写入模型的标准顶点色。夜景从独立的顶点属性读取 Blender 烘焙结果，办公室灯光另有贴图。

v0.2.0 的单个 GLB 为 **12.61 MB**。与 v0.1.0 比对，全场 2,504 个节点、2,037 个网格图元的原有顶点、颜色、法线、索引和 UV，以及全部三张内嵌贴图逐项一致。新增的顶点属性记录颜料分组。

本机 Intel Arc B390 / Direct3D 11，Chromium，1440 × 900，DPR 1。这一版以钴蓝、湖蓝、冰川蓝和海军蓝分别持续拖动整楼与九楼约 4.1 秒，均为 59.8–59.9 FPS。整楼每帧 58 次绘制，九楼 158 次。四次首次出画为 1.09–1.65 秒。

## 模型复核与重建

在项目或解压目录根部执行下列命令。核对与重建使用 Python、NumPy、Pillow 和 OpenCV。完整重建还需 Blender，本轮使用 Blender 5.2.2 LTS。Blender 的可执行文件可用 `--blender` 显式指定。

```powershell
python tools/office-twin/porcelain/build.py --verify-only
python tools/office-twin/porcelain/build.py
```

生成器在临时文件中完成烘焙，通过几何核对后写入 `public/office-twin/models/H1-porcelain-v0.6.1.glb`。原始及生成模型、平面和预览图片随本地交付包提供。版本及文件指纹记录在 `public/office-twin/SOURCE.json`。Astra 开发基线为 `6fc00dd`，原型留存在 `codex/office-porcelain-demo-20261118`。改写前的源码已推至 [GitHub 备份分支](https://github.com/zgzzmnbx/zaojia-zhisuan-astra/tree/codex/backup-office-before-porcelain-20261118)。
