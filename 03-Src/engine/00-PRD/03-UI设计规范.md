## 设计系统结构

前端样式使用三层 token 结构：

```text
基础 token：原始颜色、字号、间距、圆角、边框、阴影
语义 token：主色、背景、文本、边框、成功、警告、危险、信息
组件 token：按钮、表格、面板、弹窗、AI Dock、标签、进度条
```

设计系统资产：

```text
frontend/src/design-system/dabawei-shadcn-ui.tokens.json
frontend/src/design-system/dabawei-shadcn-ui.css
01-assets/01-UI参考图/code/大尾巴-Shadcn-UI-组件样张-v1.0.0.html
tools/check_ui_design_system.py
```

- `tokens.json`：W3C DTCG 风格的机器可读三层令牌。
- `dabawei-shadcn-ui.css`：浏览器运行时令牌；`frontend/src/styles.css` 必须优先引入。
- `styles.css` 既有 `--db-*`、`--ink`、`--muted` 等变量作为兼容别名，逐步映射到 `--dws-*`，不得再建立第四层平行主题变量。
- 静态样张：展示颜色、按钮、状态、分段切换、指标、图表、表格和弹窗，用于视觉交接，不承载业务逻辑。
- 自动巡检：校验版本、preset、核心 CSS 令牌、运行时引入和双文档登记。

## 大尾巴 Shadcn UI v1.0.0

### 设计身份

```text
Rhea 的组件比例
+ Neutral 的克制底色
+ Blue 的操作与图表语言
+ Lucide 的统一图标
+ 自托管苹方的中文一致性
+ Navattic 的扁平工作台纪律
+ 造价业务状态语义
```

源 preset：

```text
https://ui.shadcn.com/create?preset=b1au7YYAi&item=preview
```

经 shadcn CLI 确认，preset 为 `Rhea / Neutral / Blue / Blue charts / Lucide / Inter / default radius / subtle menu accent`。其中：

- `Rhea` 决定组件比例、留白、控件密度和克制层级。
- `Neutral + Blue` 决定中性工作台与主操作 / 图表的基础色相。
- `Inter` 只作为英文、数字和控件比例参考；运行时统一使用自托管苹方。
- `Lucide` 是唯一常规界面图标库；不得并行引入第二套风格冲突图标。
- preset 是设计输入，不是运行时在线依赖；现有项目禁止直接执行全量 `shadcn init/create/apply`。

### 优先级

发生冲突时依次执行：

1. 业务真实性、可复核性、无障碍和安全边界。
2. 本文件的语义 token、业务状态色和组件验收口径。
3. `dabawei-shadcn-ui.tokens.json` 与 `dabawei-shadcn-ui.css`。
4. 已通过浏览器验收的生产组件。
5. shadcn preset、Mobbin、Navattic 和其他外部参考。

### 两种使用模式

| 场景 | 使用方式 | 禁止项 |
| --- | --- | --- |
| 现有 React / CSS 项目 | 引入 `dabawei-shadcn-ui.css`，用 `--dws-*` 令牌和局部根类转译现有组件 | 不为视觉统一强装 Tailwind，不全局覆盖标签选择器，不复制第二套主题 |
| 新 React 项目 | 可用 shadcn Rhea / Neutral / Blue 建立组件底座，再覆盖大尾巴字体、token、状态语义和组件规格 | 不把 preset 默认字体、颜色或组件代码视为最终规范 |
| 非 React / 原生网页 | 使用 token JSON / CSS 与组件样张复刻比例和状态 | 不要求依赖 shadcn 运行时 |

### 核心组件目录

| 类别 | 标准组件 | 生产参考 / 验收重点 |
| --- | --- | --- |
| 操作 | Primary / Outline / Ghost / Destructive Button | 高 `30px-34px`，主操作白字深蓝，无常驻阴影，禁用态仍可辨认 |
| 输入 | Input / Select / Checkbox / Search | 高 `34px`，白底细边框，focus 使用 2px 主蓝环，错误有文字与图标 |
| 视图 | Segmented View Switcher | “项目看板｜新建填价”为生产参考；高 `36px`，两项最小宽 `148px` |
| 容器 | Panel / Analysis Card / Empty State | 白底、1px 边框、8px 圆角、无阴影；禁止灰底大卡套白卡 |
| 数据 | Table / KPI / Pagination / Filter Chip | 数字右对齐，状态不只靠颜色，历史表自身承担横向滚动 |
| 浮层 | Dialog / Sheet / Popover / Toast | 必须有标题、关闭和焦点回归；浮层可使用唯一明确阴影 |
| 反馈 | Badge / Alert / Progress / Skeleton | 蓝色表达处理中，绿 / 琥珀 / 红只表达既定业务语义 |
| 图表 | Bar / Line / Area / Donut | 中性分析用多蓝序列；业务正向绿、经验琥珀、风险红不得被蓝色替代 |
| 导航 | Global Nav / Module Rail / Tabs | 轻量选中态，不用高饱和整块填充，不显示无意义序号 |
| AI | Message / Composer / Attachment / Action Row | 助手左侧、用户右侧；输入区固定，动作回显可追溯，不堆蓝色提示卡 |

### 组件状态

每个交互组件至少定义 `default / hover / focus-visible / active / disabled / loading / error`；状态优先级为 `disabled > loading > active > focus > hover > default`。

- 颜色、背景、边框与阴影过渡默认 `150ms ease-in-out`。
- 禁止用缩放或位移制造按钮反馈，避免工作台布局抖动。
- `prefers-reduced-motion` 下取消非必要动画。
- 正常文字对比度不低于 `4.5:1`，大字和 UI 轮廓不低于 `3:1`。
- 不得只用颜色表达状态；必须配合文字、图标、数量或可访问摘要。

### Navattic 极简绝对约束

以下规则优先级高于本文其他组件描述。若后文有冲突，以本节为准。

1. **布局绝对法则：严禁卡片套娃。** 废除“灰底白卡再套白卡”的层级结构。大工作区背景必须使用统一纯白或极浅灰；各功能区之间只用 `1px solid var(--db-border)`、`border-right`、`border-bottom` 或表格线做物理分割。禁止在常驻工作区里用带背景色的大卡片容器继续嵌套小卡片。
2. **视觉绝对法则：常驻界面扁平化。** 除 Dialog / Modal、Dropdown、Toast 这类浮层外，系统内所有常驻面板、左侧栏、右侧栏、表格区、工具条、模块工作区一律 `box-shadow: none`。
3. **导航与交互法则：克制选中态。** 左侧导航激活态禁止高饱和大色块，采用文字加粗加深、极浅灰底或透明底，加 `1px` 细线 / 左侧细条指示。
4. **组件视觉法则：按钮精调。** 主按钮无边框，使用纯深蓝底和白字，圆角 `6px-8px`，padding 足够；次按钮透明或白底，加浅灰边框。所有按钮禁止干瘪，也禁止胶囊化过度。
5. **层级法则：用线和留白表达层级。** 优先通过 `border`、`divider`、字号、字重、间距表达结构，不用阴影、厚背景、重圆角堆层级。
6. **模块导航去编号法则。** 左侧模块导航不显示 `01/02/03` 等数字序号；图标、模块名、说明文字和克制选中态承担导航识别，避免编号造成视觉噪声。

### Navattic 字体与文本渲染绝对约束

为实现 Navattic 级别的现代、内敛和克制感，必须严格遵守以下排版与颜色渲染法则。

1. **绝对禁用纯黑法则。**
   - 严禁在全局任何文本、边框或阴影中使用纯黑色 `#000000`，也不使用传统深灰色 `#333333` / `#333` 作为文字或边框。纯黑在白底上对比过硬，会造成视觉疲劳和廉价感。
   - 页面主标题、强数字、关键强调统一使用 Text-Strong：`#0F172A`，字重 `600` 或 `700`。
   - 正文、表格主体、普通表单统一使用 Text-Base：`#334155`，字重 `400`。
   - 辅助说明、次级标签、占位符统一使用 Text-Muted：`#64748B`，字重 `400`。
2. **字体族基建。**
   - 全局界面使用项目自托管的简体苹方，保证不同操作系统和交付形态的中文、英文与数字保持一致。
   - 全局字体栈固定为：`'Zaojia PingFang SC', 'PingFang SC', 'Microsoft YaHei UI', sans-serif`。
   - 字重映射固定为：准体 `400`、中黑 `500`、中粗 `600/700`；不引入极细、纤细、繁体等界面未使用字重。
3. **抗锯齿渲染。**
   - 必须在全局根节点开启抗锯齿，使字体边缘更纤细锐利。
   - 强制属性：`-webkit-font-smoothing: antialiased;` 和 `-moz-osx-font-smoothing: grayscale;`。
4. **数字等宽对齐。**
   - 表格、金额、行号、统计数字必须使用等宽数字特性，保证上下行数字和小数点垂直对齐。
   - 表格数字列、金额列、统计卡强数字使用：`font-variant-numeric: tabular-nums;`。

| --- | --- | --- |
| `--db-chart-blue-deep` | `#1E40AF` | 选中项、强调项、少量末端分类 |
| `--db-chart-blue-strong` | `#2563EB` | 主序列、环状图主要分段 |

使用规则：

- 标准参考为当前项目处理趋势的分组柱状图，以及项目状态、请求模型种类的环状图。双序列柱状图默认使用 `--db-chart-blue-mid` 与 `--db-chart-blue-pale`；分类环状图从 `strong / base / mid / soft / pale / faint` 中按对比度选取，选中项可切换为 `deep`。
- 适用于中性统计、时间计数、请求次数、模型分类和聚合状态分布；标准命中、经验提示、待复核、高风险、失败等用于裁决或行动的明细图，仍优先使用固定业务状态色。

- `pale / faint / wash` 仅用于图形填充、辅助线和交互浅底，不用于小字号正文。数字标签使用等宽数字，坐标轴、图例和数据标签须达到可读对比度。
- 饼图 / 环状图中心显示总数和单位；柱状图保留序列名称、数值标签或可访问摘要。所有图表都要有可聚焦容器、`aria-label` 或等价文本说明。

#### 字体与字号硬门禁

以上表格是项目界面字号的唯一执行口径，后续组件、弹窗、会话卡片、设置页和局部重构不得自行创建第二套字号范围。大尾巴无需再次提醒，所有前端修改默认先满足本节，再讨论局部视觉细节。

- 可见业务文字不得小于 `12px`。`9px`、`10px` 禁止用于任何标题、正文、标签、状态、按钮、输入项、人员名称或辅助说明；`11px` 只允许用于空间受限的步骤圆点、图表坐标或纯数字技术标记，必须使用 `--dws-font-size-11` 并在局部 CSS 注释原因，不得用于连续中文。
- 新组件优先直接使用 `--dws-font-size-12/13/14/16/20/28` 与 `--dws-font-family-ui`。如需组件内语义别名，只允许映射到上述 token，例如“标题 `16px`、正文与控件 `13px`、辅助说明 `12px`”，不得另造 `9px/10px/15px` 等游离层级。
- 组件根节点统一使用 `font-family: var(--font-body)` 或 `var(--dws-font-family-ui)`；`button / input / select / textarea` 必须继承同一字体家族。禁止浏览器默认表单字体、第三方组件默认字体或局部英文系统字体混入中文界面。
- 同一视觉层级必须同字号、同字重、同行高：并列按钮、同组标签、人员列表、平台折叠页、状态徽标和辅助说明不得因标签类型或父级级联出现忽大忽小。
- 局部组件必须在自身根类下收口字体规则，禁止使用无作用域的 `button`、`small`、`label`、`p` 全局覆盖；也不得用大量 `!important` 掩盖级联冲突。
- 欢迎页首屏可使用 `32px-44px` 品牌标题，但必须限定在欢迎页根作用域；进入专业工作台后，页面标题回到 `28px`、模块标题 `20px`、面板标题 `16px`。

每次新增或调整 UI，交付前必须完成以下检查：

1. 对本次改动的 CSS 执行静态搜索，确认没有新增 `9px/10px` 可见文字，也没有未经说明的 `11px` 或游离字号。
2. 在浏览器运行态抽查标题、标签、分组标题、正文、辅助说明、按钮、表单控件和列表项的 computed `font-family / font-size / font-weight / line-height`。
3. 至少在实际使用宽度截图核对一次；涉及响应式或弹窗时，再核对窄宽度。发现同层级字号不一致必须在交付前修正，不能留给大尾巴再次指出。
4. 运行 `python tools/check_ui_design_system.py`，确保字体 token、UI 规范和项目长期规则仍然一致。

## 基础视觉方向

- 默认风格：浅色专业工作台，克制、干净、可信。
- 主色倾向：深蓝主按钮 + 少量蓝绿 AI 点缀，不继续扩大紫色、咖色、深蓝黑等单一大面积主题。
- 页面质感：无常驻阴影、轻边框、纯白 / 极浅灰背景、明确层级。
- 圆角：工作台组件以 6px-8px 为主；按钮和输入框可使用 8px-12px；避免大块胶囊按钮充满页面。
- 装饰：不使用渐变光球、漂浮背景、过度玻璃拟态和无业务意义的大插画。
- 文案：界面内不堆说明文字，功能靠布局、图标、状态和短标签表达。

- 禁止在一个模块里同时出现多套设置按钮样式。

### 二级分段视图切换器（Segmented View Switcher）

当前“项目看板｜新建填价”组件是生产参考。它用于同一一级模块内 `2-3` 个互斥、同级且需要保留上下文的视图，不用于左侧一级导航、Sheet 标签、筛选 chip 或执行动作。

结构与尺寸：

| 部位 | 规格 |
| --- | --- |
| 容器 | 内容自适应宽度，高 `36px`，内边距 `3px`，项目间距 `2px`，背景 `#F8FAFC`，`1px #EEF2F7` 内描边 |
| 容器圆角 | `10px`；仅此类紧凑组合控件允许外轮廓超过常规 `8px`，不得类推到常驻面板 |
| 分段项 | 高 `30px`，横向内边距 `12px`，圆角 `8px`，字号 `13px`，默认字重 `500` |
| 默认态 | 透明背景，文字 `var(--db-text-muted)` |
| hover | `rgba(255, 255, 255, 0.72)`，文字 `var(--db-text)` |
| 当前项 | 白底，文字 `var(--db-text)`，字重 `500`，`1px #E2E8F0` 描边；可用最大 `0 1px 2px rgba(15, 23, 42, 0.06)` 的控件级微阴影 |
| focus-visible | `2px solid var(--db-primary)`，偏移 `2px` |

行为要求：

- 使用带明确 `aria-label` 的 `nav` 或等价语义容器；当前项使用 `aria-current="page"`，键盘焦点始终可见。
- 视图切换只改变中间内容，不清空当前任务、文件、列映射、Skill、筛选和成果状态；图表视图隐藏时应卸载图表子树，避免零尺寸容器持续计算。
- 颜色和背景过渡使用 `150ms` 左右的标准交互节奏，不缩放、不位移、不产生布局抖动；遵守 `prefers-reduced-motion`。
- 控件保持单行且靠工作区起始侧放置。视图超过 `3` 个时改用二级导航或下拉菜单，不把分段项压缩成难以点击的窄块。
- 上表允许的微阴影只属于当前分段项的交互层级，不改变“常驻面板无阴影”规则。

### 面板与分割

- 页面分区可以是全宽区域或工作台面板，严禁“卡片套卡片”。
- 常驻面板圆角建议 `8px`，边框 `1px solid var(--db-border)`，`box-shadow: none`。
- 大工作区背景必须统一为 `var(--db-bg)` 或 `var(--db-app-bg)`，不得出现灰底白卡、白卡再套白卡的厚层级。
- 常驻模块内部优先使用 `border-top`、`border-right`、`border-bottom`、`divider` 和留白分组，不再给每个段落套独立背景卡。
- 卡片只允许用于真正重复对象列表、弹窗内容块、少量统计指标；不得用于把页面每个功能块都包起来。
- 表格预览窗口可以保留“窗口感”，但内容区域必须足够宽，不做装饰性缩窄。

### 表格

- 表格是主视觉中心，默认占据主区域最大宽度。
- 表头固定或保持可见时，应有清晰底色和分割线。
- 数字列右对齐，文本列左对齐，状态列居中或用标签。
- 数值最多显示 2 位小数。
- 长文本按列宽自动换行，最多显示 2 行，悬浮看完整内容。
- AI 操作列固定在右侧可见位置，不要求用户横向滚到最后。
- 横向滚动条可见但不突兀，不能遮挡表格内容。

### 大尾巴主题表格工具条

- 表格样式可参考 Navattic 表格工作台：轻边框、浅表头、清晰筛选条、筛选 chip、右侧导出 / 排序动作。
- 顶部工具条建议分为：左侧当前 sheet 和行数，中间搜索 / 筛选 / 字段设置，右侧排序 / 导出 / 缩放 / AI 批量复核。
- 筛选条件以 chip 展示，支持关闭和追加，例如 `只看待复核`、`表2`、`技术系数为空`、`隐藏空行已开`。
- 行高建议 42px-52px，既比传统后台舒展，也比 Navattic 更适合造价宽表。
- 第一列可承载主字段 + 次字段；数值列右对齐；状态列用语义色标签。
- AI 操作列必须固定在右侧可见位置。
- 表格底部可保留每页行数、分页、隐藏行计数和匹配摘要，但不要挤压主表格高度。

### Sheet 标签

- 当前 sheet 用主色实底或浅底强调。
- 非当前 sheet 用浅边框 / 浅底。
- 标签高度控制在 32px-36px。
- 标签过多时横向滚动，不能换行挤压表格。

### 设置弹窗

- 弹窗最大高度不超过视口，内部滚动。
- 顶部为标题和关闭按钮，中部为分组表单，底部为保存 / 取消。
- 设置项分组使用短标题，不写长段解释。
- 开关用 switch 或 checkbox，下拉用 select，数值用 input / stepper，不用长文本按钮伪装输入。
- 多类设置使用顶部 Tabs 分区时，一次只呈现一个表单区；标题与 Tabs 固定，内容区独立滚动，底部操作固定。
- 页面设置不得回显本机绝对路径、密钥或运行时标识；只说明“保存在本机运行目录”和生效范围。
- 需要边看页面边微调的工具采用右侧 Sheet，不再使用遮住目标界面的居中大弹窗。

### 智能协同标签工作区

- “协同任务 / 新建派发 / 连接设置 / 通知与记录”属于同一一级模块的四个互斥工作区，使用顶部 Tabs，不把四套长表单同时纵向堆叠。
- Tabs 下方只挂载当前面板；任务列表、派发表单、连接配置和日志继续复用真实业务状态，不因视觉重构复制状态或改变安全闸门。
- 连接状态与运行控制台作为页头摘要，标签切换不清空机器人选择、任务、目录缓存或派发草稿。

### 工作量抓取步骤条

- 固定四步为“上传工作量表 → 确认抓取字段 → 校验目标表 → 执行并复核”，步骤条只表达进度，不替代真实设置或执行按钮。
- 宽工作区使用四列；右侧智算展开或容器不足时按容器宽度改为两列，并允许输入区从双列收敛为单列。
- 工作量源表和目标控制价表是同级工作对象；字段映射可分组，但不得形成横向溢出或多层卡片套娃。

### AI Dock

- 默认宽度 360px 左右，可在设置中调整。
- 收起态只保留窄条入口，不遮挡表格。
- 等待态必须显示阶段：检索依据、整理证据、生成回答。
- 知识库模式需要有明确状态标签，例如“已调用知识库”。
- 行级复核按钮只填入问题或展开助手，由用户手动发送。
- AI Dock 视觉上是“随行复核员”，不能比表格更抢主视觉。

### 大尾巴主题 AI 助手侧栏

- AI 助手可参考 Navattic 右侧抽屉 / 客服面板：独立侧栏、白底、1px 左边框、顶部身份区、固定底部输入框；常驻状态禁止阴影。
- 右侧助手宽度建议 360px-420px；折叠态建议 52px-64px，只保留 AI 图标、风险数量和展开按钮。
- 顶部区域应包含：问问智算标识、当前模式、知识库状态、折叠 / 展开 / 关闭。
- 上下文区应展示当前 sheet、当前行、匹配状态、候选数量、是否调用知识库。
- 快捷操作区应包括：解释当前行、核查数字、生成风险提示、查库、生成报告说明。
- 消息区区分普通问答、知识库问答、行级复核和风险报告，不同模式有明显标签。
- 证据区展示知识库来源、规则命中、经验提示和待复核原因。
- 输入框固定底部，支持快捷 chip 和 `查库：` 前缀。
- Dock 模式下 AI 助手不能只是客服聊天，也不能覆盖主表格；它服务当前表格和当前业务证据。专注模式只有在用户主动进入时才暂时隐藏主表格，退出后无损恢复。

### 智能体专注模式

- 左侧设置独立一级入口“智算助手”，位于专业 Skill 选择器下方、传统业务模块上方；它是 P0 正式入口，菜单文案不使用“全屏化智算助手”等技术形态名称。
- 现有问问智算顶部身份区保留“进入智算助手”快捷动作；它与左侧入口进入同一个会话工作台，不创建第二套消息状态。
- 专注模式不是全屏 Modal：左侧功能导航保留，原中间工作区隐藏但保持 React 状态，同一问问智算会话填满剩余宽度。
- 顶部栏包含当前会话、当前任务、真实执行状态、新建会话和退出专注模式；高度建议 `48px-56px`，不做大标题 Hero。
- 消息主列建议使用 `min(880px, calc(100% - 48px))` 一类可读宽度；文件、进度、风险和成果卡可以使用更宽的受控容器。
- 底部 Composer 固定，包含附件按钮、专业能力选择、任务上下文、多行输入和发送 / 停止；附件、Skill 和发送控件必须有键盘焦点与 `aria-label`。
- 专业能力显示中文名称和版本，`Skill` 作为辅助标签；规划中 / 停用能力不可执行；任务创建后显示锁定状态，切换必须新建任务。
- 普通消息继续左灰右蓝；执行计划、确认、进度、风险、成果和错误作为独立结构化行，不强制包进聊天气泡，也不允许卡片套娃。
- “正在生成回答”和“正在执行专业任务”必须使用不同状态；专业任务只有收到后端任务 ID 和真实阶段后才能显示已开始或已完成。
- `Esc` 退出专注模式，`Enter` 发送，`Shift+Enter` 换行；存在输入草稿、附件或待确认动作时不得误清空。
- 普通笔记本宽度下左侧一级栏可以按既有规则收敛，但不得同时隐藏导航和退出入口；输入区、成果卡和错误卡不得横向溢出。
- 专注模式的完整业务和安全要求以 `00-PRD/01-模块PRD/16-对话式智能体工作台/PRD.md` 为准。

### Task 当前任务条与执行轨迹

- Task 是跨模块业务上下文，不新增左侧一级菜单；完整需求以 `00-PRD/01-模块PRD/19-Task任务对象与执行轨迹/PRD.md` 为准。
- 智算助手和专业工作区复用同一紧凑当前任务条；宽屏最多使用两行信息，窄 Dock 折叠为“任务名称 + 状态 + 详情”，不得用大型流程卡压缩 Excel 或 DOCX 主工作区。
- 当前任务条主信息显示任务名称、业务 Task 编号和状态；辅助信息显示来源、已锁定 Skill、当前阶段、复核轮次和成果版本。无任务时只显示“尚未发起任务”，不显示假编号、假进度或空 KPI。
- 执行轨迹默认放在任务详情抽屉或项目详情中展开；常驻页面只保留当前阶段摘要。轨迹节点点击后进入现有结果预览、报告、智能协同或知识治理页面，不复制专业写操作。
- 已完成节点必须来自后端真实事件和时间；未运行、不适用、失败、降级、待人工复核分别使用明确文字和现有语义色，颜色不得成为唯一状态信息。
- Tool 默认显示中文业务名称；处理器 ID、规则 / 模板版本和时间只在展开技术详情中显示。模型“正在回答”与专业 Tool“已经执行”继续严格区分。
- 组件使用纯白背景、`1px` 浅边框、低圆角、无常驻阴影、无渐变、无卡片套娃；字体、字号、行高和按钮继续服从本文唯一 token 与硬门禁。
- 页面切换、抽屉开合和 Dock 展开不得改变 Task、Run、Skill 快照、成果版本和复核轮次；减少动态效果开启时立即呈现当前真实状态。

### 状态标签

- 标签高度 22px-28px。
- 文字短，不写长句。
- 颜色服务业务状态，不做装饰。
- 同一状态全项目统一颜色和命名。

## 页面级规范

- 第一屏明确出现“造价智算 / 工程造价辅助智能体”。

### 管勘智算 v2.0 宽屏主页

创建日期::2026-06-30 18:59

主页按宽屏桌面软件设计，不按竖屏网页优先设计。后续实现 `daweiba` 时，应优先保证 1366px 以上和普通宽屏桌面体验；竖屏 / 移动端只需不阻断基本使用，不再作为主设计目标。

不得为某一个固定分辨率写死布局，不允许靠 1366、1440、1920 等单点像素值手工拼出“只在某个窗口好看”的界面。大尾巴主题必须采用桌面优先的响应式工作台：外层三栏使用 flex / grid / `minmax()` / `clamp()` / 容器约束组织，左侧导航保持稳定宽度和可折叠能力，右侧智算侧栏保持可调宽度和折叠能力，中间工作区按剩余空间自适应填满。窗口宽度变化时，优先保证中间表格和当前模块主体可用，再按断点收敛左侧二级栏和右侧助手。

#### 三栏关系

- 左侧“当前模块”窗口、中间模块工作区、右侧“随行助手 / 智算”窗口必须上下顶格，形成软件工作台。
- 左侧和右侧收起时，中间工作区必须动态扩宽。
- 中间工作区不再纵向堆叠所有模块，而是根据左侧当前模块切换显示。
- 页面不应出现大面积营销式标题、宣传说明或首屏 Hero；主界面进入后直接是工作台。
- 宽屏比例按“左侧固定、右侧可调、中间吃满剩余空间”计算；中间模块内部不允许再使用旧的小卡片宽度造成大片空白。
- 填价工作台内部使用“项目看板｜新建填价”双视图；“新建填价”继续采用“上传标准 Excel / 转换后概览”上层两列、“工作状态”下层横跨整行的结构，并且不显示表格预览。
- 工作状态模块承接原表格预览底部摘要和宽屏洞察：输入 / 匹配行数、价格列、输出文件、实物 / 技术一层命中、经验提示、复核数量、预警数量、高风险 / 低风险，以及“匹配状态”“匹配质量分布”两张状态卡。
- 结果预览页的表格预览模块必须作为单个主窗口铺满中间区域；除必要工具条和 sheet 标签外，不再混入转换摘要、经验池预警按钮、预警详情和导入经验池内容。报告预览、知识库状态页也应作为单个主窗口铺满中间区域。
- 转换概览主卡使用白底、浅灰或浅蓝信息态；不使用绿色整块背景。绿色仅用于“标准命中 / 无预警”等明确业务状态的标签、小点、图表分段，不用于普通完成概览卡。

- 主界面不能变成营销页；进入后直接是工作区，不用大篇幅介绍产品。

### 大尾巴主题左侧菜单

- 左侧菜单可参考 Navattic 的“极窄图标栏 + 一级模块栏 + 二级功能栏”结构，但必须按造价智算业务重组。
- 极窄图标栏宽度建议控制在 52px-64px，主要用于产品标识、全局搜索 / 动作、模块总入口、设置和用户。
- 一级模块栏宽度建议控制在 190px-240px，用于填价工作台、结果预览、经验池预警、工作量抓取、Word 报告、知识库问答、智能协同等模块；智能协同固定排在知识库问答下方。
- 二级功能栏不是常驻必需项，只在当前模块存在复杂子设置时出现；出现时应允许折叠，避免挤压中间表格。
- 当前选中项采用深色加粗文字 + 极浅灰底或透明底 + 1px 细线 / 左侧细条指示；禁止高饱和大色块，禁止整块蓝色、绿色、紫色填充。
- 一级模块栏不显示数字序号；不得为了表现流程感在模块名前加 `01/02/03`，避免和真实工作步骤、表格行号混淆。
- 普通笔记本宽度下，左侧菜单应自动收敛为图标栏 + 抽屉，优先保证中间表格和右侧 AI 可用。

### 填价结果预览

- 表格独占预览模块主体宽度。
- 状态、候选数量、匹配说明、预警参数、预警细节不能与数值列混乱。
- 匹配说明默认短显示，悬浮看完整内容。
- 重点数字和状态要可扫读，不能全靠颜色。
- 顶部工具条内的“批量匹配”“重算公式”“设置”等按钮使用低高度工具按钮，避免挤压表头空间；完成后的“已完成匹配”保留为浅色禁用态，不能突然消失，也不能继续保持高权重主按钮。
- 表头列宽允许像 Excel 一样在右边缘拖拽调整；不显示额外手柄或常驻提示，鼠标悬停边缘时变为可拖拽光标即可。列宽偏好按 `sheet 名 + 列标题` 保存，只影响浏览器预览，不反写输出 Excel。

### Word 报告预览

- 沿用左侧“Word 报告”，不得新增“报告预览”一级菜单。
- 页面采用“紧凑顶部状态 / 操作 + 主体真实 DOCX 预览”结构；下载 Word、下载 Excel、风险清单和刷新预览放在同一操作层级。
- 主体必须读取当前任务实际生成的 `.docx`，不能继续用报告摘要、输出文件名和指标字段拼成模拟 Word 页面。
- 预览器与 Word renderer 只在当前页有可用报告时按需加载，Worker、JSZip 和字体等资产必须同源自托管，断网可用。
- 预览容器必须有稳定高度并独立滚动；使用响应式剩余空间，不写死只适配单一窗口的宽高。
- 加载、成功、报告已更新、失败和未生成状态要清晰；失败时必须提供重试和下载 Word 兜底，不能让整个页面白屏。
- 人工修改后未“重算公式”时沿用现有报告未刷新提示；重算、风险报告写回或 job 切换后，旧预览必须失效。
- 搜索、缩放、打印等工具只在 Word renderer 实际支持时展示；网页预览定位为快速核对，正式排版以下载后的 Word 文件为准。
- 第三方组件外壳需融入大尾巴主题：白底、浅灰工作台、1px 细边框、低圆角、无常驻阴影；不得覆盖正文或抢过造价智算主操作。

### 问问智算

- 普通问答、知识库问答、快捷指令、风险报告要有不同状态提示。
- “查库：”等强制知识库模式应显示已调用知识库。
- 无证据时明确提示人工复核，不做看似确定的回答。

### 当前任务条与任务详情

- 当前任务条使用纯色表面、1px 语义边框、6—8px 低圆角、无渐变和无常驻阴影；不得做成挤压主业务区的大卡片。
- 默认 / 紧凑条采用 14px 任务名、13px 状态 / 元数据 / 按钮、12px 标签与 Task 编号；全部使用自托管苹方和 `--dws-font-size-*` token。
- 详情抽屉按“目标与身份 → 冻结 Skill 与输入 → 真实执行轨迹 → 实际 Tool → 成果 → 协同 → Experience”排列；状态同时使用文字与语义色，颜色不能成为唯一信息。
- 空态显示“尚未发起任务”，聚合异常显示“任务轨迹暂不可用，专业处理功能仍可继续使用”，不得用示例编号、KPI 或前端计时器补齐空白。
- 工作区采用独立 Task 布局行；验收必须确认 `elementFromPoint` 命中详情按钮本身，避免模块标题层覆盖造成“看得见但点不到”。
- 抽屉支持关闭按钮、Esc、焦点进入和减少动态效果；1366、1440、1920 及 Dock 展开态均不得横向溢出。

## 禁止项

- 不把工作台做成营销 landing page。
- 不用大面积渐变、光球、装饰图形遮盖主流程。
- 不为了视觉冲击牺牲表格宽度。
- 不让 AI 聊天窗口压过主表格。
- 不让设置按钮变成高大胶囊按钮。
- 不在同一模块里混用多套字号、按钮、图标风格。
- 不用颜色表达相反含义。
- 不通过 UI 改动改变后端匹配、预警、报告或下载结果。

## 前端验证口径

前端线程做 UI 改动后，至少验证：

- `npm run frontend:build` 通过。
- 普通桌面宽度下，上传、转换、表格预览、AI Dock 不遮挡。
- 宽屏窗口下，表格预览获得更多空间。
- 1366px 宽笔记本窗口下，设置按钮、sheet 标签、表格内容不溢出。
- 不按固定分辨率写死布局；至少在普通笔记本宽度、宽屏显示器宽度和 Tauri / 浏览器窗口缩放三类场景下，左侧导航、中间工作区、右侧智算侧栏能自然伸缩，不出现大片空白、横向溢出或主工作区被压扁。
- AI Dock 收起 / 展开正常。
- 预览表格横向和纵向滚动正常。
- 项目看板在普通笔记本、参考图相近宽度、宽屏和右侧 AI Dock 展开态下，KPI、图表、历史表与详情抽屉不溢出、不压扁、不出现大片空白。
- 项目看板无历史数据时不显示伪造图表；有真实数据时 KPI、图表和项目列表统计能够互相核对。
- 状态色在默认主题下语义正确。
- 如果改了主题，还要确认状态色不被主题反转。
