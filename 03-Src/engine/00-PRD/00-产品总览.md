## 产品定位

“造价智算”是面向工程造价业务的辅助智能体，当前已形成长输管道勘察测量最高投标限价编制、勘察测量结算辅助审核两条可运行的真实场景。产品以结构化规则、结构化计价库、经验池预警、人工复核和大模型解释能力为基础，帮助用户完成 Excel 填价、结算审核、风险复核、报告生成和业务问答，并以“一套底座、多个专业 Skill”作为横向扩展架构。

产品不是单点填表脚本，也不是泛用聊天机器人，而是嵌入工程造价生产链条的专业智能体。当前将“勘察测量最高投标限价编制”作为首个已验证、已登记专业 Skill，验证“标准可调用、规则可执行、经验可预警、过程可留痕、成果可复核”的方法；v5.18.0 又以独立结算审核 MVP 验证同一专业资料能够形成“模板核验—风险定位—人工复核—双成果交付”的相邻业务闭环。该模块是真实可运行场景，但尚未登记为 Skill Registry 中的第二个专业 Skill；后续再通过完整专业能力包复制到通用服务类、估概算审核、变更签证预算审核、数字与信息化项目投资计价等强规则、重表格、需解释、需留痕场景。

## 业务痛点

- 标准链长：收费标准、测绘定额、项目规则、历史说明分散，依据查找和口径统一成本高。
- 数据链散：多 sheet、多行表头、合并单元格、隐藏列、单位差异、公式缓存等表格问题频繁出现。
- 经验链断：历史经验沉淀在个人电脑、旧表批注、口头判断和项目样表中，难以组织复用。
- 审核链弱：填价依据、匹配过程、异常原因、经验偏离和复核意见不易留痕。

## AI 架构原则

造价智算采用“业务工作台 + 专业知识库 + 规则智能体 + 大模型协同 + 人工复核闭环”的混合 AI 架构。

- 凡是工程造价数字裁决，优先采用可验证的结构化规则。
- 凡是解释、追问、总结、提示和报告，交给大模型增强协同。
- 凡是规则不足、依据不充分、字段冲突或经验偏离，进入人工复核闭环。
- 当前原型先保障本地助手业务闭环；推广阶段再将价格库、知识库、规则 skill、AI 复核 skill、风险报告 skill 封装为服务能力。

## 双交互模式

造价智算保留两种互补的使用方式，共用同一专业能力、任务、规则和成果：

- 专业工作台模式：左侧选择模块，中间完成表格、预警、报告和精细复核，右侧问问智算随行解释。
- 对话式智能体模式：通过左侧一级入口“智算助手”进入保留左侧导航的宽屏会话区；右侧问问智算也可快捷进入同一工作台，在底部选择专业能力、上传文件并用自然语言驱动任务。

产品目标是“主流程可以只靠聊天完成，复杂核对可以随时进入专业页面”，而不是删除表格工作台或把计算交给大模型。会话中的上传、匹配、预警、报告和下载必须调用现有确定性 API，并显示真实动作、进度和成果。

专业工作台中的“填价工作台”已在 v5.15.0 完成 P0“项目看板｜新建填价”双视图：项目看板负责真实项目台账、处理趋势、状态 / 风险 / 匹配质量图表和历史项目；新建填价完整保留当前上传、列映射和确定性处理链。两种视图共用同一项目、任务、Skill 和成果状态，不把重复运行次数冒充项目数，也不用前端假数据营造 Dashboard。v5.15.4 将当前已验收视觉沉淀为“大尾巴 Shadcn UI v1.0.0”：以 shadcn/ui preset `b1au7YYAi` 的 Rhea / Neutral / Blue / Lucide 和 Inter 比例语言为设计输入，运行时继续使用自托管苹方；公共颜色、字体、间距、圆角和组件状态通过 `--dws-*` 令牌复用，Dashboard 具体布局仍在 `.project-dashboard` 内局部实现，不全量改造现有前端主题和工具链。

## Task 任务主线原则

造价智算把 `Task` 定义为有明确业务目标、输入、专业 Skill、预期成果和人工完成条件的一项业务工作，而不是一个英文标签或一次接口调用。统一产品表达为：

> **一项 Task，调用一套专业 Skill，组合一组可信 Tool，经过人工复核形成正式成果，再沉淀为可治理的 Experience。**

Task 是贯穿现有页面的业务上下文，不新增左侧一级菜单。智算助手负责发起和解释任务，专业工作台负责确定性处理，项目看板负责历史和成果追溯，智能协同负责派发、领取与多人复核，知识记忆负责 Experience 的人工治理。系统必须区分 `Project 项目 → Task 业务任务 → Run 技术运行 → ReviewRound 复核轮次 → ArtifactVersion 成果版本 → ExperienceLineage 经验血缘`；重试、重算、报告刷新和页面切换不得被误计为新 Task。

P0 先复用现有 `TaskEnvelope`、`SkillRuntimeContext`、项目台账、协同状态、成果引用和可信经验血缘，统一任务身份、任务定义快照、当前任务条和真实执行轨迹。未运行的阶段不得显示完成，模型文字不得冒充 Tool 已执行。正式方案见 `00-PRD/01-模块PRD/19-Task任务对象与执行轨迹/PRD.md`。

## 专业数据可视化原则

造价智算的数据可视化不是独立 BI。项目看板现有 KPI、项目处理趋势、项目状态、大模型调用波形、模型种类、风险排行、匹配质量、条件式来源分布和五阶段漏斗构成不可减少基线；新需求只增加图表，不得删除、替换、合并、默认折叠、隐藏或迁走既有图表。专业页面在用户做判断的位置新增偏离、差额、风险、阻塞、版本和证据图形，并能下钻回同口径明细；若项目看板后续新增图形，也必须追加在既有内容之外。

- v5.22.0 已完成 `VIS-01`—`VIS-15`：Task 执行与成果—经验血缘、经验偏离与 AI填价候选、结果预览逐行风险、结算金额与分 Sheet 风险、工作量抓取、多人复核、可信经验治理、项目版本、RAG 调试和 Skill 能力矩阵均已进入真实责任页面。
- 每张图只使用现有责任模块的真实数据和状态；大模型不得生成图中数值、阈值、关系或完成事件，前端不得重新裁决价格、系数、风险、复核或知识状态。
- 当前数据不足时保留正式组件、数据契约和准确不足态，测试夹具只用于隔离验收，不进入生产台账。
- 图形必须能够回到 Task、Sheet、Excel 行、复核人、成果版本或知识记录；没有可靠明细关系时只显示汇总，不制造跳转。
- UI 继续执行“大尾巴 Shadcn UI”纯白、细边框、统一令牌和唯一字体字号，不复制外部参考的深色主题、固定网格或装饰性大屏。

正式方案、完成状态和回归证据见 `00-PRD/01-模块PRD/20-跨模块专业数据可视化/PRD.md` 与同目录 `实施进度.md`；`目标模式开发提示词.md` 仅保留为本次实现边界的交接参考。

## 专业 Skill 扩展原则

造价智算的横向扩展单元不是一张可替换的“库”，而是完整的“专业能力包（Skill）”：业务场景、输入规范、结构化计价库、规则包、字段映射、风险检查、知识资料、报告模板、标准流程和验收用例共同组成一个专业 Skill。

- 用户侧名称统一为“选择专业能力”，`Skill` 作为辅助标签，避免普通业务用户把它理解成纯技术概念。
- 当前勘察测量最高投标限价编制为首个已上线专业 Skill；v5.18.0 结算审核助手是同一专业内的独立真实场景 MVP，不因此宣称第二个 Registry Skill 已上线。通用服务类造价测算仍作为第二个横向 Skill 验证方向，未真实跑通前只标记规划中或内测中；“更多造价专业”作为即将开放的扩展占位，表达专业能力将持续增加，但不代表具体业务已经可用。
- 通用底座负责 Excel、任务、规则执行、风险、问答、知识记忆、报告和协同；专业 Skill 只装载自己的专业数据、规则、模板和验收资产。
- 结构化计价库是数据资产，确定性匹配引擎是工具，`SKILL.md` 是工作说明；三者不得混为大模型自由裁决机制。
- v5.12.0 已完成专业能力选择、勘察测量 Skill 清单化、安全 Registry、任务级 `SkillRuntimeContext` 和处理 / 匹配 / 预警 / 知识 / 报告 / 下载运行时路由；测试专用第二 Skill 已证明资产隔离。当前仍只有勘察测量真实业务已上线，第二个真实 Skill 待独立资料和数据，不对外宣称已有多个专业业务上线。

## 核心用户

- 造价业务人员：希望减少重复查价、手工填表、逐行复核和报告整理工作。
- 数字化建设人员：希望沉淀可复用的规则资产、知识库资产和智能体能力。
- 评审或参赛人员：希望快速看懂产品价值、业务流程、技术边界和可演示成果。

## 核心流程

1. 从外部任务信号进入，或在专业工作台 / 智算助手中创建并确认一项业务 Task，明确项目、目标、输入、预期成果和人工闸门。
2. 选择并冻结本次 Task 使用的专业能力（Skill）。
3. 上传或接收该 Skill 支持的标准 Excel；对话入口可附加文件并补充任务目标。
4. 程序读取表2、表3、表4等关键 sheet，并把实际阶段写入同一 Task 执行轨迹。
5. 根据当前 Skill 运行时上下文的结构化计价库和第一层规则匹配基价、实物工作费调整系数、技术工作费调整系数。
6. 第一层未命中时，读取经验提示层并标识为经验参考；用户可触发经验池预警、问问智算解释和 AI填价，最终写值仍需人工确认。
7. 输出填价后的 Excel、表格预览、匹配摘要和 Word 报告，保留 Task、Run、Skill 和成果版本追溯。
8. 按任务复杂度进入“编制—多人复核”简易流程或后续标准编审流程，收集逐人结论和意见；简单任务不强制增加审批人。
9. 从真实人工修改、AI填价确认和复核意见中形成受治理的 Experience 候选；未形成候选不影响业务 Task 完成。

结算审核助手采用独立旁路：上传统一结算模板或同结构 `.xlsx` 后，由结算规则卡核验参数、算术和证据完整性，生成保留原工作表的审核后 Excel、可签署 Word 审核报告和结构化 JSON；所有不确定事实与最终审定均明确交由有权限人员复核。

> 任务主动找到人，专业 Skill 约束 AI 怎么干，结构化规则负责数字，问问智算负责解释，多人复核负责兜底，项目经验再经过人工治理变成下一次可复用的可信记忆。

### 完整性

作品完整性按同一个真实项目演示，不以互不相干的页面数量衡量：

```text
Task 进入 / 创建并确认
→ 选择并冻结专业 Skill
```

赛前新增功能应优先补这条链上的断点，而不是继续增加平行页面。v5.20.0 已完成“人工修正或复核闭环 → 自动产生候选 → 人工确认 → 提升复审 → 下一项目带来源引用 → 撤销后停止命中”和项目记忆胶囊首版；v5.21.0 进一步以稳定业务 Task、不可漂移定义 / Skill 快照和真实后端事件，把已有 Skill、Tool、人工复核、成果与 Experience 显性串联；v5.22.0 又以 `VIS-01`—`VIS-15` 把偏离、候选、风险、差额、复核、版本和能力事实放回真实责任页面；v5.23.0 再把这些既有事实组织为专业能力中心内的“数智员工上岗证据”，用同源页面和 Markdown 导出集中证明“能上岗、能干活、能成长，而且不越权”。上述版本均使用 V3.1 正式样例证明显示与聚合增强未改变三个数字和正式成果。Task P1 的自动恢复、搜索和脱敏任务摘要仍保留。详细需求与验收见模块 19、模块 20、模块 22 的 `PRD.md` 和 `实施进度.md`。

## 产品边界

- 大模型只做解释、问答、报告润色和候选提示，不直接裁决最终单价或系数。
- 基价和系数匹配优先采用可审计的结构化规则。
- 结算审核结果是辅助审核建议，不代替合同解释、现场事实确认、发票核验、签章程序和有权限人员的最终审定。
- 原始资料、标准文件、测试输入和答案表不直接改动。
- 经验池当前主要用于预警、经验提示和复核，不应偷偷改变主匹配规则。

## 成功标准

- 用户能用标准控制价 Excel 或统一结算模板生成可打开、可复核、可报告的结果文件。
- 三个核心数字的来源清楚、颜色状态清楚、逐行说明清楚。
- 规则资产可以被业务人员和其他 AI 理解。
- 参赛展示时能体现“规则链、数据链、智能体链”协同，而不是单点脚本工具。

## 价值指标

- 提效率：减少查表、匹配、复核线索整理和报告生成的重复劳动。
- 提质量：减少因人员经验差异、表格格式差异和临时查找造成的错漏。
- 提感知：让用户看到“填了什么、从哪里来、按什么规则、为什么待复核、与经验值偏离多少”。
- 控风险：把无依据、多候选、单位冲突、经验偏离等问题前移到编制过程。
- 强创新：从高频、高规则、高责任的小切口沉淀数据资产、规则资产、能力资产和治理资产。

## 推广路线

1. 先把勘察测量最高投标限价编制沉淀为首个可选择、可追溯、可验证的专业 Skill。
2. 已用结算审核助手 P0 验证同一专业资料能够复用为独立的相邻审核闭环，但不把模块页面冒充第二个 Registry Skill。
3. 以通用服务类造价测算建设第二个真实专业 Skill，验证底座、专业资产和任务隔离可以横向复用。
4. 再扩展到估概算审核、变更签证预算审核、数字与信息化项目投资计价等相邻场景。
5. 成熟后接入统一数字平台、大模型底座和数据中台，形成集团级造价 AI 能力组件、专业 Skill 和造价数字员工能力包。

推广原则为：先规则后模型，先助手后平台，先闭环后扩张，先可评估后规模化。
