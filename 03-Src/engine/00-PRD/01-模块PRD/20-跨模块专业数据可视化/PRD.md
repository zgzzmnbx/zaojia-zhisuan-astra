# 跨模块专业数据可视化 PRD

## 模块目标

在完整保留首页看板现有全部 KPI、图表、数据系列、筛选与交互，不改变任何专业裁决结果的前提下，把当前散落在 Task、结果预览、经验池预警、AI填价、结算审核、工作量抓取、智能协同、知识记忆、混合 RAG 和专业 Skill 中的真实业务数据，转化为可判断、可下钻、可追溯的新增专业图形。

本模块不是建设第二套 BI，也不是把所有数字都画成图。它只解决以下问题：

1. 用户能否比阅读长列表更快发现风险、偏离、差异和阻塞。
2. 用户能否从图形一键回到对应任务、Sheet、Excel 行、复核人、成果版本或知识记录。
3. 图形是否严格复用现有业务真相，不让大模型、前端或演示数据重新计算正式结论。
4. 各模块图形是否使用同一套字体、字号、状态色、图例、空态和交互语言。
5. 图形是否增强竞赛主线中的“真实执行、人工闸门、成果交付和可信经验进化”，而不是增加页面数量。

统一表达：

> **现有看板一张图都不减少；新增图形就近回答具体判断，并能回到同口径明细和来源。**

## 产品定位与看板增量原则

当前项目看板已经具备真实 KPI、项目处理趋势柱状图、项目状态环图、大模型调用波形图、模型种类环图、风险项目排行、整体匹配质量图、条件式项目来源环图和五阶段闭环漏斗。这一整套内容是本需求的不可减少基线。

本次只允许做增量：不得删除、替换、合并、默认折叠、隐藏、迁走或降低上述任一现有图表的可见性；不得减少其数据系列、筛选条件、点击联动、空态、汇报模式或历史项目关系。条件式来源环图仍按原有真实数据门槛显示，不得把“数据不足时不显示”误判成可以删除该能力。

`VIS-01`—`VIS-15` 是在现有能力之上的新增图形，按业务责任就近放置。若实施时确需在项目看板新增某个总览入口，只能在完整保留上述基线后新增，不得以空间不足为由覆盖、替换或折叠现有图表；本 PRD 已指定在专业页面 / 详情中承载的图形，不应被强行搬到首页。

本模块新增图形放在产生判断和动作的专业页面附近：

```text
项目看板：看整体
Task 详情：看执行与血缘
经验池 / AI填价 / 结果预览：看偏离、候选和逐行风险
结算审核：看金额差异和风险来源
工作量抓取：看抓取结果与问题类型
智能协同：看人员、轮次和退回
知识记忆 / RAG：看经验治理与检索证据
专业能力中心：看能力事实和上线状态
```

### 事实边界

- 基价 / 单价、实物工作费调整系数、技术工作费调整系数继续由结构化计价库与规则引擎裁决。
- 风险等级、经验池偏离率、结算建议值、工作量抓取结果、复核状态、知识治理状态和检索轨迹继续由各自后端模块产生。
- 前端只能做确定性的显示变换、排序、筛选、比例换算和安全聚合，不得改变源数据含义。
- 大模型不得生成图中数值、阈值、状态、趋势、关系、成果版本或完成事件。
- 测试夹具可以验证多版本、多 Skill、多轮次图形，但不得进入生产台账或在正式页面冒充真实数据。

## 功能边界

- 本模块只新增共享显示基础、`VIS-01`—`VIS-15`、必要的向后兼容只读聚合、同口径下钻和测试验收，不建立第二套业务状态机或第二套 Dashboard。
- 项目看板现有 KPI、八项图形（含五阶段漏斗）、数据系列、筛选、联动、空态、历史项目和汇报模式全部保留；新增图形不得替换、合并、默认折叠、隐藏或迁走任何既有内容。
- 正式价格、系数、风险、审核、复核、知识和报告结论继续由原责任模块产生；图形只显示、筛选、定位和解释，不新增裁决权。
- 新增只读聚合失败时，仅对应图形降级；Excel、预警、结算、工作量、报告、协同、知识、Skill、Task 和项目看板主流程继续可用。
- 不在本模块内建设通用 BI、自由查询、用户公式、组织绩效、模型训练、第二个真实 Skill、云端部署或外部消息实发。

## 当前基线

### 已有图形

1. 项目看板：分组柱状图、环形图、面积图、风险堆叠横条、匹配质量 100% 条形图、来源分布和项目闭环漏斗。
2. 智算助手：费用构成环形图与专业费用横条图。
3. 知识问答：预置知识库柱状图。
4. 左侧任务状态：当前表格匹配 / 复核 / 预警环形图。

### 当前缺口

- 图形主要集中在项目看板，专业页面仍以数字卡、文字和列表为主。
- Task 执行、成果版本和 Experience 血缘尚未形成同一条可视证据链。
- 经验池已有均值、范围、样本数、偏离率和阈值，但缺少整体分布和行级区间表达。
- AI填价候选已有排序与来源，但缺少同一价格尺度上的直接比较。
- 结算审核已有上报额、建议额和建议差额，但缺少金额变化图和分 Sheet 风险结构。
- 工作量抓取、多人复核和可信经验已有真实计数，但缺少紧凑、可筛选的状态图形。
- 现有图表字号仍需统一审计；不得继续出现 10px 可见坐标或同层中文字号不一致。

## 图形目录与详细规格

全部图形使用稳定编号。目标模式实施只有在 `VIS-01`—`VIS-15` 均完成代码、状态、测试和真实入口后才能结束。

### VIS-01：Task 真实执行轨迹

- 位置：当前任务详情抽屉 / 项目 Task 详情。
- 类型：可点击纵向或横向阶段时间线，优先使用语义 DOM，不依赖统计图表库。
- 数据：模块 19 的 TaskEvent，包含阶段、状态、真实时间、来源模块、安全引用和可用动作。
- 阶段：任务定义、Skill 冻结、输入接收、结构识别、规则处理、风险检查、人工复核、成果生成、协同复核、Experience 治理。
- 状态：已完成、处理中、待人工、失败、未运行、不适用、未形成候选。
- 交互：点击进入现有结果预览、风险、报告、协同或知识治理入口；不得复制这些模块的写操作。
- 禁止：前端计时器伪造完成、模型文字冒充 Tool 事件、未执行阶段标绿。

### VIS-02：成果—经验血缘图

- 位置：Task 详情的“成果与经验”区域。
- 类型：稳定分栏有向关系图，固定为 `Task → Run / ReviewRound → ArtifactVersion → ExperienceLineage`；使用 DOM + SVG 连线或等价轻量实现，不引入力导向图库。
- 数据：稳定 task_id、关联 Run、复核轮次、Excel / Word / JSON 成果版本与哈希、候选 / 确认 / 提升 / 命中 / 撤销 / 疑似失效状态。
- 交互：选中节点显示来源摘要和现有安全操作入口；从知识记录能够反查来源 Task 和成果。
- 空态：没有候选显示“未形成经验候选”，不影响 Task 完成；成果文件失效显示“引用存在，文件已失效”。
- 禁止：把候选显示成已确认经验、把 Run 数量显示成 Task 数量、回显绝对路径或平台秘密。

### VIS-03：偏离率—样本数散点图

- 位置：经验池预警页“本次分析”摘要与风险列表之间。
- 类型：散点图。
- 横轴：`sample_count`。
- 纵轴：现有绝对 `deviation_percent`；不得擅自改为有符号偏离。点形或辅助文字可以根据 `current_value` 与 `experience_average` 确定“高于 / 低于均值”。
- 阈值：使用本次预警真实低风险 / 高风险阈值画参考线；不同记录阈值不一致时不得画一条伪统一线，应按筛选口径拆分或明确停用参考线。
- 颜色：高风险红、低风险琥珀、未超过阈值中性；颜色之外必须有形状、标签或文本摘要。
- 交互：悬停 / 键盘聚焦展示 Sheet、Excel 行、指标、当前值、均值、范围和样本数；点击风险明细后，散点图与经验区间图同步聚焦该条记录并按该条真实值重算显示域，避免低风险被超大偏离值压缩到不可辨识；“跳到表格”继续使用独立按钮调用现有定位逻辑。
- 数据不足：少于 2 个可绘制点时显示数字摘要，不绘制误导分布。

### VIS-04：经验区间子弹图

- 位置：经验池单条预警详情，可复用到 AI填价经验池候选详情。
- 类型：横向子弹图。
- 编码：最小值—最大值为区间，平均值为刻线，当前值为圆点；当前值超出经验范围时坐标域必须自动扩展，不裁掉点。
- 文本：同时显示当前值、均值、范围、样本数、偏离率和单位；图形不能替代数值。
- 交互：点击仍使用现有定位逻辑，不改变预警等级。

### VIS-05：AI填价候选价格点图

- 位置：AI填价三栏弹窗的候选区域，保持三栏阅读结构。
- 类型：同一价格轴上的点图 / 棒棒糖图。
- 数据：当前行价格、程序稳定排序后的知识库 / 经验池候选、相似度、置信说明、来源和当前选择。
- 交互：点选候选等价于现有候选选择，只更新待确认选择；必须继续点击原“确认写入”动作才能改输出副本。
- 视觉：知识库、经验池和当前值使用不同形状与语义标签，不能只靠颜色；前三候选保持与程序排序一致。
- 禁止：模型生成候选外数值、图形自动选择并写值、改变现有候选排序。

### VIS-06：结果预览行风险迷你地图

- 位置：结果预览表格右侧边缘或独立窄轨道；不得占用主要 Excel 列宽。
- 类型：按可见 / 全量预览行生成的窄色带和可访问行列表。
- 主状态显示优先级：`高风险 > 待复核 > 第二层经验提示 > 第一层标准命中 > 其他 / 未运行`。该优先级只用于视觉主色，不覆盖行的其他真实状态。
- 交互：点击色块切换 Sheet、滚动到准确 Excel 行并复用现有闪烁定位；筛选后必须明确地图统计的是全部行还是当前可见行。
- 性能：宽表与大量行时不得逐单元格反复查询；状态数据一次整理、memo 化，图形隐藏时卸载。
- 禁止：把预警未运行显示为无风险、压缩固定 AI 列、破坏横纵滚动与人工编辑。

### VIS-07：结算审减金额瀑布图

- 位置：结算审核“审核工作台”结果态金额区域。
- 类型：三段瀑布图。
- 数据：承包商上报明细口径合计 `reported_detail_total`、签名差额、审核建议明细口径合计 `reviewed_detail_total`。
- 口径：根据真实差额方向显示“建议审减”或“建议增加”，不得假定差额永远为正；若 `上报额 - 审核建议额` 与接口差额超出金额精度容差，显示数据口径错误而不是静默修正。
- 文案：持续标注“结构化明细试算口径，不替代含税合同结算金额和最终审定”。
- 交互：选择差额段过滤到产生自动调整的审核发现；没有可定位项时只显示汇总，不制造跳转。

### VIS-08：分 Sheet 风险小多图

- 位置：结算审核“审核发现”筛选区与问题列表之间。
- 类型：每个 Sheet 一张等尺度紧凑横条 / 小多图。
- 最小数据：Sheet 名、审核行、通过行、高 / 中 / 低风险、待人工核验、自动调整数。
- 数据契约：如现有结果缺少分 Sheet 通过行等聚合，可增加只读、向后兼容的 `sheet_summaries`，只能从同一次审核真实明细计算。
- 交互：点击某 Sheet 或风险段过滤现有发现列表；小图使用相同尺度，避免不同 Sheet 被分别归一化后产生误导。
- 空态：只有一个 Sheet 时仍可显示结构条；没有风险时明确“已审核且未发现结构化风险”，不能省略审核行数。

### VIS-09：工作量抓取结果分组条形图

- 位置：工作量抓取完成摘要与问题日志之间。
- 类型：独立分组横条图。
- 数据：填写行、覆盖行、保守跳过、未匹配源行、一对多预警、预警行，以及需要时的单元格计数。
- 口径：当前字段可能重叠，默认展示原始独立计数，不做 100% 堆叠、不计算虚假总占比。只有测试证明指标互斥后才允许增加分区视图。
- 交互：点击条目过滤现有日志；没有对应明细时按钮禁用并解释原因。
- 文案：持续区分“行”和“单元格”，不得混用。

### VIS-10：复核人状态矩阵

- 位置：智能协同任务详情和智算助手复核进度卡的展开区。
- 类型：人员 × 状态维度矩阵，使用可访问表格语义；颜色只作辅助。
- 行：复核人。
- 列：平台、当前轮次、投递状态、复核状态、意见状态、最近更新时间。
- 状态：未投递 / 部分失败 / 待处理 / 已通过 / 已退回 / 未提交意见。
- 交互：选择人员只展示现有脱敏状态与意见；不在图中直接扩大受众、重试投递、通过或退回。
- 边界：普通飞书与 WeAct 分开显示，不能跨平台合并任务或人员身份。

### VIS-11：复核轮次阶段带

- 位置：智能协同任务详情“复核历史”。
- 类型：按真实轮次排列的阶段带 / 时间带。
- 数据：轮次、冻结成果版本与哈希、提交时间、复核人结论、退回 / 通过、完成时间和当前有效轮次。
- 交互：点击轮次打开现有该轮成果与意见摘要；旧轮次只读。
- 数据契约：如当前接口只返回最新轮次，增加只读历史聚合，不建立第二套审核状态。
- 禁止：把单个人通过显示为全轮通过、旧卡回调降低新轮状态、自动触发消息或审批。

### VIS-12：可信经验来源与治理双条图

- 位置：知识记忆弹窗“进化成效”。
- 类型：两个并列但相互独立的条形图。
- 来源图：人工改单 / AI填价确认、多人复核意见等真实事件来源。
- 治理图：已确认、已驳回、已撤销；检索命中、版本更正、疑似失效继续作为独立指标或单独小图，不混入同一分母。
- 交互：点击条形过滤知识记录或打开对应现有列表；无法可靠筛选时只显示指标，不制造按钮。
- 边界：只统计真实审计，不估算节省工时、准确率、组织收益或模型学习次数。

### VIS-13：项目版本阶段趋势

- 位置：项目详情中的 Task / 成果版本区域，不放首页。
- 类型：共享 X 轴的上下两张小图，背景按复核轮次或成果版本阶段分区。
- 上图：高风险、待复核等同单位计数。
- 下图：上报 / 审核建议 / 相关成果金额等同单位金额；具体指标随业务场景选择。
- 口径：禁止把金额和数量放在同一 Y 轴或双轴制造相关性；阶段必须来自真实 ArtifactVersion / ReviewRound。
- 数据不足：少于 2 个真实版本时显示“版本不足，暂无趋势”，仍展示当前版本摘要。
- 交互：点击版本进入 VIS-02 血缘或打开该版本现有成果。

### VIS-14：RAG 检索通道并列图

- 位置：大模型调试模式中的知识检索详情，不放普通业务回答和首页。
- 类型：BM25、结构化、向量、融合 / 重排后的并列条形或点图，旁边保留证据列表。
- 数据：真实调试轨迹中的候选数、保留数、得分或排名变化；没有返回的字段显示“本次未提供”，不得前端推测。
- 口径：各通道并行召回，不画成漏斗；经典检索与混合 RAG 分开标识，不暗示默认模式已改变。
- 边界：只解释检索，不影响 AI填价、三个数字、经验池和正式成果。

### VIS-15：专业 Skill 能力矩阵

- 位置：现有专业能力中心 / Skill 详情，不新增一级页面。
- 类型：Skill × 能力矩阵，不使用雷达图。
- 行：Registry 返回的真实 Skill，包括已上线、内测 / 规划、停用等状态。
- 列：输入识别、结构化匹配、风险检查、知识问答、报告、协同、验证样例等 Manifest 真实能力。
- 交互：点击进入现有 Skill 详情；只有 `can_create_task` 为真时允许使用原入口创建任务。
- 数据不足：即使当前只有一个真实可执行 Skill，矩阵本身仍可实现并如实展示其他 Registry 项的规划 / 不可执行状态；测试用 Skill 不得进入生产清单。
- 禁止：以颜色、百分比或成熟度分数把规划项包装成已完成。

## 统一数据与交互规则

### 数据来源责任

| 数据域 | 唯一业务真相 | 可增加的只读能力 |
| --- | --- | --- |
| Task、Run、事件与血缘 | 模块 19 聚合层及原责任模块 | 时间线 / 血缘只读接口、安全跳转引用 |

| AI填价候选 | 现有候选 API 与稳定排序 | 前端点图转换，不改候选生成和确认接口 |
| 结果预览行状态 | 当前预览结果、风险项和匹配说明 | 一次性行状态摘要，不重复扫描 Excel |
| 结算审核 | 独立结算审核结果 | 向后兼容的分 Sheet 汇总 |
| 工作量抓取 | 当前抓取 summary 与日志 | 只读分类计数和日志过滤键 |
| 智能协同 | 现有协同状态机、轮次与审计 | 只读人员矩阵和轮次历史聚合 |

| Skill | Registry 与 Manifest | 只读能力矩阵，不解析自然语言规则 |

### 图形到明细

- 每张可交互图必须说明点击后筛选什么、跳到哪里、统计口径是否变化。
- 图形筛选必须形成可见且可清除的状态；返回列表后不得丢当前 Task、Sheet、行或版本。
- 图形与同页数字、表格、下载结果必须使用同一份响应或同一查询参数，避免并行请求口径漂移。
- 图中数字不得只藏在 hover；必须提供标签、图例或同口径文本摘要。
- Tooltip 只补充信息，不承担唯一事实展示。

### 完整状态

所有图形都必须实现：

1. 初始 / 未运行。
2. 加载中，超过 300ms 才显示稳定尺寸骨架。
3. 有数据。
4. 数据不足，明确为什么不绘图。
5. 部分数据缺失，保留可用内容并说明缺项。
6. 错误，单图失败不让整页白屏。
7. 空筛选结果，可一键清除筛选。
8. 减少动态效果时立即显示最终状态。

当前生产数据不足以形成某张趋势或矩阵时，不得制造演示数据。只要组件、真实数据契约、数据不足态和多记录自动化夹具均已完成，即可判定该图形已实现；但必须在交付中明确当前实例为何没有足够真实点。

### 图形技术选择

- 现有项目已固定 `recharts 3.10.0`，折线、柱形、散点、参考线、参考区间和小多图优先继续使用 Recharts。
- Task 时间线、血缘、行风险迷你地图、复核矩阵和阶段带优先使用语义 DOM、CSS Grid 和轻量 SVG。
- 禁止引入 ECharts、D3 全包、关系图库、Canvas 框架或第二套状态管理库，除非现有技术确实无法满足并先取得用户确认。
- 禁止 CDN、在线字体、在线图标和远程 preset；绿色版与云端包必须离线包含所有运行依赖。
- 图形按模块懒加载；页面不可见时卸载 Recharts 子树，避免零尺寸容器警告。

### 共享层边界

共享层只负责：

- 统一外壳、标题、单位、来源、文本摘要和状态。
- 统一 token、坐标、Tooltip、Legend、格式化和可访问性。
- 纯函数数据转换。

共享层不得负责：

- 风险等级、价格候选、审核状态或知识状态裁决。
- 跨模块写操作。
- 任意路径读取。
- 用一个通用 `any` 数据结构吞掉所有业务类型。

## UI 与设计系统硬门禁

### 唯一字体和字号

| 层级 | 唯一字号 | 用途 |
| --- | --- | --- |
| 页面标题 | `28px` | 页面主标题 |
| 模块标题 | `20px` | 模块级标题 |
| 图形 / 面板标题 | `16px` | ChartFrame 标题 |
| 正文 / 关键解释 | `14px` | 结论、口径、详情 |
| 表格 / 控件 / 图例 / 按钮 | `13px` | 交互与高密度信息 |
| 辅助说明 / 图形摘要 | `12px` | 来源、单位、空态说明 |
| 纯数字坐标 / 技术刻度 | `11px` | 仅限空间受限的纯数字坐标，必须使用 `--dws-font-size-11` 并在 CSS 注释原因 |

- 可见业务文字不得小于 `12px`；禁止新增 `9px / 10px`。
- 中文分类坐标、状态、人员、Sheet、版本、图例和 Tooltip 正文不得使用 `11px`，统一至少 `12px`。
- 所有组件使用自托管苹方和现有 `--dws-font-*`；表单、SVG 文本、Recharts tick / label / legend / tooltip 显式继承或使用相同 token。
- 同一层级的 `font-family / font-size / font-weight / line-height` 必须一致，不得依赖第三方默认值。
- 数字、金额、行号、百分比、版本号使用 `font-variant-numeric: tabular-nums`。

### 色彩和组件

- 纯白主工作区、`1px` 浅边框、`6px—8px` 圆角、无常驻阴影、无渐变、无卡片套娃。
- 中性分析序列使用项目 `--db-chart-blue-*`；第一层命中绿、第二层经验琥珀、待人工橙、高风险 / 失败红、处理中蓝、未运行中性灰。
- 颜色不能成为唯一编码：同时提供图标、形状、描边、标签或文字。
- 不复制 HealthCare 深色主题；深色模式只通过现有语义 token 适配。
- 不在组件中散落新的近似蓝色和任意 hex；Recharts 需要色值时从 CSS 语义 token 或统一主题函数读取。

### 布局、响应式和动效

- 图形服从当前专业工作对象：Excel、审核发现、Task 详情和知识记录仍是主视觉。
- 根据容器宽度在双列、单列和横向滚动之间收敛，不为 1366 / 1440 / 1920 任一分辨率写死。
- 右侧智算 Dock 展开时不得压扁坐标、遮挡标签或造成页面级横向滚动。
- 图形进入动画控制在 `150ms—1500ms`，只用于数据出现和状态变化；禁止循环装饰动效。
- `prefers-reduced-motion` 下立即显示最终状态并关闭非必要自动滚动。

### 无障碍

- 图形容器可聚焦，具有准确 `aria-label`、标题和同口径文本摘要。
- 键盘能够选择散点、候选、风险段、人员和版本；焦点样式清楚。
- Tooltip 内容可通过键盘或相邻文本获得。
- 状态不能只靠颜色；对比度符合项目现行标准。
