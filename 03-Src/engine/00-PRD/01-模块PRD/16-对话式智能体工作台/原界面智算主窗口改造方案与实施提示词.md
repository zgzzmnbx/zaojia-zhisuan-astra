# 原界面智算主窗口改造方案与实施提示词

日期：2026-10-03。状态：用户已授权 Git 备份并直接执行，v5.24.10 已在正式源码实施并完成本地验收。验证口径见同目录《原界面智算主窗口验收-20261003.md》。下文保留批准时的实施方案和提示词作为设计依据。

## 1. 用户决定与本轮范围

用户决定：A/B/C/D 四个 Demo 均不采用。保留现有正式界面的组件与外观，在原界面上把现有大智算窗口作为左侧主要工作窗口，右侧提供现有专业页面的预览与操作；同时提供返回原布局的选项。

本文件最初只交付方案与提示词；随后用户明确授权“git 备份，然后直接执行，然后自己要测试”。实施新增隔离布局、设置和默认配置读取，复用原业务。既有 Demo 保留为讨论过程，不复制其页面、样式、模拟数据或状态机到正式程序，也不继续制作新 Demo。

## 2. 结论与源码依据

可以做，主要工作是改变现有组件的组合、显示条件和页面导航关系。现有系统已经具备完整大智算窗口、原专业工作区以及共享业务上下文，适合在原地增加布局选项。

| 已有资产 | 当前作用 | 本次复用方式 |
| --- | --- | --- |
| `frontend/src/components/agent-workspace/ConversationalAgentWorkspace.tsx` | 原始大智算工作台，含身份区、消息、输入与专业任务操作 | 直接作为新布局左侧主窗口；保留原消息、头像、输入区与操作外观 |
| `AgentMessageStream.tsx`、`AgentComposer.tsx`、`agentWorkspace.css` | 原消息流、Skill 选择、附件、任务操作、图表和复核卡 | 原组件原样复用，仅为新容器宽度补必要适配 |
| `frontend/src/App.tsx` 的 `.daweiba-workspace-frame` | 原专业模块、表格、报告、预警、工作量等 | 作为右侧专业区显示，不复制成第二套组件 |
| `frontend/src/App.tsx` 的 `chatMessages`、`chatInput`、当前任务与成果 | 大窗口和小 Dock 已共用状态与业务函数 | 继续使用同一来源，布局不创建第二个会话、任务或成果 |
| `frontend/src/styles.css` 的 `.is-agent-workspace` | 进入原大窗口时隐藏专业区和小 Dock | 原规则继续用于原布局，新布局独立隔离显示条件 |
| `config/project-default-settings.json` 与 `/api/project-default-settings` | 默认设置读取入口 | 后续在同一入口增加布局默认值、合法值检查和前端类型读取 |

已核对的关键约束：

- 当前 `activeDaweibaModule` 同时参与专业页显示、大会话渲染、自动折叠、滚动跟随、Escape、离开页面保护、地图生命周期及部分业务来源判定。不能只把大窗口常驻，然后继续用这个字段判断所有行为。
- 当前专业工作区常驻于 `.daweiba-main-content`，大智算位于同一父容器内。优先保留 DOM 和 React 组件位置，用新布局作用域安排左右列，降低重新挂载风险。
- 项目默认设置接口按字段组组装响应，新增 JSON 字段不会自动传到前端。确需布局默认配置时，必须一起补齐配置读取、接口透传及前端类型；这属于界面设置，不涉及计价引擎。
- 当前默认进入模块是 `agent`。返回原布局可能恢复原来的大智算专注界面，也可能恢复原专业页加右侧小 Dock，取决于切换前的位置。两种原行为都要保留。

## 3. 两种正式工作方式

| 选项 | 布局 | 行为 |
| --- | --- | --- |
| 原布局 | 原功能导航＋原专业工作区＋右侧小智算；点击原“智算助手”仍进入已有专注模式 | 继续执行目前已验收的布局、入口和操作 |
| 智算主窗口 | 原功能导航＋现有大智算主窗口＋右侧原专业页面 | 会话常驻；专业页切换发生在右侧，任务与结果共享 |

顶部全局栏、原左侧图标栏与模块导航保留。新模式中大智算位于导航右侧、专业区左侧，形成主要阅读和操作顺序。右侧“预览”承载原页面的实际交互，包括查看、映射、改单、复核和导出；不做只能看不能操作的截图窗口。

只增加两类必要入口：

1. 现有统一设置的“页面”分区增加“工作方式：原布局／智算主窗口”，沿用原设置控件样式。
2. 新布局的大智算顶栏提供“返回原布局”与“打开／收起预览”。原布局顶部不额外堆常驻控件，避免挤动已验收页面。

“原布局／智算主窗口”是布局选项；现有“AI 增强／机械模式”是业务执行模式，两者必须分开，名称、状态和默认值不得混用。

## 4. 必须保留的原样式与组件

- 不重新画大智算、输入框、头像、Skill 菜单、复核卡、消息图表或专业页。
- 不采用 Demo 的全局头部、页签、项目选择器、原型导航、CSS、示例数据和模拟执行逻辑。
- 不改原导航顺序、模块名称、原表格工具条、Sheet 标签、报告纸张、按钮外观或业务文案。
- 不引入另一套字体、颜色、圆角、图标、组件库或主题。沿用自托管苹方、现有 `--dws-*` 令牌与唯一字号表。
- 允许新增范围仅为布局设置、必要窗口动作、分隔线和新布局的容器约束。新增规则限定于 `.shell.layout-daweiba` 下的新模式类；暗色再限定 `.theme-dark`。
- 原布局的已有外层结构、样式和窄屏适配保持。不得全局覆盖 Grid、通用 token、标签选择器，或顺手重构整个 `App.tsx`。

## 5. 状态与导航设计

### 5.1 分清布局、显示对象和业务上下文

建议新增 `workspaceLayoutMode: 'classic' | 'agent-primary'`，作为唯一布局状态。

现有 `activeDaweibaModule` 与专业子视图尽可能复用。需要给大会话持续可见、右侧专业对象、滚动与业务交互来源增加清楚的派生判断；必要时增加最小的专业对象字段，不建立第二套业务状态。

实现时分别核对“当前专业模块”“大会话是否可见”“指令从哪个会话入口发起”。不要直接全量替换所有 `activeDaweibaModule === 'agent'` 条件，也不要为保持会话显示而把右侧全部模块都冒充 `agent`。

必须保留同一份当前项目、Task、Skill 冻结快照、输入文件、job_id、成果、sheet、选中行、字段映射、改单草稿、聊天输入和等待状态。

### 5.2 右侧使用原页面

- “结果预览／Word 预览”、会话成果链接与相关导航，打开现有表格或 DOCX 组件。
- 复杂映射进入原新建填价页面；预警、工作量、结算和知识等继续使用原模块组件。
- 新模式下点击左侧专业模块只改变右侧工作对象，左侧大智算保持。
- 点击左侧“智算助手”聚焦同一大会话，不重置任务，不新建会话。
- 无结果时用原空态。未接通的能力保留原状态，不增加示例结果、假进度、假按钮。
- 任务操作仍调用原业务函数。表格点击行和行级追问仍传递真实行上下文到同一会话。
- 首次打开右侧时优先恢复最近的专业对象；缺少可信对象时使用原模块的空态。

### 5.3 收起、放大与返回

- 收起右侧预览后，大智算获得剩余空间；再次打开时恢复原对象、sheet、行和草稿。
- 宽表可沿用原最大化能力，或通过必要的临时放大动作增加右侧面积；恢复后回到同一会话与对象。
- 布局切换不得通过 reload、改变大块 JSX 的 `key`、复制工作区或重新获取当前成果来实现。
- 进入新布局时记录原布局的显示现场：模块及子视图、左右折叠状态、原 Dock 宽度和有价值的滚动位置。
- “返回原布局”恢复这份显示现场；期间真实产生的消息、任务进度、成果与已提交修改继续保留，不恢复旧业务数据。
- 不取消正在执行的真实任务，不重复开始匹配，不重新生成报告，不发送外部消息。布局切换本身只处理显示。
- Escape 优先交给当前弹窗、菜单或预览操作；不能在关闭局部浮层时同时退出布局。原专注模式的 Escape 行为仅在原条件下保留。

### 5.4 默认设置

建议首次交付默认 `classic`，用户手动选择新布局；以后需要把新布局设为默认，可只改集中默认配置并重新验收。

建议配置分组 `workspaceLayout`，包含合法 `defaultMode`；非法值、缺失值与读取失败均回落 `classic`。具体字段结构以实施时的既有规范为准，不把配置解析散落到各组件。

页面内切换默认仅当前会话生效，不新增 localStorage 持久化。异步默认设置到达后，不覆盖用户已经手动选择的工作方式。不要修改原业务默认值或小 Dock 的默认宽度。

## 6. 尺寸与性能边界

- 桌面优先，按实际容器分配空间，不固定在某一分辨率。
- 新模式默认可用工作区约 55% 给大智算、45% 给专业区，作为起点而非硬比例；提供可拖动且支持键盘的分隔线。
- 字体和控件尺寸沿用原组件；容器变窄时允许原文案自然换行，不能统一缩小字号。
- 宽表继续原横向滚动，DOCX 继续原分页和缩放，不把专业页整体缩成图片。
- 两区无法同时保持可用宽度时，新模式中采取可收起预览或受控单区显示；不得挤成无法操作的两条窄栏。
- P0 不重做手机或 iPad：`<=1024px` 保留原窄屏显示规则，新增布局仅在桌面有效。重新回到宽屏时可恢复当前会话选定的工作方式，不重置业务状态。
- 同一时刻只有一个可见会话输入窗口；新模式关闭原小 Dock 的显示与焦点入口，不能重复渲染消息、附件动作或触发模型。
- 隐藏预览中的地图／知识网络等计算画布应暂停或按原规则释放；保留必要业务草稿。不能为保留页面状态让不可见 Canvas 持续计算。
- 同一专业页面只有一个真实实例；布局切换不能重复挂载 iframe、重复轮询、重复读取 Word 或重复创建任务。

## 7. 实施顺序与验收

### 阶段一：保护原布局

保存当前脏工作区，明确本次修改范围。建立原布局的固定测试数据和截图／computed style 基线，涵盖原专业页＋小 Dock、原大智算专注模式、左右折叠、两种主题与原窄屏。

保留现有组件位置与结构，增加独立布局状态和新模式类。先让原大智算与原专业区并排，再接入布局设置和返回入口。不要先把旧页面重构成另一套框架。

### 阶段二：复用真实业务并验证导航

补齐专业对象路由、原任务操作与右侧预览联动；逐项核对滚动、Escape、离开页面保护、请求来源、画布生命周期和折叠副作用。新旧模式共同消费原业务函数和结果。

### 阶段三：通过以下门禁后交付

| 门禁 | 必须证明的结果 |
| --- | --- |
| 原布局保持 | 1366／1440／1920px 下原专业页、原大会话、折叠状态与关键 computed style 对照保持；新设置项为预期增补，其他控件不被挤动；原窄屏保持 |
| 同一会话 | Dock→原专注→新布局→原布局，消息、输入、任务与当前行无丢失、无双输入、无重复模型请求 |
| 预览无损 | 表格换 sheet、定位行、输入改单草稿，关闭／打开预览与切换布局后均保留；提交仍走原确认和保存链路 |
| 真实业务 | 真实文件上传、转换、匹配、预警、报告、表格与 DOCX 查看复用原行为；没有 Demo 数据或模拟成果进入正式页面 |
| 运行中切换 | 匹配、问答或报告执行中切换显示，只改变布局；不取消任务、不重复提交、不丢等待状态 |
| 空态与异常 | 无任务、无结果、API 失败、无报告、取消等显示原诚实状态，布局仍可返回 |
| 样式隔离 | 新模式的深浅主题分别核对字体、字号、行高、主按钮前景、关键截图与宽度；原模式公共样式无新增覆盖 |
| 生命周期 | 连续切换与预览开关不出现重复 Canvas、iframe、轮询或明显性能增长 |
| 正式成果回归 | 使用 V3.1 输入核对真实流程和对应 Excel／Word 答案；若差异存在，区分原有差异和本次引入，不能修改资料去凑答案 |

基础检查复用项目现有脚本：根目录 `npm run frontend:build`，前端 `test:agent-workspace`、`test:task-context`、`test:report-preview` 及必要的专项状态测试。新增测试关注原布局恢复、草稿保留和重复执行等真实边界，不机械复制样式实现。

若配置读取接口有变，补对应后端设置验证；若触及匹配逻辑，必须执行全量 `python -m pytest backend/tests -v`。本方案不要求修改匹配逻辑。浏览器验证与业务成果核对不能被构建或单元测试替代。
