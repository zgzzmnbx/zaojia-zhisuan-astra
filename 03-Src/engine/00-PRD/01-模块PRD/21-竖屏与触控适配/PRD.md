# 竖屏与触控适配 PRD

## 文件定位

本文承载造价智算网页在 iPad 竖屏和手机触屏环境中的增量适配要求。该能力不是第二套产品界面，也不改变现有桌面宽屏工作台；业务组件、数据状态、专业规则、接口和成果继续共用现有实现。

## 版本与状态

- 对应基线：`v5.22.0`；为保证桌面宽屏可见内容原样保留，本次不改页面与接口显示版本号。
- 当前状态：`[已完成]` 首版。
- 适配边界：浏览器布局视口宽度 `<=1024px`。
- 桌面冻结边界：布局视口宽度 `>=1025px`，现有界面必须保持原样。

## 用户目标

1. iPad 竖屏能够完成模块切换、上传、处理、查看结果、问问智算和成果下载。
2. 手机触屏能够完成基本业务操作，不被三栏固定宽度、浏览器动态地址栏或软键盘阻断。
3. 桌面宽屏的三栏布局、尺寸、字号、间距、颜色、交互和状态完全不因本功能发生变化。

## 需求清单

- [已完成] 新增独立 `compact-touch.css`，在现有主样式之后加载；所有规则只存在于 `max-width: 1024px` 或更窄媒体查询中。
- [已完成] 桌面端继续只由现有 `styles.css` 和模块样式控制，不修改现有主壳 DOM、桌面折叠状态、桌面宽度设置和本地偏好。
- [已完成] iPad / 手机将左侧模块入口收敛为横向触控导航带；保留全部真实模块入口，当前模块同时显示图标和名称，导航带可独立横向滚动。
- [已完成] 右侧智算在窄屏展开时变为覆盖式 Sheet：iPad 最大宽度 `440px / 92vw`，手机为全宽；收起后保留不遮挡主流程的触控入口。
- [已完成] 中间工作区改为单列可滚动区域；填价工作台的上传、转换概览和工作状态依次纵向排列，业务组件和处理状态不复制。
- [已完成] Excel 结果预览保持真实表格形态，仅允许表格、Sheet 标签和工具条在自身容器内受控横向滚动，不把宽表转换成可能丢字段的卡片。
- [已完成] Word、知识库、智能协同、结算审核和对话式工作台保留真实组件，并在剩余动态视口中运行。
- [已完成] 使用 `100dvh`、`env(safe-area-inset-*)`、`overscroll-behavior` 和 iOS 惯性滚动处理动态地址栏、安全区与触摸滚动。
- [已完成] 主要触控按钮和表单控件最小高度 `44px`；窄屏文本输入使用 `16px`，避免 iOS Safari 聚焦时自动放大；所有主操作继续使用可点击控件，不依赖 hover。
- [已完成] 深浅色、减少动态效果和既有业务状态色继续沿用当前设计系统，不增加第二套主题。

## 交互规则

### 模块导航

- 窄屏只收敛布局，不删减模块，也不建立新的模块状态。
- 当前模块入口在触控导航带中显示名称；其他入口保留现有 `aria-label / title`。
- 导航带只横向滚动自身，不得让页面产生横向滚动。

### 智算 Sheet

- 展开、收起继续使用现有智算状态和同一会话，不新建第二份消息流。
- 展开时覆盖在主工作区之上，不重新挤压 Excel 表格；收起后主工作区仍为全宽。
- 手机端 Sheet 占满可用宽度；iPad 竖屏保留少量背景上下文。

### 表格与表单

- 表格列、状态、人工复核和 AI 操作含义不变。
- 页面主壳不得出现横向滚动；只有明确的宽表承载区可以横向滚动。
- 拖拽上传继续保留，同时必须保留点击选择文件的完整能力。
- 弹窗不得超过动态视口；手机端使用接近全屏的内容区和内部滚动。

## 功能边界

### 桌面宽屏零回归硬门禁

以下任一项变化均判定本功能验收失败：

1. `1366px / 1440px / 1920px` 下左侧导航、中间工作区、右侧智算的坐标或宽度变化。
2. 现有桌面字号、行高、间距、边框、圆角、颜色、阴影或按钮状态变化。
3. 桌面端新增可见控件、隐藏原控件，或改变左侧 / 智算折叠偏好。
4. 上传、转换、表格、预警、报告、知识库、结算、协同和下载任一现有交互变化。
5. 为适配竖屏使用 `zoom`、`transform: scale()` 或复制第二套业务页面。

实现约束：

- 适配规则必须保存在独立文件中，并在基础样式之后加载。
- 不允许任何无媒体查询包裹的业务样式。
- 不允许出现 `min-width` 桌面覆盖规则。
- 不修改现有业务组件结构即可完成首版时，不为更接近原生 App 外观增加额外 React 状态。

## 验收口径

### 验收矩阵

| 场景 | 尺寸 | 验收重点 |
| --- | --- | --- |
| 手机竖屏 | `390×844` | 单列、触控入口、智算全宽、无页面横向溢出 |
| iPad 竖屏 | `768×1024` | 模块导航、主区全宽、智算 Sheet、表格受控滚动 |
| iPad Air 竖屏 | `820×1180` | 表单纵排、项目看板、弹窗与安全区 |
| iPad Pro 竖屏 | `1024×1366` | 正确进入触控适配边界，不恢复桌面三栏挤压 |
| 桌面笔记本 | `1366×768` | 原桌面界面不变 |
| 标准桌面 | `1440×900` | 与实施前基线坐标和计算样式一致 |
| 宽屏桌面 | `1920×1080` | 原三栏比例、表格空间和智算宽度不变 |

## 验证要求

1. 运行 `node --test tests/compactTouchLayout.test.ts`。
2. 运行 `npm run build`。
3. 运行 `python tools/check_ui_design_system.py`。
4. 使用浏览器逐项核对 `390 / 768 / 820 / 1024 / 1366 / 1440 / 1920` 宽度。
5. 桌面端至少比较实施前后的主壳 `getBoundingClientRect()`、`grid-template-columns`、padding、display 和 position。
6. 窄屏确认 `document.documentElement.scrollWidth === window.innerWidth`；宽表只能在指定内部容器滚动。

### 2026-08-13 验收结果

- 专项静态门禁 `3/3` 通过，前端生产构建、UI 设计系统检查、PRD 一致性巡检和后端版本接口测试 `76 passed, 2 skipped` 通过。
- `390 / 768 / 820 / 1024px` 均确认页面级横向溢出为 `0`；模块入口和主要按钮最小高度为 `44px`，智算 Sheet 展开与收起状态均可操作。
- `1366 / 1440 / 1920px` 均未命中窄屏媒体查询。`1440×900` 下全局导航、三栏主壳、左侧导航、中间内容、工作区和右侧智算的坐标、尺寸、Grid、padding、display、position 与实施前基线逐项相同。
- 本次未部署、未重启现有服务；真实 iPad / 手机设备的 Safari / Chrome 手感复核属于后续设备验收，不得以此为由改动桌面宽屏界面。
