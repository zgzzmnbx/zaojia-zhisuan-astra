## 已确认产品决策

1. 入口沿用左侧“填价工作台”，顶部二级页签固定为“项目看板｜全国项目｜地图展示｜新建填价”；“全国项目”保留原 L7 地理地图，“地图展示”作为独立展示页，不新增左侧一级菜单。
2. 宽屏地图视图的主视觉采用约 `68% 地图 + 32% 项目详情`；容器不足时改为地图全宽加详情抽屉，不挤压现有工作台。
3. 首版预置 8 个明确标记为“演示项目”的脱敏样例，和真实项目台账物理隔离；演示项目不进入 KPI、历史项目、模型调用统计或正式成果。
4. 空间类型从第一天支持数据建模：`POINT` 单点、`AREA` 区域、`CORRIDOR` 线路。首版三类都可展示，但 `AREA` 只以行政区中心点和柔和范围光晕表达，`CORRIDOR` 只画地区间示意线，不冒充真实施工走向。
5. 地点识别优先使用显式字段和离线行政区划词典；AI 只处理歧义、简称、线路名称和上下文关联，不能生成经纬度、行政区划代码或地图边界。
6. 所有从 Excel / AI 得出的地点先进入“待确认”状态；只有用户确认或人工录入后，才进入真实项目地图。模型自报置信度不等于确认。
7. 地点识别、地图加载或地图供应商故障不得阻断 Excel 填价、三个数字匹配、经验池预警、报告生成和成果下载。
8. 地图技术直接采用 AntV L7 核心包接入 React 生命周期，不使用已归档的 `l7-react`。本测试项目默认通过 L7 MapLibre 适配器加载 OpenFreeMap Positron 测试底图，不等待地图来源审批或审图号；后续如接入 Mapbox 外部样式，token / style 仍只从受保护运行环境读取，并保留无网 / 无 WebGL 降级。
9. 测试地图视觉参考[官方 L7 Quick Start](https://l7.antv.antgroup.com/tutorial/quickstart)的浅色面图层示例，使用低对比陆域填充、轻边界和必要文本标注；台湾岛仅提供测试轮廓，南海群岛使用 [Natural Earth 10m minor-islands](https://www.naturalearthdata.com/downloads/10m-physical-vectors/) 抽取代表点，均不表达正式行政边界、海域或制图成果。
10. 当前工作区存在与其他任务有关的未提交代码；实施必须只做增量修改，不重置、不清理、不全目录暂存，不覆盖他人改动。

## 用户与核心场景

### 场景 A：比赛展示

用户进入“全国项目”，默认看到 8 个带“演示项目”标记的脱敏项目。点击山东、河北或川渝线路，右侧立即显示项目名称、专业能力、状态、待复核 / 风险、最近成果和“查看项目”。随后切到“新建填价”，上传一份包含项目名称的 Excel，地图以琥珀色虚线轮廓显示新识别的位置建议；确认后变为正式项目标记。

### 场景 B：真实项目管理

用户切换到“本机项目”，地图只展示当前实例中已确认空间档案的真实项目。未确认、冲突或未识别的项目进入“待定位项目”列表，不在地图上假定位置。点击项目后复用现有详情和成果入口。

### 场景 C：长输管道项目

Excel 中出现：

```text
项目名称：铜梁/江津-遵义-贵阳天然气管道勘察测量（标段一）
```

系统识别为 `CORRIDOR` 候选，按文本顺序提出“重庆市铜梁区 → 重庆市江津区 → 贵州省遵义市 → 贵州省贵阳市”。地图只画柔和示意线，并常驻显示“示意线路，仅表示涉及地区，不代表真实施工走向”。用户可调整节点、顺序和空间类型后确认。

### 场景 D：无明确地点或名称有歧义

“西气东输三线中段”“长江 crossing”“朝阳站改造”等无法唯一映射到行政区时，系统返回“需人工选择”，展示原始证据和可能候选，不用名称相似度强行选中省市。

## 信息架构与页面布局

### 二级导航

实现后固定为：

```text
项目看板｜全国项目｜地图展示｜新建填价
```

- 四个页签属于同一“填价工作台”，共享当前文件、列映射、Task、项目、结果和下载状态；其中“全国项目”和“地图展示”共享项目地图 API 数据，但不共享选中态、筛选状态或渲染器。
- 切换页签不得重新上传、重新创建项目、重跑识别或清空当前确认草稿。
- “全国项目”代码和 L7 依赖独立懒加载，“地图展示”代码和本地展示几何也独立懒加载；用户未进入对应页面时，不请求该页地图数据、不创建 Canvas / WebGL 场景。
- 离开“全国项目”时销毁 L7 Scene、事件监听、ResizeObserver 和未完成请求；保留已加载的业务筛选和选中项目 ID，不保留不可控的渲染对象。

### 宽屏结构

当中间内容容器宽度 `>= 1180px`：

```text
┌────────────────── 全国项目 ──────────────────────────┐
│ [演示项目|本机项目] [筛选]                         图例 │
├──────────────────────────────────┬────────────────────┤
│                                  │  当前选中项目        │
│            中国地图 68%           │  项目名称            │
│    聚合点 / 单点 / 区域光晕 / 线路   │  地点与识别来源       │
│                                  │  状态与风险摘要       │
│                                  │  最近 Task / 成果     │
│                                  │  [查看项目] [修正位置] │
├──────────────────────────────────┴────────────────────┤
│ 待定位项目 3 个  ·  L7 测试模式 / 来源说明  ·  示意线路说明 │
└───────────────────────────────────────────────────────┘
```

当内容容器 `< 1180px`：

- 地图占满可用宽度，点击项目后打开现有风格的右侧详情抽屉。
- `<=1024px` 继续服从既有竖屏 / 触控隔离层；工具条可横向滚动，地图高度不小于 `52dvh`，触控目标不小于 `44px`。
- `>=1025px` 的原项目看板、新建填价和其他页面布局必须保持原样；不得以增加地图为理由统一重构主壳。

筛选条件默认不常驻在地图主视图中；点击“筛选”打开弹窗，在弹窗内编辑搜索、空间类型、状态、风险和日期。点击“应用筛选”后才刷新当前地图，取消或按 Escape 只关闭弹窗并丢弃未应用草稿；已应用条件以轻量标签显示并支持一键清除。

测试地图保留完整世界底图，默认使用 L7 `fitBounds` 聚焦中国；不限制用户继续缩放或拖动查看世界。中国陆域以低对比浅蓝填充并配轻边界，有项目省份沿用官方 L7 `fill_china` 示例的公开 GeoJSON 以蓝色 `PolygonLayer` 高亮；台湾岛以测试轮廓显示，南海群岛以 Natural Earth 10m minor-islands 抽取的代表点和文本标注显示。上述图层只服务于本轮测试视觉，不改变地点识别、坐标来源或真实项目空间档案，并常驻标注“非正式行政边界 / 测试示意”。

### 视觉语义

项目状态和风险必须分成两个视觉通道：

| 业务含义 | 视觉方式 |
| --- | --- |
| 处理中 / 正常项目 | 蓝青色实心核心点 |
| 已完成 | 鼠尾草绿色实心核心点 |
| 历史归档 | 灰色实心核心点 |
| 待复核 | 琥珀色外环；核心点仍表达项目状态 |
| 高风险 | 红色外环和图标；不得只靠红色 |
| 未确认位置建议 | 琥珀色空心 / 虚线标记，并显示“待确认”文字 |
| 当前选中 | 深蓝描边、轻微放大，不改变原状态色 |

动效只用于两种时刻：新识别地点出现、项目状态发生变化。呼吸最多 `2` 个周期后停止；`prefers-reduced-motion: reduce` 下完全关闭，不使用循环霓虹、飞线、扫描光或 3D 地球。

## 地点与项目名称识别规则

### 识别顺序

```text
R0 用户已输入 / 已确认值
→ R1 显式字段机械读取
→ R2 离线行政区划词典与项目名规则
→ R3 受限 AI 语义消歧
→ R4 人工确认 / 修正
```

高优先级结果可以阻止低优先级覆盖。后到 AI 响应不得覆盖用户输入、已确认位置、已拒绝建议或 revision 已变化的草稿。

### R0：用户值

- 用户已手工填写项目名称时，识别结果只作为对照建议，不覆盖输入框。
- 项目已有 `confirmed` 空间档案时，新文件识别结果进入“发现新候选”提示，不直接替换旧档案。
- 用户清除位置属于明确审计动作；清除后项目回到 `unlocated`，地图立即移除。

### R1：显式字段

字段名按归一化后匹配以下词组，优先级从高到低：

```text
项目名称：项目名称、工程名称、建设项目名称、任务名称
单点 / 区域：建设地点、项目所在地、工程地点、项目地点、建设区域、所在省市
线路节点：线路起点、起点、始发地、线路终点、终点、到达地、途经地、沿线地区
```

读取要求：

- 扫描被用户选择的 sheet 以及工作簿前部说明区；限制最大 sheet 数、行数和单元格字符数，超限时报告覆盖范围。
- 记录 `sheet_name`、`cell_address`、原始字段名、原始值、合并范围和读取方法。
- 合并单元格继续沿用全项目规则：跨行合并视为范围内每行有值；跨列合并只取第一列。地点识别不得另造一套合并语义。
- 同一字段出现多个不同值时返回 `conflict`，不能取最后一个或最长一个。
- 公式无缓存值、空值、占位符、说明示例和隐藏模板行不得当成真实地点。

### R2：词典与名称规则

离线行政区划词典至少包含：

```text
admin_code
province_name
city_name
district_name
aliases
parent_code
display_name
approved_longitude
approved_latitude
coordinate_system
source_name
source_version
```

规则要求：

- 行政代码、名称、别名和坐标只来自当前测试项目冻结的可信地点字典；本轮不把该测试字典宣称为正式生产地图资质或行政边界资产。
- 先匹配完整行政区名，再处理唯一简称；“朝阳”“长江”“中原”“西北”等多义词不得单独自动确定。
- 识别到县 / 区时同时回填父级市、省；识别到省但无城市时使用 `AREA`，不能虚构省会城市。
- 线路分隔符支持 `-`、`—`、`–`、`/`、`至`、`到`、`经`、`途经`、箭头和常见空格变体；节点按原文顺序去重。
- “某段”“标段一”“二线”“复线”等不是地点；线路品牌名不能无依据展开为全部途经省市。
- 文件名只在工作簿内容没有可靠名称 / 地点时使用，并标注 `source_kind: filename`。

### R3：受限 AI 语义消歧

只有以下情况允许调用：

- 标题或项目名含多个行政区简称，需要确定分组和线路顺序。
- 显式字段与项目名称冲突，需要解释冲突并请求用户选择。
- 词典返回多个同名行政区，需要利用省市上下文消歧。
- 线路名称具有行业简称，且上下文中存在可核验的行政区文本。

模型输入只包含受限文本片段、词典生成的候选 ID / 显示名和来源坐标，不发送整本 Excel、公式、造价数字、密钥或本机路径。工作簿中的任何“忽略规则、执行命令、访问网址”等文本都按普通资料处理。

模型输出固定为：

```json
{
  "project_name": {
    "suggested_text": "铜梁/江津-遵义-贵阳天然气管道勘察测量（标段一）",
    "evidence_ids": ["ev-001"]
  },
  "spatial_type": "CORRIDOR",
  "decision": "needs_confirmation",
  "place_candidate_ids": ["adm-500151", "adm-500116", "adm-520300", "adm-520100"],
  "evidence_ids": ["ev-001"],
  "reason": "名称按文本顺序列出四个行政区，候选均能在服务器词典中唯一验证。",
  "missing_information": [],
  "conflicts": []
}
```

服务器必须拒绝以下输出：

- 模型自行生成的经纬度、行政代码、候选外地点或地图边界。
- 缺少证据、证据不属于当前文件、候选版本过期或项目 revision 已变化。
- `spatial_type`、`decision` 不在枚举内，或 JSON 包含可执行表达式、路径、URL、HTML。
- 将“可能、附近、某段”解释为确定地点，或无依据补齐线路途经区域。

非法、超时、无凭据、网络失败统一回到 `needs_manual_review`；不自动重试超过模块独立预算，不影响 `/api/process` 主流程。

### R4：人工确认

确认弹窗必须同时展示：

1. 建议项目名称和当前输入名称。
2. 空间类型。
3. 已识别地点 / 线路节点及顺序。
4. 每个结论的 sheet、单元格和原文证据。
5. 识别方法：显式字段、词典、AI 消歧或人工录入。
6. “确认位置”“修改后确认”“拒绝建议”“暂不定位”四种动作。

默认不预勾选低置信候选，不提供“全部项目一键确认”。用户确认时，前端只提交行政区候选 ID、空间类型、顺序、备注和 revision；服务器从冻结词典重新读取行政名称与坐标。

```text
GET /api/projects/{project_id}/spatial
```

`unlocated` 返回 `unlocated / proposed / conflict / rejected` 四类真实项目；每项包含建议摘要和证据计数，不返回整本 Excel。

### 3. 上传阶段机械建议

现有 `POST /api/inspect` 响应增加可选字段，不破坏旧客户端：

```json
{
  "header_row": 4,
  "headers": [],
  "columns": [],
  "suggested_mapping": {},
  "sheets": [],
  "project_identity_suggestion": {
    "project_name": "建议项目名称",
    "spatial_type": "CORRIDOR",
    "decision": "needs_confirmation",
    "places": [],
    "evidence": [],
    "recognition_method": "dictionary",
    "needs_ai": false
  }
}
```

- `/api/inspect` 只运行机械读取与词典识别，不能因 AI 等待拖慢原 inspect。
- 返回字段为可选；旧测试和旧客户端不读取时行为不变。
- inspect 临时文件按现有生命周期处理，不在数据库中创建项目。

### 4. 将草稿附加到真实项目

现有 `POST /api/process` 增加可选表单字段：

```text

```

- 草稿只提交候选 ID、空间类型、顺序、证据引用和 inspect token / 哈希，不提交任意坐标。
- 项目创建成功后，服务器重新验证草稿并以 `proposed` 写入空间表；草稿无效时主处理继续，响应中显示 `project_spatial_tracking.status=needs_review`。
- 位置写入失败不得回滚已成功生成的 Excel / Word；只记录地图旁路失败。

### 5. AI 分析与人工确认

```text
POST /api/projects/{project_id}/spatial/analyze
PUT  /api/projects/{project_id}/spatial
```

`analyze`：

- 只读取该项目允许的最新 Run 输入或已保存证据；不接受前端任意路径。
- 请求体含 `run_id`、`revision` 和可选的用户补充上下文。
- 返回 `model_live / model_cache / mechanical / degraded` 实际模式、建议、证据和失败原因。

`PUT`：

```json
{
  "action": "confirm",
  "revision": 3,
  "spatial_type": "CORRIDOR",
  "place_candidate_ids": ["adm-a", "adm-b"],
  "note": "已核对项目名称"
}
```

- `action` 仅允许 `confirm / correct / reject / clear`。
- 服务器验证项目、revision、候选、顺序、坐标系和数据源版本后写入。
- 同一幂等键重复提交返回同一结果，不新增重复 revision。
- revision 冲突返回 `409` 并要求刷新；项目不存在返回 `404`；词典 / 台账不可用返回 `503`，不得返回半确认状态。

## 地图技术方案与测试边界

### L7 使用方式

- 使用 `@antv/l7` 核心能力和经 POC 验证的地图适配包，React 组件只负责创建 / 销毁 `Scene`、同步数据和处理事件。
- 不使用已归档 `l7-react`，不从 CDN 动态加载 JS / CSS，不把 API key 写入前端源码、仓库或 `project-default-settings.json`。测试模式默认使用 L7 MapLibre 适配器加载 OpenFreeMap Positron 样式，无需 token；地图区域保留 `OpenFreeMap © OpenMapTiles Data from OpenStreetMap` attribution。
- 依赖锁定到 G0 实测通过的明确版本，不使用 `latest`。升级地图依赖必须单独回归。
- 点、聚合、行政区域中心光晕和线路分层渲染；项目数增长时不得为每个点创建独立 React DOM 节点。
- 测试地图另以低对比 `PolygonLayer` / `LineLayer` 提供陆域和轮廓层；台湾岛仅为测试可见轮廓，南海群岛仅为 Natural Earth 10m minor-islands 代表点，不得当作正式行政边界、岛礁边界或海域数据。
- 地图组件、数据转换和样式放在独立模块根类，例如 `.project-spatial-map`；不修改 L7 全局 CSS、不污染 `.project-dashboard` 和主壳。

### G0 必须先确认的地图事实

正式生产地图开发前必须写入实施进度并留证；本测试项目本轮只冻结 L7 测试运行边界：

1. 测试渲染层固定为 `@antv/l7@2.29.1` + `@antv/l7-maps@2.29.1`，官方仓库 / npm 包采用 MIT 许可；默认通过 MapLibre 适配器加载 OpenFreeMap Positron 测试样式，并显示底图 attribution。
2. 测试地点坐标来自 `approved-admin-v1.json` 的冻结代表点记录，统一使用 WGS84；该资产仅用于测试位置示意，不冒充正式行政边界。
3. 本测试项目暂不要求地图来源审批、审图号或第三方底图 key；若配置 Mapbox 外部样式，token / style 只从受保护运行环境读取。
4. 无 key、无网、WebGL / L7 初始化失败时回到地点清单与代表点示意层，不阻断主业务。
5. AntV L7 与 React 19、Vite 8、TypeScript、现有浏览器和 Tauri 开发壳的小样兼容性。

未满足正式生产地图事实时，可以完成本测试项目的 L7 地图、数据模型、识别器和降级列表，但不得把 OpenFreeMap 测试底图或代表点宣称为正式中国地图成品，也不得用于正式制图成果。

### 离线与失败降级

| 故障 | 页面行为 | 主业务 |
| --- | --- | --- |
| 地图脚本 / WebGL 初始化失败 | 显示项目地域列表、待定位列表和重试按钮 | Excel、项目看板正常 |
| 底图无网 / key 缺失 | 显示“地图底图暂不可用”，不泄露 key 细节 | 地点识别和确认仍可工作 |
| 行政区划词典失败 | 禁止确认新位置，已有确认档案只读展示 | 不影响三个数字与成果 |
| AI 超时 / 无凭据 | 保留机械候选并提示人工选择 | 不阻断 inspect / process |
| 地图 API 503 | 全国项目局部失败，不让主 App 白屏 | 其他模块可切换 |
| 单个项目坐标非法 | 隔离该项目并进入待定位列表 | 其他项目继续显示 |

## 测试矩阵

### 冻结识别样例

实现前创建至少 30 个不含敏感信息的冻结样例：

| 类别 | 最少数量 | 必须覆盖 |
| --- | ---: | --- |
| 显式字段 | 8 | 建设地点、项目所在地、工程地点、起点 / 终点、冲突字段 |
| 项目名 / 文件名 | 8 | 完整省市名、唯一简称、多分隔符、标段名、无地点 |
| CORRIDOR | 6 | 跨区、跨市、跨省、重复节点、顺序、只有一个节点 |
| 歧义与拒绝 | 6 | 朝阳、长江、中原、西北、线路品牌名、候选冲突 |
| 合并 / 公式 / 异常 | 2 | 跨行 / 跨列合并、公式无缓存、超长文本 |

机械结果必须逐项对照行政代码、空间类型、节点顺序、证据坐标和拒绝原因。AI 留出样例不得参与提示词调试；模型正确选择或正确拒绝均算有效，错误行政区不得被自动确认。

5. `/api/process` 空间草稿有效、无效、过期和写入失败时，主填价不受影响。
6. AI JSON schema、候选白名单、证据归属、超时、无 key、非法输出、提示注入和晚到响应。
7. 人工确认幂等、revision 冲突、候选版本冲突、清除 / 拒绝和审计前后值。
8. demo / real 数据域隔离，演示项目不进入台账和统计。
9. 地图查询筛选、上限、脱敏、无权限 ID、非法 ID 和单项目数据隔离。
10. 空间模块异常不改变项目、Run、成果和三个数字。

### 前端专项

至少验证：

1. 三页签切换保持上传文件、映射、当前 Task、结果和选中项目状态。
2. 地图 chunk 只在首次进入“全国项目”时加载；未进入时无 L7 Scene。

5. 聚合点、单点、AREA 光晕、CORRIDOR 示意线、悬浮、点击、键盘和触控。

10. 新 CSS 无 9px / 10px 可见业务文字，不污染项目看板、新建填价和其他模块。

### 性能与资源门禁

- inspect 机械地点识别以 10 份冻结、单文件不超过 10MB 的 `.xlsx` 测量增量耗时：中位数不超过 `0.8s`，P95 不超过 `2.0s`；超出时先优化扫描范围和缓存，不把 AI 放入同步 inspect。
- 100 个已确认项目、20 条示意线路的本机数据下，地图数据返回后 `2s` 内完成首屏可交互；筛选和选择不触发整页刷新。
- 地图依赖必须形成独立懒加载 chunk；首页和未进入地图的填价工作台不得加载 L7 运行代码。
- 连续进入 / 离开地图 10 次，活动 Scene、ResizeObserver 和自建事件监听数量不增长；控制台无 WebGL 泄漏、重复绑定和未处理 Promise。
- AI 调用使用独立超时和最多一次受控重试，总等待预算首版不超过 `20s`；超时即人工复核，不阻断主业务。
