## 四、必须交付的产品结果

### 1. 两套真实检索模式

保留现有模式并正式命名为：

```text
经典检索
```

它继续使用现有问题拆分、规则扩词、加权关键词、结构化计价库偏好、来源优先级和证据约束，行为不得退化。

新增模式命名为：

```text
混合 RAG
```

混合 RAG 必须真实包含：

```text
BM25 / 词法召回
+ 结构化字段召回
+ 本地向量语义召回
+ 多路去重与排名融合
+ 权威等级和字段硬约束门控
+ 可选轻量重排
+ 证据充分性判断
+ 受约束大模型回答
```

不能只把现有评分函数改名为“混合 RAG”，也不能只有向量检索而缺少精确与结构化通道。

### 2. 检索模式切换按钮

- 在问问智算现有“选择知识库”控件旁新增紧凑分段按钮：`经典检索｜混合 RAG`。
- 默认 `经典检索`。
- 宽屏智算助手与右侧 Dock 共用同一选择状态；窄 Dock 自动换行，不横向溢出。
- 仅知识库问答生效；普通聊天和批量匹配、预警、下载等动作不受影响。
- 每条消息发送时冻结检索模式；历史消息显示当时实际模式。
- 用户偏好保存在浏览器本地；项目默认仍来自 `config/project-default-settings.json`。
- 后端未准备好混合索引时，按钮必须禁用并显示“索引尚未就绪”，不能静默伪装成功。
- 四道预置演示题继续直接返回审核答案，不调用任何检索 / 大模型，也不能因为按钮状态而伪造混合 RAG 过程。
- AI填价结构化候选保持原排序和人工确认边界；本任务不让切换按钮改变数字候选。

### 3. 请求、响应与能力探测

保持现有接口兼容：

```text
POST /api/knowledge/search
POST /api/knowledge/ask
```

新增可选请求字段：

```json
"retrieval_mode": "classic | hybrid"
```

未传时必须走 `classic`。响应至少返回：

```text
requested_retrieval_mode
retrieval_mode_used
fallback_mode
fallback_reason
retrieval_trace.query_parts
retrieval_trace.channel_hit_counts
retrieval_trace.evidence_status
```

增加真实能力探测：混合 RAG 是否可用、索引状态、模型版本、最近构建时间。前端按钮必须使用后端真实状态。

### 4. 查询理解与硬约束

继续复用现有三段式拆分，只把“业务检索问题”送入召回。确定性提取并保护：

```text
清单编码 / 序号 / 条款号
数字 / 百分比 / 费率 / 系数
比例尺 / 管径 / 单位 / 等级 / 复杂程度
表号 / 模块 / library_ids / skill_id / project_key
```

“请用表格”“只回答”“给我讲原理”等要求只影响回答组织，不得污染召回。

向量相似不能覆盖上述硬约束。`0.22` 不能误成 `0.2`，`1:50000` 不能误成 `1:5000`，清单编码不能模糊近似。

### 5. 索引、融合与门控

- 正式资料和治理后的知识记忆是真源；所有词法 / 向量索引都是 Git 忽略、可重建缓存。
- Markdown 按标题和段落分块；Excel / CSV 按表头 + 单行记录分块；规则卡保留 ID、条件、例外和正式性。
- 为每块保存 library、Skill、项目、来源类型、标题 / sheet / 行号、权威等级、内容签名和模型版本。
- 多通道使用排名融合，不直接相加不同量纲的原始分数。
- 正式标准、项目规则和结构化精确命中的权威优先级独立于语义相似度。
- 项目记忆与正式依据冲突时，正式依据优先并进入人工复核；重排器不得裁决正式口径。
- 重排器只能重排候选，不能生成新证据。

### 6. 降级与故障边界

- 向量模型或索引不可用：自动降级经典检索。
- 向量召回超时：先用词法 + 结构化候选；仍失败再降级经典检索。
- 重排异常：直接使用融合排名。
- 零证据：明确提示“已自动转为大模型回答”，再调用普通大模型兜底；响应保持 `evidence_found=false`、来源为空，并标明兜底答案不属于知识库依据。
- 大模型不可用：保留检索依据摘要，专业主流程继续可用。
- 回答必须显示实际使用的模式和降级原因。

任何故障都不能修改原始 Excel、输出副本、结构化计价库、规则表、经验池或知识真源。

## 五、技术选型要求

先用标准题集做小规模技术验证，再确定本地 embedding 模型、向量索引库和是否启用重排器。选择必须同时满足：

- 中文业务问法效果。
- 可离线运行。
- 许可证允许项目使用和分发。
- Windows 开发版 / 绿色版、Linux 云端可运行。
- 模型体积、内存、首次索引时间和 P95 检索时延可接受。
- 模型和索引有明确版本，升级可重建、可回滚。

不要默认接入外部向量 SaaS。任何外部 embedding / rerank 服务都需要单独授权、脱敏、秘密隔离和可关闭降级；未获明确授权时使用本地方案。

把最终选型、许可证、模型体积、依赖、资源数据和取舍写入模块文档，不要只留在聊天中。

## 七、评测先行

在改默认行为前，先冻结并记录现有经典检索基线。扩充：

- 精确编码 / 数字 / 比例尺 / 单位题。
- 简单解释题和复杂约束题。
- 同义改写、口语表达和省略术语题。
- 跨文档互补证据题。
- 正式依据与项目记忆冲突题。
- 无依据但语义相似的诱导题。

必须保留现有 `0.22` 表2例外、表3系数、清单编码、数字化费率、走向图比例尺、过路过桥费和无依据题。黄金答案不仅标关键事实，还要标黄金证据 / 来源定位。

最低验收：

```text
经典模式现有题全部不退化
数字 / 编码保护集 Recall@5 = 100%
混合模式总体黄金证据 Recall@5 >= 95%
引用准确率 >= 95%
无依据题误答率 <= 5%
热索引检索 P95 目标 <= 1.5 秒（记录验收硬件）
向量、重排或模型故障时经典检索与专业主流程仍可用
```

如果混合模式没有可复现提升，就保持其为手动可选，不得把它改成默认。

## 八、UI 要求

- 严格复用 `大尾巴 Shadcn UI v1.0.0`、`--dws-*` 令牌、自托管苹方和 Lucide。
- 不使用渐变背景、常驻大阴影、高饱和红字或第二套组件库。
- 按钮、标签、正文和辅助说明字号必须对照 `00-PRD/03-UI设计规范.md`，并在运行态核对 computed font-size / weight / line-height。
- 进度按解析问题、词法检索、结构化检索、语义检索、融合重排、证据核验、组织回答逐阶段推进；不能一开始接近 90%。
- 普通用户只看简洁模式和来源摘要；现有调试模式可展开通道命中、融合排名、重排、冲突和降级原因。
- 按钮必须支持键盘、焦点、`aria-label` 和选中状态。
