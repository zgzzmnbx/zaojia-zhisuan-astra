# 造价智算知识库检索讲解手册

> 适用版本  v5.19.7
> 混合 RAG 首版  v5.19.5
> 整理日期  2026-08-11

这份手册用于把当前知识库问答讲清楚。前半部分可以直接拿来向领导、评委或同事介绍，后半部分保留操作方法、评测数据和技术口径，遇到追问时可以继续往下讲。

## 先记住一句话

造价智算会先从本地正式资料、项目规则和已确认知识记忆中找证据，再让大模型根据证据组织回答。检索结果只服务知识问答，不参与基价、调整系数和正式价格裁决。

## 三十秒介绍

可以直接这样讲。

> 我们给知识问答准备了经典检索和混合 RAG 两条真实路径。经典检索稳定、速度快，所以继续作为默认方式。混合 RAG 会同时使用关键词、结构化字段和本地向量找资料，再综合多个通道的排名。系统还会核对数字、编码、比例尺和单位，尽量拦住看起来相近、实际口径不同的材料。大模型只负责把检索到的依据讲明白，没有依据时会明确提示人工复核。它不会生成价格，也不会替代结构化计价规则。

## 一分钟介绍

造价智算里的知识问答分成三层。第一层是项目正式知识库，包括标准资料、项目规则、规则卡片和结构化计价依据。第二层是造价通用知识库，用于查询更广泛的造价资料。第三层是已经审核确认、仍在有效期内的知识记忆。

提问后，系统先在用户选中的资料库里找证据。经典检索沿用已经验证过的扩词和加权关键词方案。混合 RAG 在这套能力之外增加 BM25、结构化字段召回和本地离线向量召回，然后去重、融合排序，并用权威等级和精确字段做门控。可选重排只调整已有证据的先后顺序。

系统把正式资料放在最高优先级。遇到数字、编码、比例尺、费率或单位时，候选材料需要满足精确约束。资料互相冲突时，回答会显示证据冲突并提示复核。完全找不到可靠依据时，系统会提示“已自动转为大模型回答”，再输出不带知识库来源的普通大模型兜底答案。

## 当前能检索哪些知识

截至 2026-08-11，当前配置里有三类可选知识库。

| 知识库 | 当前内容 | 默认选择 | 使用边界 |
| --- | --- | --- | --- |
| 项目正式知识库 | 当前专业 Skill 绑定的标准资料、项目规则、规则卡片和结构化计价依据 | 是 | 项目问答和专业复核的首要依据 |
| 造价通用知识库 | 造价 AIW 问答资料，当前按 Markdown 资产载入 | 否 | 适合普通依据查询，行级勘察测量复核不纳入 |
| 已确认知识记忆 | 已确认且未失效的通用、项目或任务知识 | 是 | 正式标准和项目规则始终优先，项目知识还要通过项目标识隔离 |

当前目录扫描结果为项目正式资料 23 个、造价通用资料 13 个。这个数量会随着正式资料和配置调整而变化。

项目正式知识库当前主要覆盖下面这些内容。

- 项目说明、产品边界和知识问答规则
- 勘察测量相关标准资料与项目规则
- 基价、单价和两类调整系数的规则说明
- 要素 1 到 5 与单位的同类识别口径
- 第一层标准规则命中表
- 二维结构化计价库中的规则卡片
- 技术工作费、实物工作费相关 CSV 和 Excel 规则资产

造价通用知识库当前主要覆盖造价 AIW 资料，例如工程量清单单价、其他费用和数字与信息化项目计价依据。它需要用户在知识库选择器中主动勾选。

## 真源、索引和知识记忆的区别

这三个概念很容易混在一起。

| 名称 | 可以怎么理解 | 丢失后的处理 | 是否属于正式依据 |
| --- | --- | --- | --- |
| 正式资料和规则 | 原始档案和已批准口径 | 从正式文件恢复 | 是 |
| 检索索引 | 为了快速查找制作的目录和卡片 | 可以从正式资料重新生成 | 否，它只帮助找到原文 |
| 知识记忆库 | 经过候选、审核、确认和审计的经验知识 | 按运行数据单独备份和迁移 | 只有已确认且未失效的记录可以参与问答，权威仍低于正式资料 |

当前检索引擎直接读取和切分 Markdown、Excel、CSV。PDF 还没有进入现行 OCR 索引流程。需要使用 PDF 内容时，应先转换成受支持的可审查资料，再纳入正式知识源。

索引位于 `Codex-Temp/runtime`，属于可重建缓存。知识记忆数据库是 `Codex-Temp/runtime/knowledge-memory.sqlite3`，保存记录、版本和审计，不能按普通索引缓存处理。

## 一次提问怎样完成

```text
用户选择知识库和检索模式
        ↓
系统识别真正要查的业务问题
        ↓
在所选知识源中召回原始知识块
        ↓
执行精确字段和权威等级检查
        ↓
判断证据充分、冲突或不足
        ↓
有证据时交给模型整理回答
        ↓
显示来源、实际模式和降级状态
```

用户如果在问题里同时写了输出格式和补充说明，程序会把它们与业务检索问题分开。只有真正要查询的业务部分进入检索，避免“用 Markdown 表格回答”之类的要求污染召回词。

## 经典检索怎样工作

经典检索是当前默认稳定路径。它会切分问题、扩展业务近义表达，并按关键词、标题、字段和来源权重计算候选顺序。

它适合下面的情况。

- 问题里的标准名称、编码或数字比较明确
- 日常查询追求稳定和较低等待时间
- 需要沿用已经长期回归验证的检索结果
- 混合索引尚未就绪或发生故障

旧客户端没有传入检索模式时，后端固定使用经典检索。这保证了老入口和原有调用方式继续可用。

## 混合 RAG 怎样工作

混合 RAG 会让几种检索方法同时找资料，再综合判断。这里的 RAG 可以理解为“先检索依据，再根据依据生成回答”。

| 环节 | 人话解释 | 主要价值 |
| --- | --- | --- |
| BM25 | 看问题和资料里哪些词出现得准、出现得有区分度 | 擅长标准名称、专业词和少见词 |
| 结构化召回 | 单独识别编码、数字、比例尺、单位等字段 | 擅长精确值和表格规则 |
| 本地向量召回 | 把文字转换成 384 维本地确定性特征，再计算相似度 | 补充改写题和字面不完全一致的表达 |
| 去重 | 合并内容相同或高度重复的候选 | 避免同一依据反复占位 |
| RRF 融合 | 综合多个通道的名次投票 | 避免某一个通道单独决定结果 |
| 硬门控 | 核对权威等级、数字、编码、比例尺和单位 | 拦截相似但口径不一致的材料 |
| 规则重排 | 结合权威性和各通道得分调整最终顺序 | 让更可靠、更贴题的证据靠前 |
| 证据判断 | 标记证据充分、证据冲突或证据不足 | 决定能否进入回答阶段 |

首版本地向量模型叫 `local-hash-embedding-v1`。它只使用 Python 标准库，不下载神经网络模型，也不调用外部向量服务。它的优点是离线、确定、容易发布，语义覆盖能力仍有继续提升空间。

重排模型叫 `local-rule-rerank-v1`。它根据已有候选的权威等级和通道分数调整顺序。它不能添加索引外的内容，也不能制造新依据。

## 数字和正式依据怎样守住

造价问答里最危险的问题往往来自“看起来很像”。两个段落可能只差一个小数、一个编码位数或一个单位，业务结论却完全不同。

混合模式会先从问题中提取需要严格核对的字段。

| 字段 | 典型内容 | 保护方法 |
| --- | --- | --- |
| 数字 | `0.22`、`5000` | 候选证据必须包含可核对的等价值 |
| 编码 | `10101002` | 按完整编码约束候选，不用模糊相似替代 |
| 比例尺 | `1:500` | 比例尺口径需要一致 |
| 单位 | `万元`、`km` | 数值和单位一起判断 |
| 权威等级 | 正式标准、权威规则、结构化规则、项目说明、通用参考 | 高权威来源优先，低等级材料不能覆盖正式规则 |

硬门控发生在排序前。候选材料连基本精确条件都不满足时，不会因为向量相似而挤进答案依据。

## 大模型在这里负责什么

大模型负责把已经找到的证据整理成容易阅读的结论、表格和解释。它可以概括规则，说明引用位置，也可以按用户要求调整回答格式。

它没有以下权限。

- 不能凭空补出检索结果里没有的依据
- 不能裁决正式资料之间的冲突
- 不能生成或确认最终价格
- 不能改变基价、实物工作费调整系数和技术工作费调整系数
- 不能把一个项目的知识记忆自动带到另一个项目

在混合模式中，如果大模型不可用，接口仍会根据已有证据返回简化回答，并标记 `evidence_fallback`。经典模式沿用原有调用边界。

## 为什么不会改动填价结果

知识问答和结构化计价是两条隔离的业务路径。

知识问答可以解释某条依据、展示候选来源、提醒人工复核。正式填价仍由二维 Excel 数据库、匹配规则和人工确认完成。三个数字的裁决也继续走既有结构化规则。

因此，用户在经典检索和混合 RAG 之间切换，只会改变知识问答怎样寻找证据，不会改变 AI 填价候选、经验池预警、工作量抓取、报告计算或 Excel 写值。

## 两种模式怎样选择

当前建议很明确。日常默认使用经典检索，遇到改写、长问题、跨资料查找或经典结果不理想时，再主动切换混合 RAG。

| 使用场景 | 建议模式 | 原因 |
| --- | --- | --- |
| 明确编码、标准名称、数字快查 | 经典检索 | 稳定、速度更快，精确保护集表现相同 |
| 普通日常知识问答 | 经典检索 | 当前默认路径，已有长期回归基础 |
| 口语化改写或字面差异较大 | 混合 RAG | 多通道召回能补充单一关键词路径 |
| 一个问题跨越多个资料 | 混合 RAG | 融合排序更容易汇总不同来源 |
| 需要观察证据通道和降级轨迹 | 混合 RAG | 返回 BM25、结构化、向量和重排状态 |
| 混合索引不可用 | 经典检索 | 系统会禁用混合入口或自动降级 |

当前评测结果也支持继续保留这个选择。

| 指标 | 经典检索 | 混合 RAG | 怎么理解 |
| --- | --- | --- | --- |
| 黄金证据 Recall@5 | 1.000 | 1.000 | 当前保护集的黄金依据都进入前五 |
| 精确保护集 Recall@5 | 1.000 | 1.000 | 数字和编码保护题均命中 |
| 引用准确率 | 1.000 | 1.000 | 评测中的前五引用集合完整支撑黄金证据 |
| 无依据误答率 | 0 | 0 | 无依据题没有被强行回答 |
| nDCG@10 | 0.950597 | 0.951188 | 混合模式排序质量只小幅领先 |
| 热检索 P95 | 969.823 ms | 1428.589 ms | 混合模式约多 458.766 ms，仍低于 1.5 秒目标 |

评测题集共 12 项，其中 8 项进入检索指标，4 道预置演示题因绕过检索而单独统计。这个样本可以证明当前保护题没有退化，仍需要继续积累真实业务题，才能判断更多口语表达和长尾资料的表现。

这里的引用准确率是评测文件里的专门口径，表示前五引用集合对黄金证据的支撑比例。它不能替代用户对回答正文和正式原文的最终核对。

## 在界面里怎样使用

### 从知识库问答页面切换

1. 打开左侧的“知识库问答”。
2. 在“知识库状态”中先选择要查询的知识库。
3. 在知识库选择器下方找到“经典检索”和“混合 RAG”分段按钮。
4. 选择一种模式后再发送问题。
5. 回答下方查看请求模式、实际模式、证据状态和降级提示。

### 从右上角设置切换

1. 点击右上角设置按钮。
2. 打开“统一设置”。
3. 进入“页面设置”。
4. 在“知识库问答”区域切换检索模式。

两个入口共用同一个状态。当前选择保存在本机浏览器偏好中，刷新页面后可以恢复。每条已经生成的历史消息会冻结当时的请求模式和实际模式，之后切换不会改写旧消息。

混合索引未就绪、损坏或能力探测失败时，混合按钮会禁用，页面继续保留经典检索。进入知识库页面时，后端会对尚未构建或已经过期的混合索引尝试重建。

### 强制进入知识库问答

在普通对话中，可以在问题前加以下任一前缀。

- `查库：`
- `查库:`
- `#知识库`

这会把问题明确路由到知识库问答。资料库选择、项目隔离和检索模式仍按当前页面状态执行。

## 怎样判断这次回答是否可靠

先看回答下方的检索轨迹。

| 页面信息 | 需要看什么 |
| --- | --- |
| 请求 | 用户当时选择了哪种模式 |
| 实际 | 系统最终使用了经典、混合或预置答案 |
| 证据状态 | 证据充分、证据冲突、证据不足或预置答案 |
| 已降级 | 哪个能力失败，系统采用了什么替代路径 |
| 来源依据 | 文件名、标题路径和对应证据片段 |
| 已确认记忆 | 回答是否使用了治理后的知识记忆 |

然后检查三个问题。

1. 来源是否属于本题应该使用的知识库。
2. 数字、编码、单位和适用条件能否在原文中对应上。
3. 回答有没有越过“解释依据”的边界，擅自给出最终价格或规则裁决。

涉及正式结论时，应打开来源原文复核。系统给出的排名代表检索相关性和权威性判断，不等同于签字审批。

## 怎样公平比较两种模式

四道预置演示题会在检索和模型之前直接返回人工审核答案，页面实际模式显示“预置演示答案”。这些题不能用来比较经典检索和混合 RAG。

可以按下面的方法做一次公平对比。

1. 固定同一组知识库。
2. 选择一条没有出现在预置问题中的真实问题。
3. 先用经典检索提问并记录来源、证据状态和等待时间。
4. 原样复制问题，切到混合 RAG 后再次提问。
5. 比较前五条证据是否包含正确原文，关键数字和单位是否一致，答案有没有提示冲突或降级。

如果两个模式都找到同一份正式依据，优先使用响应更快的经典检索。经典模式漏掉了正确改写或跨资料证据时，再采用混合 RAG 的结果，并继续核对原文。

## 发生故障时会怎样

| 故障 | 用户看到的结果 | 系统处理 |
| --- | --- | --- |
| 混合索引未构建或已过期 | 混合按钮暂不可用 | 尝试重建索引，经典模式继续工作 |
| 混合索引损坏 | 能力探测显示不可用 | 关闭混合入口并保护经典路径 |
| 向量通道不可用 | 回答标记降级 | 继续使用 BM25 和结构化召回 |
| 重排超时 | 回答标记降级 | 保留融合排序结果 |
| 大模型不可用 | 回答标记证据降级 | 混合模式返回基于证据的简化回答 |
| 没有可靠证据 | 显示“已自动转为大模型回答” | 输出无知识库来源的普通模型兜底，并保留业务边界提示 |

故障注入报告已经记录一次完整恢复过程。损坏索引时出现 `hybrid_vector_index_corrupt: invalid JSON`，随后分别验证向量不可用、重排超过 180 ms 和模型不可用的降级路径。索引恢复后重新生成 4014 个知识块，返回 5 条结果，证据状态恢复为充分。

## 知识记忆怎样进入问答

知识记忆用于保存经过治理的经验知识。新内容先成为候选，再经过审核和确认。只有状态为已确认、仍在有效期内的记录可以参与问答。

通用知识可以在所有项目中使用。项目知识和任务知识需要项目标识完全一致，避免跨项目串用。正式标准或项目规则与记忆发生冲突时，正式资料优先，相关记忆应进入疑似失效或人工复核流程。

当前默认审核策略只允许“操作方法”和“一般解释”两种低风险通用知识自动通过。项目口径、价格、系数、正式标准和冲突项仍需人工确认。

知识记忆库异常时，系统会降级到现有正式知识库问答。Excel、预警和报告主流程不受它阻断。

## 常见追问怎么回答

### 这是不是在网上搜索

当前知识检索使用项目内本地资料和已确认记忆，不调用外部向量服务。有证据时，大模型只依据证据组织回答；零证据时，系统明确切换为普通大模型兜底，并保持来源为空。

### RAG 到底是什么

RAG 是“检索增强生成”。在这个项目里，它的顺序很清楚。程序先找依据，模型再根据依据写回答。

### 为什么保留两种模式

经典检索速度更快、已有稳定基线。混合 RAG 增加了多通道召回和降级能力，适合难查、改写和跨资料问题。两条路径并存后，现场可以按风险和问题难度选择。

### 混合 RAG 一定更好吗

当前题集里，它的黄金证据召回和经典模式相同，排序指标略高，等待时间也更长。它提供了更多找资料的角度，实际收益取决于问题类型。现阶段保留手动选择更稳妥。

### 向量最相似能直接作为答案吗

不能。向量只提供一个召回通道。候选还要经过精确字段、权威等级、融合排序和证据充分性检查。

### 它会不会给工程自动定价

不会。知识问答只做依据检索和解释。基价、单价、实物工作费调整系数和技术工作费调整系数继续由结构化规则和人工确认控制。

### 没查到会怎么回答

系统会明确提示“已自动转为大模型回答”，随后提供普通大模型的一般性回答。该回答不属于知识库依据，不得伪造价格、系数、标准出处或项目事实；涉及正式业务口径时仍以项目规则和人工复核为准。

### 正式资料和知识记忆冲突时听谁的

正式标准、权威规则和结构化规则优先。知识记忆需要被标记为疑似失效并交给人工处理。

### 为什么有时选择混合模式，回答却显示经典检索

这表示混合能力不可用或运行中发生故障，系统已经降级。查看回答下方的“已降级”信息可以看到原因。

### 为什么有时显示预置演示答案

四道演示题使用人工审核答案，专门保证现场展示稳定。它们在检索和模型调用之前直接返回，所以实际模式会显示“预置演示答案”。实质改写后会回到正常检索。

### 新资料怎样加入

先把资料纳入受控知识源和对应资料库配置，再重建索引。正式资料本身继续作为真源，不能为了迎合检索结果修改原文。

## 面向领导或评委的收口说法

可以用下面这段话结束介绍。

> 这套知识问答的价值，在于把本地正式资料、结构化规则和可治理记忆放进同一套可追溯流程。用户可以在经典检索和混合 RAG 之间主动选择，系统会显示实际使用的模式、证据状态和降级原因。有证据时模型只讲依据；零证据时明确转为无知识库来源的普通大模型回答。价格和正式规则仍由结构化业务系统与人工复核守住。

## 不应使用的说法

下面这些说法会夸大系统能力，应避免。

| 不应这样说 | 更准确的表达 |
| --- | --- |
| AI 会自动学会所有项目经验 | 经验先进入候选和审核流程，确认后才能参与问答 |
| 向量最相似就是正确答案 | 向量只是一个召回通道，还要经过硬门控和权威排序 |
| 混合 RAG 会自动确定价格 | 混合 RAG 只服务知识问答，价格仍由结构化规则和人工确认 |
| 系统查不到时模型仍可当作知识库回答 | 零证据时会明确转普通大模型兜底，来源为空，不得冒充知识库依据 |
| 选了混合模式就一定使用成功 | 每条回答会显示请求模式、实际模式和降级原因 |

## 最后只背五句话

1. 先检索本地证据，再让模型组织回答。
2. 经典检索默认稳定，混合 RAG 由用户主动打开。
3. 混合模式同时使用关键词、结构化字段和本地向量，并受精确字段与权威等级约束。
4. 没有依据就提示人工复核，模型不能生成价格或裁决正式规则。
5. 两种模式都真实存在、可以评测，也能在故障时降级。
