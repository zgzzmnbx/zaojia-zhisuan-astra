# 结算审核助手模块 PRD

## 模块目标

面向长输管道勘察测量结算编审场景，新建一套与现有最高投标限价填价链路隔离的“结算审核助手”。系统读取前辈提供的统一结算报价模板，依据模板参数、确定性算术规则和已明确的结算审核经验，对承包商上报数据进行结构化辅助审核，输出：

1. 审核风险清单与待人工核验事项；
2. 已写入“造价审核”栏的 Excel 副本；
3. 可归档的 Word 辅助审核报告。

本模块服务于竞赛演示和真实业务试点，首期目标是跑通“上传结算表 → 规则审核 → 风险解释 → 下载审核后 Excel 与 Word 报告”的完整闭环。系统只提供可追溯的审核建议，不替代专业审核、造价审核、合同判断和最终签章。

## 参赛价值

- **创新性**：把前辈经验、统一模板、确定性规则、结构化风险、人工复核和双成果输出组合为可运行的专业审核工作台，而不是让大模型自由判断结算金额。
- **作品完整性**：形成一条真实、可演示、可验证、可追溯、异常可降级的结算审核闭环；即使没有大模型或外部服务，核心审核仍可本地运行。
- **可信边界**：规则负责计算和提示，模型仅可在后续解释依据，最终结论必须由专业人员确认。

## 功能边界

本模块只对统一结算模板及同结构 `.xlsx` 中可确定读取的参数、公式和资料索引进行辅助审核。合同适用性、工程量真实性、成果完整性、付款真实性、签章效力和最终审定结论必须由专业人员确认；任何缺少明确依据的项目均降级为“待人工核验”，不得由系统强行裁决。

## 当前版本范围

当前版本：v5.18.0 P0，作为独立一级模块接入现有左侧工作台。

首期只支持前辈提供的 `.xlsx` 统一模板及其同结构派生文件，不承诺兼容旧版二进制 `.xls`、任意结算格式、扫描件或缺少模板结构的自由表格。上传文件不覆盖，所有成果写入独立运行目录。

## 业务流程

```text
承包商结算表（统一模板）
→ 文件与模板结构校验
→ 读取承包商上报明细
→ 模板参数及算术审核
→ 前辈经验专项规则审核
→ 形成可自动建议项与待人工核验项
→ 写入造价审核栏及审核结果总表
→ 生成 Word 辅助审核报告
→ 专业人员复核、确认、签章
```

前辈描述的完整业务流程为“承包商报审 → 专业审核 → 造价中心审核 → 承包商确认 → 内审 → 最终结算”。本模块定位在“造价中心辅助审核”环节，不跳过任何人工确认节点。

## 输入资料

### P0 必需输入

- 按统一报价模板编制的 `.xlsx` 结算表；
- 表内承包商上报工程量、基价、系数、金额及其他费用凭证编号。

### 正式审定仍需人工核验的资料

- 结算书、计算底稿及合同、补充协议；
- 经确认的工作量、勘察测量成果和过程资料；
- 分包备案、协议、发票、收据、付款凭证；
- 签字、盖章、日期、数据一致性及异常数据说明。

缺少以上资料时，系统仍可完成结构化试算，但必须保留“待人工核验”，不得自动判断真实性或合规性。

## 规则矩阵

| 规则编号 | 审核事项 | P0 处理方式 | 风险等级 | 依据 |
| --- | --- | --- | --- | --- |
| JS-001 | 统一模板基价与系数偏离 | 与只读参考模板的同项参数对比，给出建议值并写入造价审核栏 | 高 | 统一报价模板 |
| JS-002 | 明细金额算术不一致 | 按 `工程量 × 实物系数 × 基价 × (1 + 技术系数)` 重算 | 高 | 统一报价模板计算结构 |
| JS-003 | 深度大于 300m 钻孔重复乘 1.2 | 识别深度区间及基价公式，提示取消额外 1.2 基价调整 | 高 | 前辈指导 |
| JS-004 | 室内试验技术费取值或重复收费 | 室内试验技术工作费按 1.2 提示；不得再重复计取报告编制费 0.1 | 高 | 前辈指导 |
| JS-005 | 航测、线路走向图重复计技术费 | 命中明确关键词时，技术工作费建议为 0 | 高 | 前辈指导 |
| JS-006 | 其他费用合计遗漏或算术错误 | 对承包商各费用列全量求和并写入审核合计 | 高 | 统一报价模板计算结构 |
| JS-007 | 其他费用缺少证据编号 | 保留金额、标记待人工核验，不自动审减为 0 | 高 | 前辈指导 |
| JS-008 | 2024 口径与框架下浮参数偏离 | 对汇总表参数与参考模板 `0.90 / 5% / 6%` 对比，提示核验合同 | 中 | 统一报价模板、前辈指导 |
| JS-009 | 工程量、成果、签章和付款真实性 | 生成全局人工核验清单，不做自动真实性判断 | 待人工核验 | 前辈指导 |

规则优先级为“明确专项规则 → 参考模板参数 → 算术校核 → 人工核验”。专项规则与模板公式冲突时，必须在报告中显式记录冲突及采用的建议口径，不能静默覆盖。

## 审核结果数据结构

每个结构化问题至少包含：

- `id`：本次任务内唯一编号；
- `severity`：`high / medium / low`；
- `category`：参数、算术、专项规则、证据或结构；
- `sheet`、`row`、`coordinate`；
- `title`、`current_value`、`suggested_value`；
- `basis`：规则编号与依据说明；
- `action`：建议处理动作；
- `auto_adjusted`：是否已写入造价审核建议栏。

任务汇总至少包含审核 sheet 数、审核明细行数、通过行数、结构化风险数、高风险数、待人工核验数、承包商明细口径合计、审核建议明细口径合计和建议审减额。金额汇总明确为“结构化明细试算口径”，不替代含税合同结算金额。

## Excel 写回规则

- 原始上传文件只读；成果文件命名为 `【审核后】原文件名.xlsx`。
- 保留原 sheet、合并单元格、公式、打印设置和样式。
- 测量费表写入 `W:AC` 造价审核栏；勘察费表写入 `Y:AE`；其他费用表写入 `O:Y`。
- 自动调整值使用浅黄色底，需人工确认项使用浅红色提示，通过项使用浅绿色；批注统一注明“造价智算辅助审核建议，需人工确认”。
- 新增第一张 `审核结果` sheet，汇总问题、依据和待核资料。
- 不写回原始输入，不改现有结构化计价库、匹配规则、经验池、最高投标限价任务或知识记忆。

## Word 报告结构

1. 封面标题与“待人工审定”提示；
2. 项目与文件信息；
3. 审核范围、依据和功能边界；
4. 汇总指标及结构化明细试算金额；
5. 发现问题清单；
6. 待人工核验资料清单；
7. 辅助审核结论与后续处置建议；
8. 专业复核、造价审核、承包商确认和最终审定状态签认栏。

报告不得编造合同条款、法规编号、签章状态或资料真实性。引用前辈经验时写为“项目结算审核经验”，不包装为正式法规。

## UI 与交互

- 左侧模块名称为“结算审核”，入口与现有一级模块同层。
- 页面严格采用“大尾巴 Shadcn UI v1.0.0”正式令牌：纯白平面工作台、1px 中性边框、主色蓝、轻量状态色、苹方字体、6px–8px 克制圆角；模块内禁止渐变背景、常驻阴影和多层嵌套卡片。
- 页面顶部使用与填价工作台一致的双标签切换：“审核工作台”承载上传、成果概览和人工核验清单，“审核发现”承载风险筛选、问题列表、规则依据和处置建议。两个标签页随中央工作区宽高自适应并尽量填满可用区域；四步流程仅在审核工作台展示；审核发现页不重复显示模块标题、场景说明和规则状态，但复用“辅助审核已完成”成果条及“新建审核 / 审核后 Excel / 审核报告”操作。
- 首屏包含模块定位、四步流程、模板下载/演示样例、拖拽上传区和明确的“开始辅助审核”主操作。
- 结果态在“审核工作台”展示指标带、金额边界和人工核验清单，在“审核发现”展示风险筛选、问题列表、证据与建议详情；Excel/Word 双下载在两个视图均可用。
- 所有“审核结论”统一表述为“审核建议”或“待人工核验”；不得出现“一键审定”“自动定案”。
- 1280×720 桌面视口优先，窄屏改为单列；焦点态、按钮禁用态和错误信息清晰可见。

## API 设计

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/settlement-audit/profile` | 返回模块版本、支持格式、规则摘要和边界 |
| `GET` | `/api/settlement-audit/sample` | 下载自编演示样例 |
| `POST` | `/api/settlement-audit/review` | 上传统一模板结算表并执行辅助审核 |
| `GET` | `/api/settlement-audit/download/{job_id}/{kind}` | 下载 `excel`、`report` 或 `result` 成果 |

接口单独使用结算审核运行目录和任务 ID，不复用 `/api/process`、既有 `job_id` 或主填价状态。

## 隔离与降级

- 结算审核引擎独立于 `FillEngine`，不修改三个数字匹配、经验池预警、工作量抓取、问问智算和协同任务逻辑。
- 前端工作台只在用户进入“结算审核”模块时挂载，不改变其他模块状态。
- 规则执行不依赖大模型、飞书或 WeAct；外部服务异常不阻断结算审核。
- 参考模板缺失或损坏时直接拒绝审核并说明原因，不使用不完整规则继续输出。
- 无法确定的工程量、合同参数和证据真实性全部降级为人工核验，不强制填入结论。

## 验收口径

- 自编演示样例能稳定识别：基价偏离、实物系数偏离、金额算术错误、深孔 1.2、室内试验 0.1、其他费用漏计、凭证缺失和汇总参数偏离。
- 正确样例行不产生结构化误报，并写入与承包商一致的造价审核建议值。
- 审核后 Excel 保留全部原 sheet 和样式，新增 `审核结果`，承包商上报栏不变，造价审核栏及批注可见。
- Word 报告可由 `python-docx` 重新打开，内容包含问题、依据、待核清单和“待人工审定”边界。
- 上传文件、原始统一模板和实际案例的 SHA-256 在测试前后保持不变。
- 模板错误、非 `.xlsx`、超限文件和路径越界下载均被拒绝。
- 现有后端全量测试和前端生产构建通过；本模块 PRD 硬检查通过，全局巡检中的既有外部资料缺口必须如实记录，不得伪造文件。
- 运行态在 1280×720 和窄屏完成上传、审核、筛选、问题详情与双成果下载；浏览器控制台无错误。

## 本阶段不做

- 不承诺自动完成完整结算审定，不替代合同、财务、内审和签章流程。
- 不支持扫描件 OCR、任意格式自动映射、跨专业结算和多人在线审批。
- 不让大模型生成工程量、基价、系数、审减额或最终结论。
- 不把前辈经验写入现有最高投标限价规则资产，不改变主价格匹配逻辑。
- 不自动修改正式知识库、统一模板、实际案例、经验池或历史任务成果。
