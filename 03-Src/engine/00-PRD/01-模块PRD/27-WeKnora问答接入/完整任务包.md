# 造价智算 × WeKnora：第一阶段问答接入任务包

版本：Q1-v1.0｜编制日期：2026-09-29｜状态：实施规划，尚未执行代码修改和本机联调。

## 本轮唯一目标
在不破坏造价智算原有知识问答、项目记忆和造价业务的前提下，将当前独立 WeKnora 的完整知识问答接入造价智算原聊天区，形成可手动选择、可追溯引用、可停止、可关闭的新通路。

本包是既有 WeKnora 计划的接入阶段补充，不另建平行产品：执行 D3、D4 和本阶段必需的 D6 回归子集；不启动 D5 完整资料管理，不开展 Wiki、实体图谱、自动回退或业务规则重构。新门禁统一用 QG0—QG4，不能把它们写成原 G0—G6 全部通过。

## 怎么交给 Codex
以造价智算项目为本轮主工作目录。将本文件夹整体放入该项目的模块 PRD 目录，建议为 `00-PRD/01-模块PRD/WeKnora问答接入/`；先检查是否已有同名模块，已有则合并本轮增量，不覆盖现有资产，不编造模块序号。WeKnora 仍保留独立目录。

让执行器读取 `05-目标模式启动提示词.md`。能够读取本次 ChatGPT 对话时，先读本轮需求和上一轮审查；无法读取时，本包可以独立执行，不把聊天链接的可访问性作为所有开发工作的前置条件。

执行器应在两个真实本地 Git 根目录核查事实。下面路径是历史定位线索，不是可直接相信的运行路径：
- 造价智算：`D:\Codex-Temp\260612-【ai大赛】-管勘智算-V2.0`
- 独立 WeKnora：`D:\Codex-Temp\260924-【WeKnora】WeKnora知识库`

本轮明确允许在范围内修改造价智算，并对 WeKnora 项目的非秘密接入配置、测试和交接文档做必要增量。旧文档“停在 D2、宿主只读”是上一轮阶段限制，由本轮用户的“先做问答接入”授权更新；其余保密、规则隔离和非破坏性要求继续有效。无需因旧阶段停止语句反复询问是否开工。

## 文件定位与事实层级
- 任务定义以 `tasks.json` 为结构化索引，验收定义以 `acceptance.json` 为结构化索引；Markdown 为同源的人类可读版本。
- 实际进度以宿主现有 `PROGRESS.md` 中新增的 Q1 区块为唯一状态入口；不要新建根目录 TASKS.md，不再维护一套相互矛盾的状态。
- 测试结果另外写入验收报告和 result JSON。模板中的 `not_run` 不是通过。
- `config.example.json` 是宿主适配层设计示例，不是 WeKnora 原生配置，不得直接发送给上游。
- 仓库代码证明“实现存在”；仓库历史报告证明“当时记录过实测”；本轮真实操作日志才证明“当前机器、本轮版本通过”。三者不得混写。
- 本包的 `tools/validate_bundle.py` 只校验任务包的结构、引用与一致性，不验证任何应用功能。

## 交付默认状态
产品默认仍是原有问答。新增增强开关默认关闭；本机验收期间可以显式开启，结束恢复进入测试前状态并记录。用户从设置打开增强后，仍需在原聊天区显式选择 WeKnora，不能替用户全局改默认引擎。软件缺少 WeKnora、模型或凭证时，原有功能照常启动。

# 第一阶段实施规划

## 1. 可观察的最终结果
用户仍在造价智算原来的聊天窗口提问。启用增强后，可选择“原有问答”或“WeKnora 增强”。新通路调用真实 WeKnora，会显示实际引擎、所选资料、处理状态和回答来源；可停止请求、打开引用。停掉或关闭 WeKnora 不会破坏原问答和造价主流程。

这里的“独立”是独立部署、数据与责任边界，不是要求用户必须离开智算网页；这里的“不破坏”是旧默认行为、旧接口和旧数据继续成立，不是禁止增加一个经过隔离的新入口。

## 2. 已核对的起点与不能继承的结论
截至本次仓库核对，造价智算主分支为 `d7eb069e0cd6931535391cba6da5348c39eb91a3`，独立 WeKnora 主分支为 `4e188e362cd8b780142a2bf33101216138311b9a`。本机执行前必须重取 HEAD、dirty 文件和运行版本，不得 reset 到这些提交。[S01][S02]

WeKnora 当前版本计划为 v0.2.11，D3/D4 尚未实施；Windows Docker Desktop/WSL2 是主用路线。13 份资料的 9,604 条有效块及向量是历史验收记录，不是本轮实际检查结果。新增八份资料不能仅凭“纯向量检索命中”就宣称完整生成问答已经验收。[S03]

造价智算旧 `/api/knowledge/ask` 有预置题提前返回和无证据通用模型兜底。旧选库包含 `project-core`、`cost-aiw`、`knowledge-memory`；其中 cost-aiw 本来就不用于行级勘察测量复核。[S06][S07]

## 3. 范围冻结
### 必须完成
- 原聊天区的引擎手动选择，设置中的增强启停开关与清楚的连接状态。
- 宿主后端薄适配：连接、认证、资料范围、会话映射、完整知识问答、事件转换、取消、引用代理。
- 首版只接普通问答的 `cost-aiw`，内容仅为已获准且实际完成解析的文档白名单。
- 增强会话内多轮追问；范围或引擎变化后隔离会话，不把旧历史自动外发。
- 严格无证据处理、明确故障提示、用户主动切回原模式。
- 冷启动、断服务、取消、权限、引用和旧业务无损回归；真实资料对照测试和本地交付。

### 明确不做
- 自动选引擎、技术故障自动回退、跨引擎混合生成、双引擎同时后台跑。
- 从智算上传/删除/重解析文档、全量同步、双写、重建向量；D5 完整资料管理后置。
- Wiki 展示接入、自动 Wiki、Neo4j、GraphRAG、文章图谱替换；已有 Wiki 保留不动。
- 用 WeKnora 改写价格、两个系数、规则执行、风险裁决、记忆审核；行级问答仍走原链路。
- 飞书、WeAct、Stopwatch/Gork 新接入；不启动机器人，不发消息。
- 云部署、端口公网开放、Tauri/绿色版重新构建、升级 WeKnora/模型/镜像、迁移 VMware、第三个网关进程。

## 4. 产品行为决策
### 4.1 两层控制，避免“默认关闭却不能用”
第一层是本机设置中的“启用 WeKnora 增强问答”，出厂默认关闭；只保存非秘密布尔值。第二层是原聊天区的“问答引擎”，首次仍为原有问答。

用户开启第一层后，可选择第二层的 WeKnora；未配置或不可达时明确显示原因，不装成可用。关闭第一层应终止本模块在途请求、禁用新增强请求，保留历史记录，随后新的普通提问按界面明示的原有模式处理；不自动重发刚才失败的问题。

优先复用现有设置 UI 和保存机制。项目默认值按现有规范放入 `config/project-default-settings.json` 的新命名空间，运行地址、凭证引用和实例信息放入受保护的本机运行配置。不能把密钥写入前端、默认配置或仓库。[S08]

### 4.2 两个引擎，两套选库偏好
原有模式保留原默认选择和经典/混合检索。增强模式首次显式显示“造价通用知识库”，暂不支持的项目正式库、知识记忆显示不可选及原因；不继承旧模式可能同时勾选的三类库，再偷偷只检索一个。

切回原有模式恢复原来的选库和检索偏好。`engine_mode` 与 `retrieval_mode` 是两个维度；增强不把 classic/hybrid 当成 WeKnora 算法开关。前端不把旧模型下拉选择直接覆盖 WeKnora 已获准的模型配置。

### 4.3 普通问答与业务问答分开
增强仅适用于 `context_type=general`、`row_context=null`、全部所选库均已映射的普通问答。行级复核、带业务候选的解释、记忆治理等继续原行为；对应页面不出现可误用的增强选择。

客户端错误发送业务上下文到新增增强接口时明确拒绝，不静默剥离 row_context 后再假装处理了这条业务问题。`project_key` 仅作宿主本地归属，不能充当身份，也不能把完整项目、Excel 行、记忆或历史会话自动拼给上游。

### 4.4 原有问答不是增强失败后的自动“接盘者”
旧 JSON 接口保持原请求和返回；原有预置题与原兜底逻辑不被本轮重构。新通路不能调用 `get_demo_answer`、`get_row_demo_answer` 或 `_run_general_model_fallback`。

增强故障显示“重试”或“切回原有问答”。重试必须是用户明确动作并使用新的 request_id；切回时保留原输入，不自动再次发送，显示旧方式可能使用不同资料/无依据通用回答的既有语义。

### 4.5 流式体验与证据约束
目标是 SSE 状态与回答展示，但不为逐字动画牺牲范围验证。默认采用完整上游响应缓冲、引用与状态校验后发送正文的 `buffered_verified` 模式；只有固定版本真实事件证明引用范围在正文前已确定且不会被后续事件扩大时，才允许 `live_validated`。

无法保证安全逐字流式，不阻断其余可用问答，但必须在能力和报告中标明。禁止把拿到的整段回答人为定时切字，假装是实时模型生成。无论哪种模式，都必须能停止和正确结束。

## 5. 实现架构
```text
原聊天 UI
  ├─ 原有问答 → 原 /api/knowledge/ask（JSON）→ 原完整链路
  └─ WeKnora → 新 /api/knowledge/ask-stream（SSE）
                    ↓ 宿主后端同一进程
             配置/授权/文档范围编译
             会话与请求注册/并发约束
             WeKnora HTTP 客户端/事件适配
             引用归一/受控原文代理
                    ↓
             独立 Windows WeKnora
```

第一版不要为了 provider 抽象把旧千行函数大搬家。旧函数保持原处，新路由注册一个边界清楚的 APIRouter 即可；需要共用的纯校验或 DTO 通过小模块抽出，避免从新模块反向导入 main.py 造成循环依赖。

## 6. 建议代码落点（新建建议，不是既有文件断言）
宿主可在 `backend/app/knowledge_gateway/` 下组织 `router.py`、`contracts.py`、`settings.py`、`scope.py`、`weknora_client.py`、`sessions.py`、`sse.py`、`citations.py`。结构可按现有风格合并，避免仅为凑文件机械拆分。后端已有 httpx 依赖，优先复用，不新增 Go/Node 网关或新的 Web 框架。[S10]

前端在现有 `components/knowledge/` 及 API 调用层增量扩展；建议将新 SSE 客户端和状态机拆出，App.tsx 只接入必要入口，不顺便重构主页面。模块测试放现有测试体系。

引擎设置、运行地址、凭证引用、库映射和审计分层；请求/会话/引用最小持久化优先复用宿主现有基础设施，或使用模块独立 SQLite 文件。严禁直连 WeKnora PostgreSQL/向量表。只保存完成所需的最小状态，不另建一套完整聊天产品。

## 7. 五个门禁
- QG0：两个仓库、本机运行、旧行为、真实认证/资料映射基线完成。
- QG1：新增后端通路及隔离、SSE、取消、引用、权限测试完成。
- QG2：原聊天区完整交互、偏好隔离、来源回看和历史兼容完成。
- QG3：真实资料对照、故障注入、旧业务和关闭回退验证完成。
- QG4：证据整理、文档回写、受限本地存档与交付状态恢复完成。

每个门禁先自测，失败修复后保留第一次失败记录再复测；无需在每个任务间问用户“是否继续”。真实凭证、资料授权或无法自动完成的人机验证缺失时，只阻塞相应 live 子任务，其余 mock/代码/回归继续；最终不得把 blocked 写成 pass。

## 8. 成功判据与停止点
80 项验收定义见矩阵；不是要求人工点 80 次，也不要求每个断言独立调用模型。同一自动化用例可证明多个断言，但每项须有可定位的证据。

硬门禁：旧默认路径和核心成果无新增回归；增强不走预置答案/通用兜底；范围与身份无越界；错误状态、取消和关闭成立；引用可以在真实浏览器打开。质量门禁：完成有原文期望的真实问题集，区分接口成功与答案正确。不能以 200、几个关键词或截图存在代替语义验收。

达到 QG4 后停止，不自动进入 Wiki/图谱、D5、云发布或默认引擎切换。最终只对实际完成的 Q1 范围下结论。

# Q1 接口与安全契约

本文是本轮宿主侧设计。固定上游的字段、认证和事件以当前锁定源码与实际响应校准；不是把下列 DTO 原样转发 WeKnora。任何修改需更新契约与测试，不能静默兼容为扩大范围。[S04][S05]

## 1. 新旧 API 隔离
保留 `POST /api/knowledge/ask`、`POST /api/knowledge/search`、原库列表及其他既有调用者契约。旧端点不改 content-type，不顺带增加强制的新字段，不改变没有 engine_mode 的请求。

本轮新增候选接口，实施前检查路由冲突：
| 接口 | 用途 | 约束 |
|---|---|---|
| `GET /api/knowledge/capabilities` | 配置/模块启用/连接/映射/流式能力 | 非秘密；关闭时不访问上游，不触发生成或入库 |
| `POST /api/knowledge/ask-stream` | 增强完整问答 | 本轮只接受 `engine_mode=enhanced`，显式资料范围 |
| `POST /api/knowledge/requests/{request_id}/cancel` | 宿主级取消 | 校验请求所有者；幂等；不是重新生成 |
| `GET /api/knowledge/citations/{citation_id}` | 引用元数据和安全节选 | opaque ID；每次检查归属和来源有效性 |
| `GET /api/knowledge/citations/{citation_id}/preview` | 来源预览 | 受控文档句柄，不接受任意 URL 或路径 |

设置写入优先复用宿主原接口，不能复用时才增量增加受保护的本机设置端点；只允许修改本模块非秘密开关，不能从浏览器提交任意 base_url、凭证或知识库 ID。另设主动“检查连接”动作时，需区分只读连接检查和用户触发的生成自测，默认不消耗生成调用。

## 2. 宿主输入
```json
{
  "question": "请解释这类项目的清单包含内容，并给出来源。",
  "engine_mode": "enhanced",
  "library_ids": ["cost-aiw"],
  "document_ids": null,
  "conversation_id": null,
  "request_id": "new-client-uuid",
  "context_type": "general",
  "row_context": null
}
```

`document_ids` 是宿主逻辑文档句柄，可选；null 表示已映射逻辑库内全部有效白名单资料，不表示上游租户全库。空数组拒绝。首版 UI 不必做复杂文件过滤，但后端范围编译和限定文件测试必须成立。

增强新端点未传/空 library_ids、未知 ID、部分库不支持、非法上下文、超长问题均拒绝。不会影响旧端点原来的默认解析规则。`auto` 本轮返回 `ENGINE_NOT_SUPPORTED`；legacy 由前端调用旧 JSON 入口。客户端无法关闭 strict_evidence；传入 false 或模型地址等禁止字段应报契约错误。

问题最大字符数建议 4,000，且有服务端字节上限；这是起步工程配置，不是上游限制。conversation_id 首轮允许 null：宿主在当前合法主体下创建逻辑会话，并在 meta 与 done 返回服务端会话句柄；后续追问提交该句柄并验证归属。已有宿主会话机制可复用，不能要求客户端先取得一个没有创建入口的句柄。request_id 仅用于幂等，绝不视为身份。

## 3. 上游认证与连接
历史 D2 样例验证的检索使用 X-API-Key，完整问答使用 Bearer；不要假定同一密钥自动适用所有端点。先以合成/已获准最小样例逐一验证会话创建、问答、stop、元数据与预览的认证方式、权限范围、到期和撤销行为。[S05]

优先使用官方支持的最小权限服务凭证；固定版本不能以同类凭证完成全套操作时，使用已授权的受保护登录会话或官方支持的凭证组合，记录能力差异。不通过 SQL 插入管理员 key，不使用全库管理员权限绕过集成设计。

凭证仅来自受保护环境/本机秘密配置，不打印、不进入配置接口、不进入浏览器/localStorage、Git、错误页或测试截图。使用实际 auth_type 分派，不能让调用者在请求中自选任意 header。认证失效只返回明确错误，不静默换账号或引擎。

主用实例记录为 Windows API `127.0.0.1:18091`、管理网页 `127.0.0.1:18090`；旧示例 18081/18080 是 VMware 路线。按本机基线核实后使用，不自动探测所有端口或从当前网络找一个“可用的 WeKnora”。[S03][S09]

## 4. 资料范围编译和版本
宿主逻辑 cost-aiw → 本机实例身份 → 明确上游 KB → 获准文档白名单。运行映射至少保存 host_document_id、upstream_document_id、kb_id、source_sha256、来源版本、解析状态和来源授权引用。

用现有获准导入清单及历史验收文件校验，不能只比文件名。冷基线可本机只读核对文件摘要；每轮请求复核权限和已缓存映射有效性，不必反复下载全部文件。检测到删除、解析失败、版本变化或映射漂移时失效缓存并阻止增强，不能扩大检索范围凑答案。版本不明确不能从文件年份自行断言效力。

`scope_revision` 是排序后的文档身份、内容版本/摘要、授权策略版本等形成的稳定摘要。会话还需绑定 principal 和实例身份。切换范围、策略或实例时必须换上游会话。

精确文档范围上游仅传非空 `knowledge_ids`，宽 `knowledge_base_ids` 留空；历史样例指出两者同时传会合并范围。标签只是分类，不等同于授权；前端选一个标签时，也须编译成明确文件白名单，不能只改显示文案。[S05]

## 5. 上游完整问答
已知上游路线包括创建会话 `POST /api/v1/sessions`、完整问答 `POST /api/v1/knowledge-chat/{session_id}`、停止 `POST /api/v1/sessions/{session_id}/stop`。[S04][S05]

沿用经本机复核的 `agent_enabled=false`、`web_search_enabled=false`、`disable_title=true` 和已获准模型，不开启联网/Agent/工具/文件生成。普通知识问答必须实际走完整 WeKnora 问答，不退化为取片段后继续调用旧生成器。

不更改全库 Wiki/图谱设置；新通路不调用 Wiki/图谱/入库接口。核对所用上游问答路线不会自动带入其他库、旧租户会话或业务上下文。原文、旧项目记忆和完整业务行不得额外发送到未经批准的模型端点。

## 6. 会话、身份与状态
本轮可限定本机单用户、单 worker 的受控试点，不能由此宣称企业多租户权限已完成。优先复用宿主现有身份。没有成熟登录体系时，新增端点限制本机来源和可信 Origin/Host，使用服务端生成的浏览器会话凭证绑定请求；不相信客户端自报 user_id/project_key，不将代理的客户端 IP 当成认证。

若宿主当前可从网络访问，新增增强端点必须另加可靠鉴权/网络限制；不能为限制增强而擅自改变旧系统监听与部署。无法建立边界则增强保持关闭，旧系统照常运行。带 Cookie 的状态写入按现有策略做 CSRF 防护，来源代理禁止跨站凭证滥用。

会话键至少包括：principal、宿主 conversation_id、engine、instance_id、scope_revision、policy_revision。只复用同引擎同范围且状态明确的 WeKnora 会话；旧引擎历史、失败半答、项目记忆不自动灌入。界面切引擎可保留可见旧聊天，但提示新的知识上下文已建立。

同一会话同一时刻只允许一个在途生成。全局增强并发初始 1，忙时立即返回 MODULE_BUSY，不建立无限队列、不占用旧业务资源等待。多 worker 使用共享注册机制；没有实现时在增强配置检查中明确拒绝多 worker 模式，而不默默出现多份独立锁。

请求状态：created → validated → upstream_open → receiving → completed；任何非终态可转 failed/cancelled/interrupted。终态不可逆，采用原子终态提交。取消后迟到正文不得写聊天记录或变为成功。

相同 request_id + 相同内容再次请求：返回重复/当前状态，不创建第二次生成；相同 request_id + 不同内容返回冲突。存储最小请求指纹并绑定 principal，避免跨浏览器误命中。生成 POST、创建会话 POST 不自动重放；超时但上游是否执行不明时明确标记 outcome_unknown。

## 7. SSE 宿主协议
统一事件：`meta`、`status`、`sources`、`delta`、`done`、`error`、`cancelled`。meta 包含宿主 conversation_id、实际引擎、范围版本及 stream_mode；每个事件均含 request_id 和递增 seq；恰好一个宿主终态事件（done/error/cancelled）。`status` 只表示已知阶段，不编造完成百分比。

历史上游事件名为 reference/content/complete；字段结构必须用本轮脱敏真实样本冻结。解析需支持 UTF-8 跨字节、CRLF/LF、多行 data、心跳、多个事件同块、事件跨块、终止缺失；未知非终止事件可记录类型后忽略，不把 thinking/reasoning 当答案展示。[S05]

默认 `buffered_verified`：接收上游事件并保留在内存的大小受限缓冲；完成后验证引用范围、来源有效性和无证据状态，通过才发送 sources、正文 delta 和 done。不能把“先收到一个 reference”当作整个后续流永不出现其他来源的证明。

可选 `live_validated` 仅在固定上游具备经过测试的前置范围保证时开启；须另外测试后置引用、错误来源、取消和终止。安全条件无法证明时保持默认，不为达成逐字流式伪造能力。

若上游断流未 complete，不能把累积正文写成完整成功。live 模式已显示内容标 incomplete=true 并保留“回答中断”；buffered 模式未展示的正文不泄漏。未知严重 schema、范围错误直接终止，不能降为旧方式。

取消 API 应先设置本地终态、停止转发，再尽力调用 stop 并关闭连接。用户取消或标签页关闭要清理；上游 session 尚未返回时取消，注册取消标记，ID 到达后立即补 stop。停止失败标 upstream_stop_confirmed=false，不声称云端计费一定终止。

## 8. 结果与“有来源不等于正确”
新结果至少包含：request_id、engine_requested、engine_used、selected_library_ids、scope_revision、answer、citations、retrieved_candidates、evidence_status、citation_scope_validated、stream_mode、timings、incomplete、error_code。

本轮新通路 engine_used 只能为 weknora；旧历史记录不强行迁移，不把 curated_demo 冒充它。

`evidence_status` 定义：
- `cited`：存在经过范围/身份校验的可追溯参考来源；不表示每个事实已被程序证明正确。
- `insufficient`：固定无依据拒答，或没有任何有效来源；无来源的实质生成正文不得交付。
- `conflict`：确有可识别的冲突依据且不能确定适用版本，要求澄清；不能仅见两个年份就伪报冲突。
- `unverified`：来源或最终状态无法可靠判定；显示限制或终止，不能标“已核实”。

这一新枚举是对旧设计里 supported 的谨慎细化，只影响新增协议，不改旧接口 evidence_status。`citation_scope_validated=true` 只证明范围校验通过；分数、引用数量和命中数量都不等于事实置信度。

上游固定拒答但 reference 事件仍有命中时，保留为 retrieved_candidates；不能把候选来源冒充支撑答案的 citations。无可靠句段级映射时，来源卡片称“检索参考资料”，不能编造逐句引用绑定。

不强制每个金额问法都拒答：有直接依据时列明规格、单位、版本、包含/不含和适用限制；缺规格给有据选项并追问，不能编出统一报价。未获得原文证据时不得虚构页码、Excel 行号、文件效力、价格或系数。

## 9. 引用代理与持久性
引用结构建议：citation_id、host_document_id、upstream_document_id、chunk_id（未知 null）、title、source_version（未知 null）、locator_kind、locator_value、excerpt、preview_path、scope_revision。

locator 必须来自真实元数据。来源的“Excel 第 5744 行”不能自动改成 Markdown 行号或 PDF 页码；未知定位允许显示文件/章节，但必须诚实标注精确位置未知。

citation_id 为宿主生成的不透明句柄，绑定 principal、请求、实例、文件版本和允许范围；每次点击重检权限和文档有效性。只拼装固定上游路径，禁任意 url 参数、重定向越界、目录穿越和把绝对磁盘路径传前端。

引用卡片和新消息最小元数据随原聊天存储兼容持久化；服务重启或浏览器刷新后应可再打开原来源。过期/删除/失效时明确提示，不换到“同名最新版”冒充旧证据。原 WeKnora 数据库与上传文档不因此改写。

预览复用现有组件或采用最小只读抽屉，渲染 Markdown/HTML 时消毒、不加载任意外链资源、限制响应大小；正文和引用都视为不可信文本，不能成为工具指令。来源无法证明时不得给出看似可用的伪引用链接。

## 10. 超时、重试、缓存与日志
起步目标（须实测而非宣传）：connect=3 秒、read_idle=30 秒、total=90 秒；total 用单调时钟覆盖验证、创建会话、等待和接收，不能每步重置。停止上游的独立清理预算建议 5 秒。只读 GET 最多一次有限重试，创建/生成 0 次自动重放，自动回退 0 次。

缓冲正文设置字节与事件数上限；超限终止，不无限消耗内存。后台 capabilities 不发生成请求；关闭时不做上游轮询。只缓存非秘密健康/映射元数据，正文缓存不是本轮目标。

日志仅记录 request_id、脱敏主体、库范围摘要、实际引擎、事件类型/数量、状态码、耗时、版本与 stop 状态。不记录完整问题、答案、文档片段、认证头或模型 prompt。真实内容测试证据只在获准本机受保护目录，提交 Git 的报告只留脱敏断言、计数和定位说明。

初始真实生成验证预算最多 100 次（直连、宿主、旧模式、合成与失败样本合计），达到上限保留结果并阻塞额外 live 调用；不得靠无限跑模型“刷过”测试。本预算是本轮建议上限，不是费用报价。

## 11. 错误语义
新端点进入 SSE 之前使用清楚的 JSON 错误及适当 HTTP 状态；进入 SSE 之后发 error 并终止，不再企图更改 HTTP 头。

稳定错误建议包括 MODULE_DISABLED、CONFIG_INCOMPLETE、ENGINE_NOT_SUPPORTED、INVALID_SCOPE、SCOPE_NOT_MAPPED、SCOPE_DRIFTED、UNSUPPORTED_CONTEXT、PERMISSION_DENIED、AUTH_EXPIRED、SERVICE_UNAVAILABLE、UPSTREAM_TIMEOUT、RATE_LIMITED、MODULE_BUSY、CONTRACT_MISMATCH、DUPLICATE_REQUEST、REQUEST_CONFLICT、STREAM_INTERRUPTED、CITATION_EXPIRED、CANCELLED。NO_EVIDENCE 属可解释的问答结果，原则上用 done+insufficient 而不是服务 500。

401/403、schema 错误、无依据、范围问题、用户取消、已输出半答均不会触发任何自动换引擎。旧接口错误语义不受本轮新错误表影响。

## 阶段依赖与验收的区别
任务的 acceptance_ids 表示该组件负责支撑哪些最终断言，不表示单个后端任务必须提前完成尚未开发的前端验收。前置组件实现且局部测试通过后可记 implemented_pending_e2e，并继续下游任务；真实浏览器/题集验收按 acceptance.json 的 verification_gate 补齐。只有证据齐全才记 verified，QG4 才可给出整阶段结论。

核验应用响应只是第一层；再核对认证、映射库、白名单资料解析完成与来源标识，最后做预算内的合成/获准问答测试。合成测试放隔离测试库，不上传到主库。生成和 stop 可建临时会话；只清理本轮拥有的会话/测试库，保留用户原会话。

主库已存在 Wiki；本轮不增加文件、不触发重解析、不修改库级索引配置。这样无需为问答联调冒险关闭/重建现有 Wiki。备份是风险前提，不是进行本不必要的数据修改的理由。

实际认证按端点矩阵验证；没有合法凭证时完成 mock 测试和 UI，不把管理员口令写进脚本、也不绕过认证。

## 4. 真实题集：比较能力，而不是比较 HTTP 200
在本地生成 `live-qa-cases.local.json`：至少 30 题，其中 26 题有可定位依据，覆盖已获准 13 份资料每份至少 2 题，另外 4 题明确无依据。题型包含单位/规格、费用包含与排除、宽泛问价后澄清、清单短句反查、条款解释；不能编造资料本来没有的内容来凑数量。

题集排除现有预置题；每题记录允许文档、期望来源与真实 locator、必答点、禁止结论和是否应追问。源文在本机只读核验，语义金标准不能由待测同一回答反向生成。执行器无法可靠建立金标准的题保留 awaiting_review，不假造“人工确认”。

同题先直接调用固定 WeKnora，再由智算增强通路调用；同模型配置、同文档范围、同全新或同等历史会话条件，统计语义一致性和引用正确性，不要求随机生成文本逐字一致。旧模式只对实际同时拥有的资料做公平对照；不覆盖的题标 not_comparable，不能算旧模式错误，也不能把旧泛模型回答当有据基准。

质量目标：26 道有据题至少 24 道完整满足金标准，4 道无据题全部明确无依据。任何已经回答出来的关键价格/系数/单位不得错误；发现实质错误为关键缺陷，即使平均分达标也不能带病通过。真实不存在的版本冲突等边界用隔离合成夹具验证，不能捏造真实文件效力。

记录首次失败与复测；没通过就定位是上游检索/生成质量，还是宿主改错范围/会话/截断/引用，不混成“模型偶发”。必要修复限于本轮适配与得到证据支持的受控配置，不升级整个系统。

## 5. 性能与资源
报告真实样本数和同组的首次可见状态、首次正文、完整回答 P50/P95、失败数；区分冷启动/热启动、buffered/live、直连/宿主。不要把 VMware 的历史秒数迁移成 Windows 保证。

默认每次总预算 90 秒、全局增强并发 1；测试第二个请求时及时返回忙，不让任务无限排队。宿主额外开销用成对测量说明，不使用随机模型单次耗时差冒充适配耗时。CPU/内存记录来源及采样方法，不给未经测量的“零影响”结论。

## 6. 失败注入
优先通过测试客户端/代理夹具模拟连接拒绝、401/403、429、5xx、慢响应、非法 schema、SSE 中途断开和 late delta；不为测错密钥撤销用户原凭证，不破坏生产防火墙或模型配置。

真实停服务测试至少一次：确认 WeKnora 无在途任务，使用当前受控停止方式暂时停止主用应用；增强提示不可用，原有问答和主业务仍可用；恢复后新会话增强可用，资料/Wiki 保持。仅记录动作实际完成的范围，不主动维护 VMware。

真实取消测试同时观察前端终态、宿主任务注册与上游 stop。无法确认上游停止时必须显示并记录“本地已停止，上游停止未确认”，不能声称计费已停止。

## 7. 业务无损回归
运行旧后端/前端测试、前端构建和仓库要求的有效门禁；比较正式样例的 Excel/Word 业务语义，而非仅压缩文件字节 hash。用冻结的非确定性生成输出或比较稳定字段，排除时间戳和生成措辞噪声。

重点覆盖：填价/最高投标限价、两个系数、结算审核、风险报告、人工复核、知识记忆审核、导出、旧文章图谱、机器人调用路径的本地 mock。不能为验收去向飞书/WeAct 发送真实消息。

若仓库已有自动截图/浏览器工具，核对宽屏、窄屏、深浅色与旧聊天的布局。新增增强控件只占其必要位置；不顺带重做 App.tsx、全局 CSS、地图或其他页面。

## 8. 回退
功能回退：设置中关闭增强；停止新增强请求并清理在途状态；UI 回到明示原有问答，但不自动重发任何请求。关闭之后不轮询 WeKnora，也不触发其模型调用。

报告准确列出：宿主实际运行版本、WeKnora 实例、默认开关状态、当前服务是否运行、是否需要启动器启动、配置/日志/证据本机位置、当前已知阻塞。完成本机测试不等于云部署完成；本轮禁止自动 push 和发布。

按仓库已有规则更新 CHANGELOG、当前版本计划和模块 PRD；必要脚本从当前 AGENTS 读取，不凭历史路径猜命令。仅暂存本轮文件/片段并本地提交，不能把未跟踪秘密或无关改动一起提交。

# 证据与执行治理

## 1. 唯一状态入口
把本包任务 ID 注册到宿主现有 PROGRESS.md 的 Q1 区块：任务状态、依赖、证据路径、最后结果、下一动作。WeKnora 项目的 PROGRESS 只写供给侧摘要与宿主交接引用，不复制一套独立且冲突的进度表。

`tasks.json`/`acceptance.json` 是任务与验收定义，执行状态进入本机 result 和报告，不把模板的 not_run 批量改 pass。

## 2. 每项证据最小字段
- 对应任务/验收 ID，执行时间及明确时区。
- 两侧 Git HEAD、dirty 摘要、运行 build、实例身份、脱敏配置版本。
- 实际命令或操作、退出码、预期与实际、pass/fail/blocked/not_run。
- 测试种类：unit/mock/live/browser/manual。live 和 manual 不能互相替代。
- 证据路径、首次失败、修复差异、复测次数、剩余限制。

证据文件原文放本机受保护且 Git 忽略的模块目录；提交版只留脱敏摘要。不要将密钥、完整真实资料、完整问答正文或模型 prompt 编入 Markdown、Git 或共享任务报告。

## 3. 三种结论不能混用
`代码实现完成`：相关功能代码和 mock 测试存在。
`本机联调通过`：当前宿主、当前 Windows WeKnora 的真实链路验证通过。
`Q1 验收通过`：本轮硬门禁、质量与回归门禁都通过，引用浏览器交互和回退证据齐备。

缺凭证、资料或真实浏览器时，可以交付已完成代码，但必须写“本机联调/最终验收未完成”，不能拿静态检查等同成功。

## 4. 决策记录模板
ADR-Q1-编号：问题；当前代码/实测证据；可选方案；选择及理由；涉及文件；对旧行为影响；测试覆盖；回退方式。

允许自行决策：模块内部命名、最小文件划分、复用现有组件、真实接口字段校准、确有证据的超时预算调整。

不得自行扩张：新增模型提供商、扩大真实资料出站范围、升级上游、大规模源码重构、图谱/Wiki、云上线、默认切增强、生产数据写入或任意多轮生成花费。

## 5. 上下文不足时续跑
先更新 PROGRESS、BLOCKED、DECISIONS 与任务证据，不要求用户重复已确认需求。写出当前分支和 dirty、已完成任务、下一未阻塞任务、必读文件、已知限制。续跑先读取这些文件再继续，不从头重新安装或重做 D0—D2。

## 6. 独立复核
最后至少做一次与主实现分离的复核：可用只读审查子任务或独立审查轮，聚焦旧路径变化、秘密泄漏、范围漂移、认证、SSE 终态与取消竞态。避免多个执行器并行修改 main.py/App.tsx；一次只有一个合入负责人。复核发现必须有修复或明确阻塞，不用“整体没问题”代替检查记录。
