# Task 任务对象与执行轨迹 P0 实施进度

> 更新时间：2026-08-13
> 当前状态：P0 已完成并通过验收

## 开始前关系核对

1. `TaskEnvelope` 是外部协同入站契约，以 `source_system + source_task_id + event_type` 形成业务幂等键；协同任务继续使用 `FS-*` 编号并保存人员、投递、复核轮次和审核状态。
2. 网页专业处理以 `job_id` 作为一次运行目录和 `process-state.json` 的身份；项目台账把同一 `job_id` 幂等登记为 `run_id`，继续负责 Project、Run 和 Artifact，不把 Run 冒充业务 Task。
3. 可信经验继续在 `knowledge-memory.sqlite3` 中保存事件、候选、审计和项目胶囊；P0 只把其真实 `task_id / project_id / artifact_version / candidate_id` 作为血缘聚合来源。
4. 新增最小兼容层采用独立 `BusinessTask + TaskLink + TaskEvent`：稳定业务 Task 保存不可漂移的定义与 Skill 快照，TaskLink 关联 `job_id / run_id / collaboration_task_id / source_task_id`，TaskEvent 只记录真实后端事实。删除新增运行库和接线即可回滚，不迁移、不删除、不批量改名既有数据。

## 已完成改动面

- 后端：已新增独立 `business-tasks.sqlite3` 的 `BusinessTask + TaskLink + TaskEvent`，建立 `task_id ↔ job_id ↔ run_id ↔ collaboration_task_id ↔ source_task_id` 显式映射；新增 Task 详情、时间线和项目 Task 列表只读接口，聚合异常降级而不阻断专业主流程。
- 前端：已新增 `CurrentTaskBar`、`TaskDetailDrawer`、`TaskTimeline`、状态 / 动作工具与局部 CSS；智算助手、专业工作区、结果预览、Word 报告、项目详情和右侧 Dock 复用同一 Task 上下文，不新增一级菜单。
- 事件与血缘：任务定义、Skill、输入、结构、规则、风险、人工复核、成果、协同和 Experience 只由真实后端事实驱动；未运行、不适用和未形成候选如实占位。成果内容哈希变化才增加 Task 成果版本，项目恢复不再回退完成状态。
- 安全：聚合视图不回显服务器绝对路径、平台用户 / 群 ID、文件 Key、秘密或任意前端路径；缺少可靠关系的旧记录不按名称猜测合并。

## 风险与保护措施

- Task 聚合失败必须返回明确降级状态，不得阻断 Excel、预警、报告、问答、协同或经验治理。
- 不修改三个数字规则、正式二维知识库、经验池母版、报告模板、V3.1 输入和标准答案。
- 旧记录只有可靠编号关系才关联；缺少关系时保留“待归类”，不按项目名或文件名猜测合并。
- 当前工作区的未跟踪测试资料、截图、VI 和输出目录均不纳入本任务提交。
