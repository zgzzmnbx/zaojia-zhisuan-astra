## 四、总体业务边界

统一产品表达：

一项 Task，调用一套专业 Skill，组合一组可信 Tool，经过人工复核形成正式成果，再沉淀为可治理的 Experience。

必须守住：

1. Task 是贯穿现有系统的业务对象，不新增左侧“Task 中心”一级菜单。
2. Project、Task、Run、ReviewRound、ArtifactVersion、ExperienceLineage 必须分开。
3. Task 表示一个稳定业务目标；重试、重算、报告刷新、下载和页面切换不得新建 Task。
4. 更换 Skill、可靠上游 source_task_id 变化或用户明确开始新的独立业务目标时，才新建 Task。
5. 现有专业模块仍是业务真相：匹配模块负责数字，协同模块负责审核，知识治理模块负责候选状态；Task 聚合层不得建立第二份可编辑状态。
6. 大模型只可辅助理解目标和组织文字，不得生成价格、系数、风险等级、完成状态、审核结论或虚构执行事件。
7. 不修改结构化计价库、三个数字规则、经验池母版、正式知识资料、报告模板、V3.1 输入和答案文件。
8. 不发送真实飞书 / WeAct 消息，不重试真实协同任务，不部署云端，不 push；除非用户另行明确授权。

## 五、P0 必须完成的后端范围

### 1. 稳定业务 Task 身份

- 兼容现有 job_id、run_id、协同 task_id、source_task_id 和 TaskEnvelope 业务幂等键。
- 不做破坏性数据库迁移，不删除或批量改名历史字段。
- 旧任务没有可靠关系时标记“待归类”，不得按同名项目或文件名自动合并。
- 重复创建、事件重放、接口重试和历史回填必须幂等。

### 2. 不可漂移的任务定义快照

至少包含：

- task_id、项目与来源。
- 任务名称、目标和必要说明。
- 输入文件安全引用、类型、版本和哈希。
- skill_id、中文名称、版本、Manifest 哈希和运行时摘要。
- 预期成果、成功标准和人工闸门。
- 协同任务需要的编制人、复核人和截止时间。
- 创建、更新、完成时间和当前 Run、成果版本、复核轮次。

### 3. 真实 TaskEvent 轨迹

按任务实际经过的阶段表达：

任务已定义
→ Skill 已冻结
→ 输入已接收
→ 结构已识别
→ 规则已执行
→ 风险已检查
→ 人工已复核
→ 成果已生成
→ 协同已完成
→ Experience 已治理

要求：

- 事件必须来自真实后端事实，保存时间、来源模块、状态和安全引用。
- 未调用显示“不适用”，未开始显示“未运行”，失败显示脱敏原因和可用动作。
- Experience 没有形成候选时显示“未形成候选”，但不阻止业务 Task 完成。
- Task 聚合层异常时降级为“任务轨迹暂不可用”，不得拖垮 Excel、预警、报告、问答或协同主流程。

### 4. 统一只读聚合接口

至少实现等价能力：

GET /api/tasks/{task_id}
GET /api/tasks/{task_id}/timeline
GET /api/projects/{project_id}/tasks

如需创建和旧任务对账接口，必须校验输入、幂等并审计。接口不得返回本机绝对路径、App Secret、访问令牌、群 ID、用户 ID、文件 Key 或连接票据。

### 5. 数据架构必须最小、可回滚

- 优先采用“统一身份登记 + 旧编号关联 + 真实事件聚合”。
- 项目台账继续负责 Project、Run 和 Artifact。
- 专业处理任务继续负责计算状态。
- 智能协同继续负责人员、投递、轮次和审核状态。
- 可信经验继续负责候选、确认、提升、命中、撤销和失效。
- 不要为了概念统一一次性搬迁所有运行库。

## 六、P0 必须完成的前端范围

### 1. 当前任务条

- 在智算助手和主要专业工作区复用同一组件。
- 显示业务 Task 编号、任务名称、来源、已锁定 Skill、规范状态、当前阶段、复核轮次和成果版本。
- 提供真实可用的“查看任务”“返回当前阶段”“查看成果”等动作；没有目标时不显示假按钮。
- 结果预览与 Word 报告只显示紧凑 Task / 版本摘要，不挤压主表格和 DOCX。
- 右侧 Dock 只显示任务名称、状态和详情入口。
- 无任务时明确显示“尚未发起任务”，不生成假编号、假进度或空 KPI。

### 2. 任务详情与执行轨迹

- 使用详情抽屉或项目现有详情区域，不创建新一级页面。
- 展示任务身份与目标、责任信息、Skill 快照、真实轨迹、实际 Tool、人工复核、成果版本和 Experience 血缘。
- 节点进入现有结果预览、Word 报告、智能协同或知识治理页面，不复制逐行改值、通过 / 退回和知识确认逻辑。
- 页面切换和抽屉开合不丢当前 Task、Run、Skill、成果和复核轮次。

### 3. 跨模块接力

- 项目详情按业务 Task 展示，不把每个 Run 冒充新 Task。
- 同一 Task 在智算助手、填价工作台、结果预览、Word 报告、智能协同、项目详情和知识来源中显示同一身份。
- 从任一页面进入详情后返回，不重复创建任务。

### 4. 组件边界

不要把全部 UI 继续堆进 App.tsx。根据现有结构合理拆分 CurrentTaskBar、TaskDetailDrawer、TaskTimeline、utils 和局部 CSS。App.tsx 只保留必要状态桥接和模块路由，不复制任务业务逻辑。

## 七、UI 是硬门禁，文字不得乱

用户明确要求：新功能必须遵循现有 UI 规范，尤其不能出现同层文字忽大忽小、字体不一致、按钮和标签各用一套字号。

### 1. 唯一设计来源

00-PRD/03-整体UI设计PRD.md
00-PRD/03-UI设计规范.md

不新建第二套主题，不引入 Tailwind / shadcn 初始化，不全局覆盖现有组件。

### 2. 唯一字体与字号

- 页面标题：28px。
- 模块标题：20px。
- 面板标题：16px。
- 正文：14px。
- 表格、控件、导航、按钮：13px。
- 辅助说明：12px。
- 可见业务文字不得小于 12px。
- 禁止新增 9px / 10px 可见文字。
- 11px 只允许有明确注释的图表坐标、步骤圆点或纯数字技术标记，本模块默认不要用。

### 3. 字体实现

- 使用项目自托管苹方和现有字体变量。
- 输入框、按钮、状态标签、任务名称、人员、时间和轨迹节点继承同一字体。
- 同一视觉层级必须 font-size、font-weight、line-height 一致。
- 不允许第三方组件或父级级联造成同组文字大小不一。

### 4. 视觉语言

- 纯白主工作区、1px 浅边框、6px—8px 低圆角、无常驻阴影、无渐变。
- 禁止灰底大卡套白卡、卡片套卡片和营销 Hero。
- 层级靠字号、字重、留白、分割线和状态色表达。
- 主操作使用现有深蓝语义色；图标使用 lucide-react，不用 Emoji。
- 状态统一：处理中蓝、待人工橙、成功绿、失败红、未运行 / 不适用中性灰；颜色不是唯一信息。

### 5. 当前任务条

- 宽屏最多两行，整体建议控制在 48px—72px，以现有工具条密度为准。
- 主信息突出任务名称、编号和状态；来源、Skill、阶段、轮次和版本属于辅助层。
- 窄 Dock 折叠为“任务名称 + 状态 + 详情”。
- 不得显著压缩 Excel 表格、聊天区或 DOCX 预览。

### 6. 响应式与无障碍

- 按容器宽度响应，不为单一屏幕写死。
- 1366、1440、1920，以及右侧 Dock 展开后的窄中间区都必须可用。
- 支持键盘焦点、aria-label、Esc 关闭抽屉和 prefers-reduced-motion。
- 禁止横向溢出、文本覆盖、状态徽标挤成乱码。

### 7. UI 验证

- 静态搜索本任务 CSS / TSX 中全部 font-size、font-family、font-weight、line-height，清除游离值。
- 运行 python tools/check_ui_design_system.py。
- 在浏览器核对标题、正文、标签、按钮、输入框、人员、时间和轨迹节点的 computed font-family、font-size、font-weight、line-height。
- 同一层级任意不一致，先修复再验收。
- 保存普通宽度、宽屏、Dock 展开、空任务、运行中、失败 / 待人工、详情抽屉和深浅色截图到 Codex-Temp，并逐张人工查看。
- 控制台不得有本任务新增错误、未处理 Promise、零尺寸图表或明显无障碍警告。
