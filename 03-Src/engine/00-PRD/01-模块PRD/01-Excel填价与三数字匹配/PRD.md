# Excel 填价与三数字匹配 PRD

## 已批准的后续增强边界（2026-09-05）

本模块下述已实现行为继续作为 v5.23.8 基线。目标 v5.24.0 的新 AI 模式、复杂表格理解、三字段候选辨析及人工确认需求统一进入 `00-PRD/01-模块PRD/24-AI增强匹配与离线双模式/PRD.md`。现有“模型只解释/不改变主匹配”等描述继续保护机械模式与旧辅助入口；新语义分支按模块 24 的已批准边界实施，不修改共享 A/B 算法、不生成库外数值、不绕过确认，也不把本模块未来条目提前标为已完成。

## 模块目标

读取标准控制价 Excel，围绕表2、表3、表4完成基价、实物工作费调整系数、技术工作费调整系数三个核心数字的匹配、填入和来源说明。在现有确定性填价基线上，逐步补齐“编制条件确认—项目参数冻结—专项规则复核—人工定案—依据交付”的可信最高投标限价编制闭环。

## 前辈经验反哺设计

### P0：近期可信编制闭环

1. **编制资料和场景先于填价**
   系统不再把“成功读取一个 Excel”视为已经具备完整编制条件。资料清单只做齐备性确认和缺失提示，不自动判断资料真实性；项目阶段、采购方式和框架适用性属于任务级上下文，必须由用户确认。

2. **项目参数不得散落在单元格和聊天中**
   下浮率、综合单价、标准版本和市场询价口径统一进入项目级参数卡。参数必须区分“结构化规则确定”“项目文件确认”“人工录入待核”三种来源，不得因历史项目或大模型回答自动套用。

3. **实物工作费调整系数先治理、后写值**
   当前 `physical_factor_rules` 和 `physical_factor_overrides` 仅保留表头。第一阶段先建立可读规则、依据和冲突样例，并以旁路风险提示验证；只有正式依据、业务口径和回归样例共同确认后，才允许进入第一层自动写值。

4. **专项自检作为主匹配后的独立防线**
   专项自检至少覆盖：
   - 线路航测采用框架综合单价时，不再另计技术工作费；
   - 走向图编制不再另计技术工作费；
   - 钻探深度超过 300m 的部分，不额外计取 1.2 基价调整；
   - 室内试验技术工作费与单独成篇报告 0.1 的适用边界；
   - 2024 版下浮 10% 与框架合同下浮参数的适用范围和组合顺序。

   这层只生成结构化风险和处置入口，不直接复用结算审核引擎，也不改变正式填价的 A/B 确定性匹配模式。

5. **导出前完成一次人机协同检查**
   导出检查需同时回答“数字是否可确定、依据是否齐备、项目参数是否确认、是否还有人工未处理项”。质量门禁不强制阻止业务人员导出工作稿，但必须把未处理风险写入 Excel、Word 和任务留痕。

### P1：专业深度增强

1. **工作量与计价方法一致性**
   复用工作量抓取已有源表 / 目标表定位能力，新增只读差异检查，重点识别钻探进尺、岩石类别、深度分段、单位、重复项、漏项，以及成果报告采用方法与计价项目不一致。

2. **标准外取价和其他费用依据链**
   对标准未覆盖项目建立明确的取价路由，不把“经验值”直接包装成正式价格。最高投标限价阶段以采购技术要求、框架单价、询价单和测算说明为主要证据；合同协议、发票、收据和支付证明属于结算阶段证据，不混用。

3. **完整标准出处和三个字段人工复核**
   在现有轻量追溯基础上补齐标准版本、章节 / 表号和适用条件，并将人工确认扩展到基价、实物工作费调整系数、技术工作费调整系数三个字段。大模型只解释冲突、差异和依据，不产生候选数字。

## 开发前置确认

以下业务口径未确认前，相关 P0 只能形成风险提示，不得修改正式规则值：

1. 当前技术费规则存在 `室内试验 + 试验 = 0.10`，前辈经验提出室内试验并入岩土工程勘察实物工作费后技术工作费按 `1.2`、不重复计取单独报告 `0.1`。需要确认 `0.10` 的准确业务含义、适用字段和保留范围。
2. 2024 版勘察费下浮 10% 与框架合同下浮率是否叠加、先后顺序及适用场景，需要按采购方式和正式文件确认。
3. 超过 300m 部分取消额外 1.2 的口径是否同时适用于最高投标限价编制和结算，需确认规则适用阶段。
4. 市场询价进入人工确认值时，需明确最小证据集合、有效期、询价数量和异常报价处置口径。

## 功能边界

- 基价来自结构化计价库。
- 技术工作费调整系数优先使用第一层标准规则。
- 实物工作费调整系数当前第一层规则未启用，后续补规则前按未命中处理。
- 第二层经验提示只在第一层未命中时使用，并以经验参考方式标识。
- 不允许大模型自由生成最终单价或系数。
- 主流程采用“两阶段批量匹配”体验：`开始转换` 阶段不得批量写入价格或两个系数，只生成待匹配预览；`批量匹配` 阶段才调用既有匹配引擎完成价格、两个系数、诊断列、Excel 输出和 Word 报告。
- 辅助填价只服务“人工复核后采用候选”的下阶段能力，不自动填入正式结果，不一键批量采用候选，不把候选逻辑外溢到主匹配、经验池预警或第二层经验提示。
- v5.4.0 的辅助填价 MVP 只针对基价 / 单价字段；候选生成使用独立 `fill_assist.py`，模式放宽只用于候选展示，不改变主匹配。
- 辅助填价与标准依据追溯按“两步走”推进：第一步先完成基价 / 单价弹窗内合并展示候选和轻量追溯；第二步再扩展到实物工作费调整系数、技术工作费调整系数的候选和溯源。
- 辅助填价后续需求以 `09-辅助填价与人工复核闭环/PRD.md` 为主入口；本模块只保留与三数字主匹配相关的边界和验收口径。
- 辅助填价候选排序按相似度降序排列；相似度相同时，知识库候选优先于经验池候选；再按置信度和经验池样本数做次级排序。
- 当前辅助填价入口属于结果预览的行级操作：固定 `AI` 列内，书本图标只查看结构化候选，机器人图标启动 AI填价并自动解释排序候选；横向滚动宽表时该列仍应固定在右侧可点击。
- 辅助填价详情必须使用 Dialog / Modal 弹窗：顶部展示 sheet 和行号，中部展示待填字段、当前值、行上下文、候选来源、说明和风险提示，底部保留取消和确认写入动作；不得再在主页面或表格下方追加常驻内容。
- 价格辅助填价弹窗内的“依据追溯”只展示结构化线索和规则说明入口；完整“标准依据 / 依据出处”字段尚未维护时，不得把轻量线索包装成正式标准条款。
- 投标限价编制与结算审核共享专业资料和可复用规则候选，但保持独立业务状态、独立处理链和不同证据口径；不得把结算发票真实性核验直接迁入限价填价。
- 专项自检是主匹配后的旁路防线，不修改正式 A/B 匹配模式，不以专项风险为由静默覆盖主匹配结果。
- 任何项目下浮率、框架综合单价、市场询价值或标准外人工值都必须带来源和人工确认，不允许大模型或历史均值直接裁决。

## 验收口径

- 输出 Excel 可打开，原始输入不被覆盖。
- 点击“开始转换”后，结果预览可见但 `matching_status=pending`，价格和两个系数尚未批量写入；下载 Excel / Word 应等待批量匹配完成。
- 点击“批量匹配”后，系统完成原本主流程中的价格、两个系数识别填写、公式刷新、报告生成和可下载输出。
- 命中第一层为绿色，命中第二层为黄色，未命中为红色。
- 逐行报告能说明当前命中层级、匹配说明和待复核原因。
- 修改匹配逻辑后必须运行后端测试。
- 辅助填价 MVP 若启动开发，应至少保留候选来源、候选排序原因、人工确认人机边界和写入留痕；没有结构化依据的候选不得写成确定结论。
- 辅助填价前端验收：AI 列内两个圆形图标按钮保持同列居中，AI 列横向滚动时固定在右侧；点击书本图标只打开弹窗，不改变当前结果预览页面整体布局。
- 价格依据追溯验收：点击书本图标后，同一弹窗内必须能看到价格候选和“当前价格依据追溯”；追溯至少展示匹配过程、经验池依据或项目规则入口之一，并明确轻量追溯不等于完整标准出处映射。
- P0 新增能力不得改变 `08-测试与演示/测试-V3.1-260802/` 现行核心业务验收结果：必须使用 `【项目例子】【测试输入】可行性研究勘察测量控制价计算 -v3.1【演示】 .xlsx` 跑通正式流程，并将生成的 Excel、Word 分别与同目录两份 `【答案-对应版本v3.1】` 文件核对。旧 100 行、500 行测试表只保留为历史回归资料；资料缺失、项目参数冲突、实物系数、超深钻孔、室内试验、航测 / 走向图和带风险导出继续使用独立专项回归样例。
- 实物工作费调整系数第一层从“风险提示”切换为“自动写值”前，必须完成正式依据确认、说人话规则表、程序规则表、冲突样例和逐条自动化测试。
- 导出前质量门禁必须区分“系统已确定、经验提示、人工已确认、待人工处理”四种状态；带风险导出不能伪装为全部审核通过。
- 项目级计价参数必须进入任务快照和成果说明；重新打开历史项目时能够说明当时采用的参数及来源，不随当前默认配置变化。
