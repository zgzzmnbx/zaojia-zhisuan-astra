# AI 增强匹配与离线双模式——加强版 PRD

文档版本：v1.0.0｜确认日期：2026-09-05｜优先级：P0（决赛升级主线）

实施基线：v5.24.0｜计划软件版本：v5.24.1

状态：方案已获用户批准，G0—G4 修复门禁已完成，本地 v5.24.1 已交付，未部署、未 push；本文仍是本次升级需求的唯一权威来源，实施方案解释如何实现，不得降低本文门禁。有限题集和合成性能样本不外推为所有异构 Excel 的准确率或性能。

## 模块目标

让大模型在真实 Excel 的结构理解、专业要素提取和疑难条目适用性辨析中产生可验证的业务增量，形成“材料理解 → 证据核对 → 人工确认 → 可信取价 → 成果输出”的核心闭环。模型返回可核验的要素、候选条目和缺失条件，程序继续从冻结的知识库与规则资产读取数字。

保留原有机械匹配引擎与行为作为独立可选模式及离线兜底。不得通过增加模型调用次数、把规则结果重新润色、预置答案或视觉动画冒充核心智能升级。上线依据为质量、人工工作量和速度的对照证据。

## 已确认决策与工作假设

### 用户已确认的硬要求

1. 新任务默认使用新的 AI 增强模式；原机械匹配保留，能手动选择并独立离线工作。
2. 原规则对原始或人工确认输入的明确命中按现状自动处理。新增 AI 推断只要可能影响三个数字，必须先人工确认，再由程序写入可信资产中的值。
3. 模型不可用、超时、响应非法时自动降级，并明确提示实际执行模式、原因与未处理事项。
4. 保留“开始转换 → 待匹配预览 → 批量匹配”的流程；理解阶段不得提前批量写价格和系数。
5. 保护现有功能、数据、人工修改、主题与布局；不能为了新能力重写既有业务核心。
6. 首版覆盖可读取的 `.xlsx`、复杂结构理解及三个数字相关的候选辨析；不扩展 PDF、图片 OCR、旧 `.xls`、宏执行或任意 Excel 自动化。
7. 开发由 `gpt-5.6-luna`、`max` 思考强度的目标模式任务完成。开发模型与软件运行时模型分开配置。

### 不阻挡开工的工作假设

- 运行时先复用当前用户设置及凭据入口，不自行新增付费服务、换供应商或修改全局问答配置。源码默认模型当前为 `deepseek-v4-flash`；实际可调用模型、网络与响应质量必须开工实测，不能把默认值当作在线能力证明。
- 以约 100 个有效业务行作为首轮性能样本规模，另设 500 行分块扩展样本。这是工程测试口径，不代表用户实际最大文件规模。
- 性能目标见“验收口径”。决赛日期、决赛赛制、最大文件规模及新增服务授权尚未给出，不编造日期、不把复赛 8+2 分钟自动当成决赛安排。
- 本轮交付本地实现、测试证据、发布资产携带检查和文档；不自动部署云端、push、发外部消息或启动机器人。用户随后另行安排实际发布。

## 模式、入口与历史兼容

| 场景 | 默认行为 | 不变量 |
| --- | --- | --- |
| 专业工作台、智算助手中新建填价任务 | `ai_enhanced`，创建时冻结 | 两入口读同一个任务模式，不能各自维护一份状态 |
| 用户明确选择机械模式 | `mechanical` | 原引擎、原归一化、A/B 模式、三个数字层级、样式和成果口径保持原样 |
| 历史任务缺少模式字段 | 解释为 `mechanical` | 不覆盖历史文件、不重算历史结论、不静默引入模型 |
| 旧客户端/旧接口契约 | 通过兼容适配显式走机械模式 | 新受控前端必须发送模式；不能仅把所有缺省 API 请求改成 AI |
| 飞书/WeAct、结算、原工作量抓取等原入口 | 本轮保持原处理链并标记实际机械路径 | 本轮“新任务默认 AI”仅指上述已支持的交互式填价入口；不偷偷升级机器人或其他专业模块 |
| AI 故障 | 机械降级或提示人工映射 | 明示请求模式与实际模式；不足数据保留待复核 |

模式在任务创建/开始转换时冻结。已经有运行结果、人工修改或确认记录的任务需要切换模式时，创建同 Task 下的新 Run 和成果副本，保留旧 Run；不得对已确认成果就地覆盖。旧任务继续使用创建时的选项和 Skill 资产版本。

纯机械流程不得依赖新模型客户端、模型缓存、外部网络或 AI 配置的有效性。缓存损坏、无 API key、新模块异常都不能阻止旧流程。这里保证的是匹配流程离线；既有联网问答不被宣称为离线能力。

## 表格理解与输入输出边界

### 支持的首版复杂性

- 列移动或命名变化，表头前存在项目说明，多层表头、多数据块、重复表头。
- 同一格混写专业内容、等级、规格等，章节标题或备注提供行级上下文。
- 多 sheet、纵横合并、空行、隐藏行、小计合计行，须沿用原模块适用的选择、过滤和隐藏规则。
- 对扫描覆盖范围建立行清单：业务行、非业务行及排除原因。超过资源上限必须显示范围和未处理数，不得静默截断。

程序读取原始值、公式文本、缓存值、坐标与合并范围；模型不能改写数量、凭空补单位或生成公式。公式无缓存值时不得当作 0，应使用原有安全重算能力或列为待核实。合并单元格沿用项目默认：跨行共享值、跨列仅首列有值。章节语义继承是独立带证据的建议，不得改造底层合并规则。

表级模型输出声明式映射，不输出可执行代码、命令、任意路径或表达式。模型判断的字段映射会影响三个数字时，用户必须在理解预览中确认该映射/要素方案。结构合法与有来源不等于业务适用性已确认。

### 输出策略

- 已受支持的控制价计算表：继续在原输出副本中按既有坐标回填，保留原格式与公式，不把标准输入无故重新排版。
- 异构 `.xlsx`：生成仅用于本任务的标准化中间数据，绑定真实来源坐标；按已上线 Skill 的现有可信控制价模板形成计算表。先确认映射和目标行，不凭模型新造模板、公式或计价条目。
- 模板中没有可落位条目时，列入“未映射记录”；禁止按相似文字随意塞入目标行、自动扩展未知费用公式或直接计入总额。结果预览必须显示数量及原文，不得丢弃。
- 源行与目标行允许存在显式分配关系，但首版不自动执行一对多拆量、多对一合量或单位换算；这些情况转人工处理，数量不按模型建议自行改变。
- 人工映射的输入与异构来源可追溯。原文件保持只读；中间文件、候选、运行审计进入当前任务输出/运行目录，不写回正式知识库或经验池。

## 三个数字的判断及确认契约

| 字段 | 可信数字来源 | AI 可以增加什么 | 必须保留的边界 |
| --- | --- | --- | --- |
| 基价/单价 | 当前 Skill 的结构化计价库 | 要素提取、有限候选比较、适用条目建议 | 不生成库外价格；单位不一致不进入可采用候选 |
| 技术工作费调整系数 | 已启用第一层规则；未命中时的原第二层经验提示 | 识别证据中存在的条件，指出规则适用或缺失条件 | 不杜撰标准条文；第一层优先；经验来源不可升级为标准 |
| 实物工作费调整系数 | 原第二层经验提示及受控人工候选 | 提取影响条件、说明经验候选差异或无依据 | 第一层当前未启用，不能为增强 AI 而自动补规则或假称标准命中 |

对同一字段，原规则明确结果不得被 AI 自动覆盖；若模型发现冲突，仅新增待核实建议。无候选、多候选、单位冲突、适用条件不足、来源失效均允许返回 `needs_review`/`no_candidate`，不强制选第一名。

候选清单先做可信来源检索和硬条件过滤，再送模型；模型选择仅能引用本轮候选集中的稳定 ID。候选中的自由文本均作为资料处理，不能指挥模型忽略限制。正式计价库条目与标准出处分开标识：只有库中条目不等于已经维护了正式条款出处。

模型建议至少包含：记录 ID、目标字段、建议要素、候选 ID、支持证据坐标/原文、排除差异、缺失条件、风险提示。模型自报置信度、相似度最高、JSON 解析成功均不是自动写值依据。

人工确认必须覆盖具体 sheet/行/字段与具体候选，保留旧值、新值、候选来源层级、确认人、时间、备注、输入与成果版本。表级确认只确认展示出来的映射和要素；不能暗含同意所有后续候选。字段候选不预勾选、不一键全部采用，不扩大到任意自定义库外数值。

服务器确认时从冻结资产重新读取数字，拒绝前端/模型提交的任意值，检查候选合法性、单位、规则适用前提、版本与当前单元格可编辑性。与人工修改冲突、候选过期、来源版本变化必须拒绝旧确认，并要求重新生成。确认与写回幂等，重试不新增重复审计、Task 或成果。

确认后沿用现有公式刷新及报告更新机制；若尚未重算，清楚显示待重算与旧报告状态。未确认建议不进入正式总额。经验提示保留原黄色和来源，人工确认保持原人工修改样式；不能统一涂成绿色“标准命中”。

## 性能、故障与审计要求

- 常规流程最多两轮串行模型依赖：表级理解＋一轮疑难组辨析。多个独立数据块允许有限并行，不能宣称整文件永远只有两次请求。
- 模型只返回足够校验的短结构化结果，长解释按需展开。限制数据块和输出大小，不能把全部工作簿或整个知识库原封不动送入模型。
- 模型执行使用独立预算，不继承当前通用客户端 90 秒单次超时与最多 3 次网络尝试。超时、失败、重试、排队均计入预算；不得用前端进度条掩盖后端继续长时间运行。
- 去重键必须包含完整专业要素、单位、章节/备注作用域与来源版本；缓存还必须包含输入相关内容哈希、Skill/规则/知识库/模型/提示词/解析器版本。缓存仅是建议，首次需要的人工确认不能绕过；修改、撤销和过期后失效。
- 明确区分 `model_live`、`model_cache`、`mechanical`、`manual_confirmed`、`degraded`，分别记录真实调用次数与延迟。模型判断或缓存未被实际消费时不得计为 AI 成功处理行。
- 降级必须从未受未确认 AI 数据污染的原输入及原机械映射执行。已经人工确认的 AI 来源输入若继续使用，应标成“已确认输入＋机械执行”，不能声称全程纯机械。
- 异构文件在离线状态下无法按原机械入口解析时，保留可恢复状态并提示人工映射，不自动猜字段。失败/取消/切模式之后晚到的模型响应不得写回；部分失败只影响关联块，用户确认与已有成果保留。

## 功能边界

- 新语义分支与原机械匹配并存；不修改共享 A/B 归一化、知识库单价、正式系数规则、经验均值/阈值、报告计算或工作量抓取规则以提高 AI 命中率。
- AI 不负责生成最终数值、决定无证据条件、直接改写公式、自动写正式资产、关闭风险或批准知识记忆。
- 不扩展结算业务、第二专业 Skill、知识网络、机器人行为或任意文件执行；只做与本模块集成必要的兼容修改。
- 不新增一级导航、不重排主界面、不移除原按钮和图表。模式开关、证据和确认通过现有设置/弹窗/任务区局部接入；深浅色与窄宽屏按既有 UI 硬门禁独立验证。
- 首版先在原模式可验证基础上增加分支；不能以“重构更整洁”替换整个 `fill_engine.py` 或通用模型客户端。
- PRD 中规划路径不是已经存在的生产模块；实现后才能修改当前软件版本和模块完成状态。

## 验收口径

### G0：实施前基线

记录 HEAD、已提交/未提交文件、重要业务资产哈希、已有后端/前端测试结果及 V3.1 Excel/Word 成对验收。已有失败必须查明与本任务的关联，不能删测试或修改答案来消除差异。当前已发现 `App.tsx`、`styles.css` 存在未提交改动及其他资料变动，实施时重新检查并完整保留。

### G1：旧模式无损与故障独立

- 升级后的机械模式在有网、断网、无密钥、模型 429/5xx/超时、缓存损坏、新 AI 配置无效时保持原匹配结果与可用性，匹配模型调用数为 0。
- 使用 `08-测试与演示/测试-V3.1-260802/` 正式输入，Excel 与该目录对应答案核对三数字、公式/计算值、表结构、行覆盖、颜色、待复核状态、隐藏行和诊断；Word 核对业务核心、金额、依据、风险、分页与可读性。时间戳和输出文件名等动态字段仅允许显式白名单忽略。
- 新模式在相同已支持标准输入上也不得改变既有确定性业务结果。新增语义审计优先进入旁路，不制造原成果差异；确需新增用户可见来源说明时逐项列出新增差异，不能忽略数字/公式/风险差异。
- 原问答、经验池预警/导入、工作量抓取、结算审核、人工改单/重算、Word 预览、Task/历史、协同适配、Skill 隔离及发布资产携带完成针对性回归。

### G2：新模式正确性

覆盖三字段、有候选/无候选/多候选、单位冲突、条件缺失/矛盾、未知条目、恶意指令文本、多块表头、合并范围、公式缓存缺失、隐藏/空白/小计/合计、来源过期、重复点击、手改冲突、刷新、取消和部分失败。未确认写入数、库外数字写入数、错误单位自动采用数、未说明漏行/重复行数必须均为 0。

至少冻结 12 个语义与结构验收案例（标准格式仅作对照，必须包含两个系数及拒绝推荐），至少 4 个案例在提示词调优前作为留出集；至少覆盖 3 种不同表结构。衍生/合成案例必须标明，不能冒充不同单位的真实文件。每例事先记录人工或可信规则验证的期望与证据，不得从待评模型的输出反向生成标准答案。

真实文件足够时增加外部格式验证；不足时仍完成合成回归和可用真实文件验证，单列“真实异构文件泛化待补”，不能宣称任何表格都能识别。标准答案中有未定业务口径的字段作为拒答/待复核测试，不把未经确认的价格当真值。

评估完整流程与“同输入同候选集、禁用语义模型”的对照。至少展示 3 个由真实模型有效解决的疑难案例及 1 个正确拒绝推荐案例。推荐精确率目标不低于 95%，可判定疑难项有效解决率目标不低于 80%，报告分子/分母、字段分布和留出集，不用全拒答换取精确率。有限样本结果不得外推为全行业准确率。

### G3：速度与真实调用

首轮配置建议：100 行、最多 20 个疑难组、最多 3 个数据块、输入载荷约束明确；冷缓存首次产生可复核结果中位数目标 ≤30 秒、P95 目标 ≤45 秒；模型阶段总墙钟硬上限 60 秒，超过则取消该阶段并降级。以上是待测目标，未验证前不能写成产品现有性能；不能通过放宽正确性或静默缩样本达标。

记录至少 20 次冷缓存端到端尝试（含失败），统计上传完成到可复核状态的机器时间；另记人工作业、确认时间及最终 Excel/Word 导出时间。标注模型、日期、网络、样本规模、输入/输出 token、缓存状态和超时率。500 行样本验证分块、资源上限与健康接口响应，不承诺同样的时延。目标未达先优化，外部条件无法达标时如实报告、保留机械默认回滚开关，不把任务标记为全部验收完成。

不得用 `curated_demo`、风险演示旁路、mock、预置答案或热缓存结果证明实时模型推断。V3.1 演示样例仅证明回归；AI 增量用独立安全副本/样例走真实新增模型端点，明确 `generated_by_model` 与实际调用记录。

### G4：界面、交付与完成

完成前端生产构建、后端全量测试、V3.1 双模式成对核对、真实浏览器多宽度/深浅色/字体与控制台检查、新旧模式切换及实际模型调用验证。绿色版做配置携带、启动和新旧模式冒烟；云包构建/检查证明资产齐全但不部署。原机密和运行数据不得进入版本包、测试报告或 Git。

只有 G0—G4 的必需证据满足、需求状态准确、文档更新、版本升级及本地 Git 存档完成后，Luna 才能标记目标完成。缺 API 凭据或无网络可先用 mock 完成其他测试，但真实 AI 与速度门禁仍未通过；无法推进时按目标工具的阻塞规则留档，不能把部分完成冒充交付。
