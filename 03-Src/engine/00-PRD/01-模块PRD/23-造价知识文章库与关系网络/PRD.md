## 模块目标

建设一个适合普通读者浏览的造价知识文章库。用户既可以像阅读专题文章一样逐篇查看，也可以通过类似 Obsidian 的关系网络发现概念、业务环节和风险主题之间的联系。

首期以 50 篇真实、可读、可追溯的造价知识文章形成最小完整产品。关系由文章主题、标签和人工确认的关联清单在构建期生成，浏览器只读取已经冻结的图数据，不在页面打开时调用大模型、计算向量或扫描全文。

本模块是“阅读与发现”能力，不是现有“问问智算”的检索底座，也不参与任何价格、调整系数、风险等级或正式标准裁决。允许复用现有智算窗口显示用户点击的本地文章正文，但该动作属于确定性 UI 展示，不构造问题、不触发回答和沉淀。

## 用户价值

1. 新用户可以按专题连续阅读，快速建立造价知识框架。
2. 用户阅读单篇文章时，可以沿关联文章继续探索，不依赖准确输入关键词。
3. 关系网络可以直观看出哪些文章属于同一主题、哪些知识跨越合同、计价、结算和风险环节。
4. 文章与来源依据保留可追溯关系，避免把通俗知识文章误认为正式标准或项目结论。
5. 独立数据和延后加载保证该功能即使异常，也不影响现有填价、预警、报告、问答和协同主流程。

## 内容规划

### 主题矩阵

首期建议使用 10 个主题、每个主题 5 篇，共 50 篇。Luna 必须先读取本地资料，根据真实来源细化标题，不得仅凭常识批量扩写。

| 主题 | 建议覆盖方向 |
| --- | --- |
| 油气输送管道工程 | 从第 1 册正文与清单中节选工程分类、项目特征、计量单位和阅读方法 |
| 储罐制作安装工程 | 从第 2 册清单中节选储罐相关项目的分类、特征与计价资料使用提醒 |
| 通用安装工程 | 从第 3 册清单中节选安装专业分类、项目边界、特征表达和清单阅读方法 |
| 其他工程 | 从第 4 册清单中节选其他工程项目的适用范围、分类与使用边界 |
| 参考计价依据 | 从第 5 册中节选参考项目、适用条件、单位和引用边界 |
| 全费用清单单价 | 结合第 1—5 册解释清单结构、全费用口径、项目特征、工程量和复核要点 |
| 建设项目其他费用 | 从 2024 年其他费用依据中节选费用类别、适用阶段、资料条件和复核边界 |
| 概算指标与费用定额 | 从 2005 年概算指标说明及 2005、2015 年费用定额中节选指标与费率资料的阅读方法、版本差异和适用提醒 |
| 数字与信息化项目投资 | 从 2024 年数字与信息化项目投资计价依据中节选投资构成、工作内容和计价资料使用方法 |
| 软件行业基准数据 | 从 2025 年中国软件行业基准数据中节选指标含义、样本口径、数据应用和误用风险 |

主题矩阵是数量和覆盖度约束，不等于文章标题。若本地资料不足以支撑某一方向，必须换成有依据的主题，不得为了凑数编造内容。

### 单篇文章结构

- 标题应直接表达问题或知识点，避免营销化标题。
- 正文控制在 450—650 个汉字，标题、元数据和来源清单不计入。
- 正文通常包含问题背景、核心解释、应用提醒和边界说明，但不强制机械套用固定小标题。
- 每段增加新的事实、判断或操作信息，不用同义反复凑字数。
- 语言自然、克制、专业，避免机构宣传腔、模型套话和空泛升华。
- 文章页明确标注“知识文章，仅供辅助阅读；正式业务以有效标准、项目规则和人工复核为准”。
- 来源依据记录到清单，不在正文中虚构条款号、页码、价格、比例或结论。

### 资料来源

首期唯一资料源为项目现有 `06-知识库问答资料/造价AIW资料库`。该目录当前由 `manifest.json` 管理 13 项 `ready` 的 AIW Markdown 资产，覆盖 2024 年全费用工程量清单单价第 1—5 册及正式正文、建设项目其他费用、数字与信息化项目投资、2005 年概算指标说明、2005 / 2015 年费用定额和 2025 年软件行业基准数据。

- Luna 只读取 `manifest.json` 声明且状态为 `ready` 的 Markdown 文件，不回到外部原始资料目录继续扩源。
- 文章采用“节选、整理、通俗改写”的方式形成，不能把连续大段原文简单复制成文章，也不能加入 AIW 资产没有依据的新事实。
- 每篇 `source_basis` 至少记录一个 AIW `asset_id`、输出文件名和可定位的标题路径；Excel 问答版能定位时再记录工作表与行号。
- 13 项 AIW 资产只读不改，新文章和关系清单仍写入独立的 `造价知识文章库`，不得混入现有目录或反写现有 `manifest.json`。
- 默认不得上传本地资料、调用外部内容接口或引用网络材料。若 13 项资产不足以支撑预定主题，应调整选题或缩小结论，不得编造。

## 数据设计

### 独立目录

实施时新建以下目录，不移动或改名现有知识资产：

```text
06-知识库问答资料/造价知识文章库/
├─ README.md
├─ manifest.json
├─ articles/
│  ├─ cost-001-文章标题.md
│  └─ ...
└─ reports/
   ├─ 内容质量报告.md
   └─ 关系完整性报告.md
```

### Manifest 契约

`manifest.json` 是首期唯一机器可读清单，建议结构如下：

```json
{
  "schema_version": 1,
  "library_id": "cost-articles-v1",
  "title": "造价知识文章库",
  "article_count": 50,
  "articles": [
    {
      "id": "cost-001",
      "title": "示例标题",
      "category": "造价基础",
      "tags": ["示例标签"],
      "summary": "不超过八十字的摘要",
      "file": "articles/cost-001-example.md",
      "source_basis": ["资料源内的相对标识"],
      "status": "published"
    }
  ],
  "relationships": [
    {
      "source": "cost-001",
      "target": "cost-007",
      "type": "manual",
      "weight": 1.0,
      "reason": "说明两篇文章为什么相关"
    }
  ]
}
```

- 文章正文不依赖 YAML 解析，避免为 front matter 增加新后端依赖。
- `source_basis` 保存可展示的资料名称或相对标识，不向前端暴露本机绝对路径。
- 关系按无向边处理，每条只保存一次；`source` 小于 `target`，便于确定性去重。
- 首期 `type` 固定为 `manual` 或 `shared_topic`。即使由 Luna 批量生成，也必须经过结构校验并保留 `reason`。

## 关系建立规则

1. Luna 先形成 50 篇标题与主题矩阵，再为每篇文章确定 3—6 个稳定标签。
2. 每篇至少连接 2 篇、最多连接 5 篇，避免单篇孤立和中心节点过载。
3. 优先建立“前置知识—后续应用”“同一业务阶段”“共同风险点”“跨阶段证据链”等可解释关系。
4. 同分类或同标签只能作为候选依据，不能仅因出现一个宽泛词就强行连边。
5. 每条边必须有简短 `reason`，图上默认不显示长说明，文章详情可以查看。
6. 构建脚本必须检查节点数、边数、悬空 ID、自环、重复边、孤立节点、连通分量、度数分布和文件存在性。
7. 首期不在运行时重新算相似度；需要重建时由离线脚本生成新清单并人工复核差异。

## 页面与交互

### 信息架构

在现有“知识库问答”一级模块内增加二级页签，不新增左侧菜单。建议页签为：

```text
知识库状态｜造价文章库｜知识网络
```

现有知识库状态、知识库选择器和问答设置保持原逻辑。新增页签只做最小接线，主要代码放入独立组件目录。

### 文章目录

- 默认展示文章总数、分类筛选、标签筛选和标题 / 摘要搜索。
- 列表仅请求元数据，不传输 50 篇全文。
- 每项显示标题、分类、摘要、标签和相关文章数量。
- 空结果、加载、错误和重试状态必须完整；错误不得扩散到现有知识页。

### 文章阅读器

- 点击文章后单独请求正文，支持返回目录、上一篇 / 下一篇和相关文章。
- 点击相关文章可以在同一阅读器内切换，不创建第二套页面状态。
- Markdown 仅开放必要、安全的展示能力；不得执行原始 HTML、脚本或危险链接协议。

### 知识网络

- 使用 `react-force-graph-2d` 二维 Canvas 力导向图；50 个节点无需图数据库和复杂 WebGL 架构。
- 星云画布使用隔离的深空视觉；节点颜色按分类、尺寸按有限连接度区分，初始排布完成后停止动画。
- 默认显示全部网络，支持缩放、拖动、搜索定位、悬停邻居高亮和点击节点打开文章。
- 普通节点名称从 `1.5×` 开始由浅到亮显示，`2.25×` 达到正常亮度；选中、悬浮和搜索命中节点不受该渐变限制，始终保持清晰高亮。
- 点击空白处必须清除选中状态；左下角节点卡片在选中后持续显示，并列出可点击的具体关联笔记名称，点击后复用同一节点选择与文章读取流程。
- 首次进入可播放 1 秒星云铺开、低幅持续漂移和拖动惯性；首次状态遵循系统减少动态效果，用户可用知识网络专属开关覆盖并保存偏好，不影响其他模块。
- 进入网络页签时默认收起左侧功能导航；右侧关系列表默认折叠，展开后覆盖在画布右侧，不再增加页面纵向高度。
- 点击节点后展开现有智算 Dock，并以普通本地消息显示该文章正文和来源依据；不得调用 `/api/knowledge/search`、`/api/knowledge/ask` 或任何模型接口。
- 本地文章在智算 Dock 中沿用既有逐字符展示机制和既有速度；不得为知识网络修改全局消息节奏，用户点击正在展开的消息时仍可立即显示全文。
- 智算 Dock 开合或宽度变化时，图谱根据实际容器宽度重算 Canvas 并重新聚焦，不使用写死的页面宽度。
- 选择节点后弱化非邻居，显示标题、分类、摘要和关联原因。
- 支持减少动态效果；图形不可用时提供可操作的关系列表替代。
- 外围控件继续使用项目自托管苹方、`--dws-*` 令牌、字号和深浅色体系；深空画布的星点、光晕和云气只作用于本模块，不改变其他亮色或暗色页面。

## 技术设计

### 前端隔离

- 新组件集中放入 `frontend/src/components/knowledge-articles/`。
- `frontend/src/App.tsx` 只做页签和数据入口的最小接线，不继续堆积文章与图谱业务逻辑。
- `frontend/src/App.tsx` 可负责把节点 ID 转换为一次独立文章详情请求并追加本地展示消息；该函数不得复用问答提交、检索、记忆候选或任务状态函数。
- 图谱组件使用 `React.lazy` 或等价动态导入，只有用户进入“知识网络”后才下载和挂载。
- 离开图谱页签必须卸载图形子树，不能用 `display:none` 长期保留动画循环。
- 已选用 `react-force-graph-2d 1.29.1`，MIT 许可、React 19 构建通过；依赖只进入 `KnowledgeNetworkGraph` 异步 chunk，不进入主入口包。
- 不在启动阶段预取正文或图谱。若做空闲预加载，只能在首屏稳定后、浏览器空闲时执行，并且可取消、不得阻塞其他页面。

### 后端隔离

- 新建独立只读服务，例如 `backend/app/knowledge_articles.py`；`backend/app/main.py` 只注册路由。
- 建议接口：
  - `GET /api/knowledge-articles` 返回元数据列表。
  - `GET /api/knowledge-articles/{article_id}` 返回单篇正文和元数据。
  - `GET /api/knowledge-articles/graph` 返回 50 个节点和冻结关系。
- 服务启动时不得遍历和解析 50 篇正文；只在第一次请求时读取并校验清单，结果按内容签名缓存。
- 单篇正文按安全相对路径读取，拒绝路径穿越、绝对路径和清单外文件。
- 文章模块异常只返回自身错误，不影响 FastAPI 健康检查和其他业务接口。

### 发布携带

实现后必须把独立文章库加入绿色版和云端发布资产检查。缺失文章库时允许主程序启动，文章页显示明确不足态；不得因可选文章资产缺失阻断 Excel、报告或问答。

## 性能红线

以下均为发布硬门禁，任一不满足都不得宣称完成：

1. 打开应用、项目看板、填价、预警、报告、智能协同或现有知识库状态页时，不发起文章或图谱 API 请求。
2. 图谱依赖必须形成独立异步 chunk，不能进入主入口 bundle；构建报告和浏览器 Network 均需提供证据。
3. 首次文章列表请求只返回 50 篇元数据和关系计数，不返回全文；响应体应控制在 100 KB 以内。
4. 正文只在点击文章后读取；同一文章可使用有限内存缓存，不能在后台一次读完 50 篇。
5. 关系图只使用冻结的最多 50 个节点和受控边数，运行时不调用大模型、不生成 embedding、不扫描全文。
6. 离开图谱页签后不再存在动画帧、ResizeObserver 或隐藏 Canvas 持续工作。
7. 新模块故障、超时或数据损坏不能改变现有 `/api/knowledge/search`、`/api/knowledge/ask`、填价、三个数字、经验池、风险、报告、Task 或协同状态。
8. 宽屏 `>=1025px` 既有布局零变化；窄屏规则独立隔离。暗色改动不得影响亮色模式。

## 功能边界

- 不新增左侧一级菜单，不新建第二个“问问智算”聊天窗口。
- 现有智算窗口只作为文章正文的显示容器；节点点击不得构造用户消息、调用模型、记录 RAG 轨迹、生成知识候选或改变会话检索模式。
- 不修改现有造价 AIW 资料库、知识问答索引、知识记忆 SQLite、结构化计价库、规则表或经验池。
- 不让文章或关系图参与基价 / 单价、实物工作费调整系数、技术工作费调整系数、风险等级和成果生成。
- 不在页面加载时调用大模型生成文章、摘要、标签、关系或布局。
- 不用知识图谱概念包装普通标签列表；所有边必须可解释、可定位、可校验。
- 不引入 Neo4j、独立图服务、外部向量数据库或运行时 GraphRAG。
- 不把本地绝对路径、密钥、内部平台标识或未授权原文返回前端。
- 首期不把 50 篇文章接入现有 RAG；后续如需接入，必须另立 PRD、审核来源并重做检索与性能回归。

## 验收口径

1. 内容验收：恰好 50 篇，正文逐篇达到 450—650 个汉字，标题和内容不重复，分类数量符合矩阵，来源依据非空，硬性文风检查通过。
2. 关系验收：恰好 50 个节点；每篇 2—5 个邻居；无悬空、自环、重复边和孤立节点；边有原因；关系图和相关文章列表来自同一清单。
3. 阅读验收：搜索、分类、标签、文章详情、上一篇 / 下一篇和相关文章跳转真实可用；正文只在点击后请求。
4. 图谱验收：缩放、拖动、搜索定位、邻居高亮、节点点击打开文章、减少动态和列表降级均可用。
5. 性能验收：初始启动和其他模块零文章请求；图谱为独立懒加载 chunk；图谱未打开时不下载、不挂载；离开后停止渲染；元数据响应不超过 100 KB。
6. 兼容验收：现有知识问答、四道预置回答、经典 / 混合 RAG、知识记忆、填价、经验池、报告、Task 和智能协同接口及交互保持原样。
7. 自动化验收：运行文章清单 / 关系 / 安全专项，前端专项，`python -m pytest backend/tests -v`、前端生产构建和 `python tools/check_prd_consistency.py --strict`。
8. 运行态验收：在亮色与暗色、390 / 768 / 1024 / 1366 / 1440 / 1920 宽度核对字体、布局、控制台和 Network；宽屏现有关键页面与实施前基线无差异。
9. 核心业务验收：使用 V3.1 正式输入跑通主流程，将新生成 Excel、Word 分别与现行标准答案核对；三个数字、公式、风险和成果内容不得因本模块变化。
10. 发布验收：绿色版和云端资产检查能携带文章库；文章资产缺失时模块诚实降级，主程序和现有业务仍可启动。

## 回滚方案

- 前端保留单一功能开关，可隐藏新增二级页签，但不能影响现有知识库状态和问答入口。
- 后端新增路由可独立撤除，不修改现有知识接口的数据契约。
- 文章库全部位于独立目录，回滚代码时不需要迁移或改写现有知识资产。
- 如果性能、兼容或 V3.1 回归任一失败，维持功能关闭，不得用减少测试范围换取上线。
