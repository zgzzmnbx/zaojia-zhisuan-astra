```text

项目根目录：
D:\Codex-Temp\260612-【ai大赛】-管勘智算-V2.0

7. 本次改动涉及的模块 PRD、规则说明和专项交接文件

SSH 登录信息保存在本机 Git 忽略文件：
Codex-Temp/runtime/cloud-deployment-credentials.json

大尾巴已经授权你读取并使用其中的 SSH 账号密码完成本项目的既有云服务器发布。但必须遵守：

- 优先使用 Python paramiko 直接读取该文件并建立 SSH/SFTP 连接，不把密码拼进命令行。
- 执行前确认该文件仍被 git check-ignore 命中。

你必须直接执行完整闭环，不要只给方案：

一、接手与边界
- 检查 git status、当前分支、最新提交、版本号和未提交改动。
- 保留用户无关改动，不得擅自加入、移动、覆盖或删除。
- 从代码和项目文件确定目标版本，不凭聊天猜测。
- 不修改三个数字匹配、正式规则、结构化计价库、经验池、报告模板或业务功能，除非本次待发布改动本来就包含这些内容。

二、本地门禁
- 按 AGENTS.md 和改动范围运行前端构建、后端测试、专项测试、PRD 一致性检查和 git diff --check。
- 任何应通过的门禁失败都先查明原因；不能带病发布，也不能把旧失败伪装成本次成功。

三、发布包
- 必须优先运行 `python tools/build_cloud_release.py`，由脚本在 Codex-Temp/cloud-deploy/ 下建立本次独立暂存目录；不得再复制上一版暂存目录作为文件清单。
- 构建器生成最小但完整的运行包，包含后端、frontend/dist、business-skills、项目默认配置、部署保护、云端检查器，以及所有已上线 Skill Manifest 声明的结构化计价库、规则、知识源、经验池和报告模板资产。
- 必须确认构建器的首页 JS / CSS 层级检查、秘密排除检查和资产门禁通过，并使用脚本输出的 UTF-8 `tar.gz` 与 SHA256。
- 严禁包含 .env.local、SSH 凭据、机器人秘密、知识记忆 SQLite、任务队列、日志和运行缓存。
- 如需人工复核暂存目录，再运行：
  python tools/check_cloud_release.py --release-root <待发布目录>
- 上传后计算云端 SHA256并与构建器输出值比对。
- 优先使用 `python tools/deploy_cloud_release.py preflight` 读取发布前快照，再用其 `publish` 子命令自动执行上传、验 SHA、运行数据继承、切换、验收和失败回滚；手工命令作为排障后备。

四、云端发布
- 发布前记录 current 真实目标、主服务状态、机器人 enabled 配置、机器人 systemd 状态、真实 runner 数量、健康版本和磁盘空间。
- 上传到 /tmp，解压到 /opt/zaojiazhisuan/releases/ 下的新目录，绝不覆盖旧发布目录。
- 从上一发布目录复制 .env.local 和 Codex-Temp/runtime 到新目录，发布包不得覆盖运行秘密和运行数据库。
- 切换前再次验证目标版本、frontend/dist 和关键资产存在。
- 使用既有 /opt/zaojiazhisuan/venv 安装需要的依赖。
- 切换 /opt/zaojiazhisuan/current 后运行 deploy/install_cloud_runtime_guard.sh，确保云端主服务和机器人内部 API 使用 1285。
- 重启主服务并有限轮询 /api/health。健康版本必须与目标版本一致；如果 `version` 为旧运行器兼容值，以 `release_version` 判定实际发布版本。
- 若主服务未恢复，立即将 current 切回发布前记录的目录，恢复运行保护和主服务；确认旧版恢复后再报告失败。

五、第二层机器人
- 主服务健康后读取 /api/collaboration/feishu-app-bot/status，执行 `systemctl enable --now zaojiazhisuan-feishu-bot.service`，保持双平台监督器常驻 `active`。
- 监督器状态不等于平台运行态；必须逐一核对 `profiles`：已启用平台要求 `running=true / profile_consistent=true` 且恰好一个运行器，已关闭平台要求 `running=false` 且运行器为零。
- 普通飞书和企业 WeAct 按各自 `enabled` 状态独立恢复，不得为了发布验收强行改变平台开关。
- 运行 tools/check_feishu_deployment.py --mode cloud --check-health。
- 禁止为了验证向任何飞书或 WeAct 群、个人发送测试消息，尤其禁止向未授权群发送。

六、上线验收
- 验证公网 /api/health 为 HTTP 200 且返回目标版本。
- 验证公网首页和当前 JS/CSS 资源为 200。
- 核对首页实际引用的 bundle，并在 bundle 中验证版本和本次关键功能标识；不要被浏览器缓存误导。
- 对 /api/knowledge/search 做一次不调用大模型的检索验证。
- 核对 current 软链接、主服务、机器人状态、runner 数量和回滚点。
- 删除 /tmp 中本次上传包，不删除任何历史发布目录。

七、文档与 Git
- 更新 docs/云服务器部署说明.md，写清版本、发布目录、上一回滚目录、SHA256、健康检查、关键功能、主服务和机器人状态。
- 如版本或模块状态发生变化，同步 README.md、CHANGELOG.md 和 00-PRD/02-当前版本计划.md。
- 只暂存本次相关文件，完成 git commit 并 push 当前分支；不得把 09-视觉识别-企业VI 或其他无关未跟踪文件混入提交。

最终答复必须给出可核验结果：
- 目标版本与 Git 提交
- 云端发布目录与回滚目录
- tar.gz SHA256
- 本地构建和测试结果
- 公网健康、首页、bundle、知识检索结果
- 主服务、机器人和 runner 状态
- 文档回写、Git 提交和推送结果

只有以下情况可以停止并请求人工处理：凭据无效；服务器经有限重试仍不可达；发布包资产门禁无法通过且缺失资产无法从项目中找到；回滚也失败。停止时必须说明云端当前实际运行版本和服务状态，不能只说“失败”。
```
