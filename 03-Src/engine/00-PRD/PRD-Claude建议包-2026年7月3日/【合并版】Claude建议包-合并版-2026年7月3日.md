3. **本建议包遵守项目核心原则**：结构化规则裁决，大模型解释辅助，人工复核兜底；不建议推翻当前架构，不建议让大模型直接裁决价格、单价、系数或审减金额。

# 二、项目理解与现状判断

**生成日期**：2026-07-03  
**基于版本**：造价智算 v5.3.7  
**判断主体**：Claude（外部产品规划顾问）

## 2.1 产品定位

造价智算是一个**工程造价辅助智能体**，当前核心场景聚焦于**长输管道勘察测量最高投标限价编制**。

它不是：
- ❌ 普通填表脚本
- ❌ 泛用聊天机器人
- ❌ 单点自动化工具

它是：
- ✅ 嵌入工程造价生产链条的专业智能体
- ✅ Excel 工作台 + 规则审查台 + AI 复核助手 + 成果输出中心
- ✅ 造价数字员工雏形

**核心定位特征**：
- 首个落地场景：长输管道勘察测量最高投标限价编制
- 总能力框架：工程造价辅助智能体 / 造价数字员工
- 推广路线：先助手后平台，先闭环后扩张，先可评估后规模化

---

## 2.2 当前核心业务场景

### 业务痛点（四类）

| 痛点 | 表现 | 造价智算如何解决 |
|---|---|---|
| 标准链长 | 收费标准、测绘定额、项目规则、历史说明分散，依据查找和口径统一成本高 | 本地知识库、规则表、标准资料 Markdown 化，问问智算快速检索依据 |
| 数据链散 | 多 sheet、多行表头、合并单元格、隐藏列、单位差异、公式缓存等表格问题频繁 | 结构化 Excel 读表引擎、归一化规则、公式兜底计算、表格预览与人工修改 |
| 经验链断 | 历史经验沉淀在个人电脑、旧表批注、口头判断和项目样表中，难以组织复用 | 经验池预警模块、历史控制价导入、同类记录比选、偏离率风险分级 |
| 审核链弱 | 填价依据、匹配过程、异常原因、经验偏离和复核意见不易留痕 | 三层匹配逻辑、逐行说明、颜色状态、Word 报告、风险报告、行级 AI 复核 |

### 核心用户

1. **造价业务人员**：希望减少重复查价、手工填表、逐行复核和报告整理工作。
2. **数字化建设人员**：希望沉淀可复用的规则资产、知识库资产和智能体能力。
3. **评审或参赛人员**：希望快速看懂产品价值、业务流程、技术边界和可演示成果。

---

## 2.3 当前已有能力

### 3.1 Excel 填价与三数字匹配

- 输入标准控制价 Excel，识别表2、表3、表4等关键 sheet。
- 根据二维知识库和第一层规则匹配 `基价 / 单价`、`实物工作费调整系数`、`技术工作费调整系数`。
- 三层判断：第一层标准规则（绿色）、第二层经验提示（黄色）、未命中（红色）。
- 输出填价后的 Excel、表格预览、匹配摘要和逐行说明。

### 3.2 填价结果预览与输出

- 浏览器中查看填价结果、匹配状态、预警摘要。
- 支持多 sheet、表头行偏好、显示列偏好、隐藏空行、公式兜底计算。
- 支持人工修改输出 Excel 副本的普通值单元格，保存后刷新预览、留存修改记录。
- 下载 Excel 与填价结果预览共用隐藏空行口径。

### 3.3 经验池预警

- 独立于正式知识库，只用于转换后比选预警。
- 用户手动触发"运行经验池预警分析"，按同类记录匹配（字段完全匹配 + 非空要素顺序匹配）。
- 输出预警参数、预警细节、风险分级（低风险 5%、高风险 20%）。
- 大尾巴主题下，预警模块与经验池导入模块上下排列，导入模块默认折叠。

### 3.4 问问智算 AI 助手

- 右侧随行 AI Dock，承载问答、快捷指令、行级复核、风险报告。
- 本地知识库证据检索后回答，无依据时提示人工复核。
- 强制知识库模式：以 `查库：`、`查库:`、`#知识库` 开头提问时，必须走本地知识库检索。
- 行级 AI 复核手动触发，点击按钮只填入问题或展开助手，不自动发送。
- 风险报告可跳转到表格，定位指定 sheet、行和指标。

### 3.5 原始工作量抓取

- 从委托方工作量表中抓取数量、系数和备注，写入控制价计算表。
- 按要素1-5 + 单位匹配（字段完全匹配 + 非空要素顺序匹配）。
- 术语归并旁路规则只作用于工作量抓取，不影响主匹配和经验池预警。

### 3.6 Word 报告生成

- 报告金额与费用汇总一致，公式缓存为空时兜底计算。
- 匹配摘要不输出过长逐行日志，风险报告使用大模型润色。

### 3.7 桌面端与评委版

## 2.5 当前架构原则

### 核心原则

```text
结构化规则裁决，大模型解释辅助，人工复核兜底
```

### 混合 AI 架构

- **凡是工程造价数字裁决，优先采用可验证的结构化规则**。
- **凡是解释、追问、总结、提示和报告，交给大模型增强协同**。
- **凡是规则不足、依据不充分、字段冲突或经验偏离，进入人工复核闭环**。

### 三个关键数字的三层判断

| 层级 | 名称 | 是否自动写值 | 颜色 | 说明 |
|---|---|---|---|---:|---|
| 第一层 | 标准规则 / 固定知识库命中 | 是 | 绿色 | 可确定命中，直接填写 |
| 第二层 | 经验提示层 | 是 | 黄色 | 第一层未命中，但知识库经验数可用 |
| 第三层 | 大模型辅助层 | 否 | 不直接着色 | 只做解释、总结、报告、问答 |

### 边界约束

- 大模型不参与价格裁决，只用于风险报告、行级复核、问答、导出提示和过程解释。
- 基价和系数匹配优先采用可审计的结构化规则。
- 原始资料、标准文件、测试输入和答案表不直接改动。
- 经验池当前主要用于预警、经验提示和复核，不应偷偷改变主匹配规则。

## 2.10 这个项目不是普通填表工具，也不是泛用聊天机器人，而是工程造价专业智能体

### 10.1 为什么这个判断很重要

如果把造价智算当作"普通填表脚本"，会导致：
- 只关注"能不能自动填价"，而忽视"填价依据是什么、为什么这样填、如何复核"。
- 只关注"能不能生成 Excel"，而忽视"Excel 是否可审计、报告是否可留痕、经验是否可复用"。

如果把造价智算当作"泛用聊天机器人"，会导致：
- 误以为"AI 可以直接裁决价格、系数或审减金额"。
- 误以为"AI 可以替代专业人员的最终判断"。

### 10.2 工程造价专业智能体的特征

1. **嵌入真实业务流程**：嵌入限价编制、结算审核、估概算审核等真实工作流程。
2. **规则可审计**：三个关键数字的来源、匹配逻辑、颜色状态、逐行说明都可追溯。
3. **数据可沉淀**：知识库、经验池、规则表、标准资料、问答记录都可持续积累。
4. **过程可留痕**：填价依据、匹配过程、异常原因、经验偏离、复核意见、人工修改都有记录。
5. **AI 辅助而非替代**：大模型只做解释、问答、风险报告、行级复核，不直接裁决最终数字。

### 10.3 这一点对后续功能设计的影响

- 辅助填价：不应设计为"AI 自动填价"，应设计为"AI 提供候选，附带来源/匹配理由/相似度/风险提示，用户确认后写入"。
- 结算审核助手：不应设计为"AI 自动审减定案"，应设计为"AI 辅助发现问题/组织证据/形成审核意见草稿，由人工审核确认"。
- UI 设计：不应设计为炫技官网/营销落地页，应设计为生产级工作台/审查台/表格工具/AI 助手侧栏。
- 参赛展示：不应展示为单点填表脚本/泛用聊天机器人，应展示为规则链/数据链/智能体链协同的造价数字员工。

---

### 一句话总结

造价智算不是普通填表工具，也不是泛用聊天机器人，而是**嵌入工程造价生产链条的专业智能体**，采用"结构化规则裁决 + 大模型解释辅助 + 人工复核兜底"的可信 AI 机制，通过规则链、数据链、智能体链三链融合，形成可复制的造价数字员工样板。

后续功能设计必须守住这一定位，不得让大模型直接裁决价格、单价、系数或审减金额，不得推翻当前规则体系，不得牺牲可审计性和可留痕性。

| 输出是什么 | 治理报告（重复记录清单、疑似异常值清单、单位不一致清单、空值统计）、清洗建议（不自动删除，人工确认后处理） |

| 技术复杂度 | 低-中（重复检测用现有 A/B 匹配模式；异常值检测用统计方法如 IQR / 标准差，纯结构化计算） |
| 业务价值 | 高（经验池是预警的根基，脏数据直接导致预警不可信；且 PRD 已有 `[待开发] 经验池数据质量治理` 条目） |
| 风险边界 | 只输出治理报告和建议，不自动删除或修改经验池数据；清洗操作必须人工确认；模板文件仍然只读 |

| 是否适合近期交给 Codex | **是**。逻辑清晰、复用度高、不碰核心匹配、PRD 已有入口 |

## 3.5 结论

1. **近期最值得做的组合**是：辅助填价（MVP）+ 风险报告增强 + 知识库质量检测 + 演示/评委模式优化。这个组合复用度高、风险低、且直接强化"可信、可核验、可演示"三个当前最重要的目标。
2. **结算审核助手**价值最高但应分阶段：先用"风险报告增强"打底座，再做审核工作台。
3. **横向场景扩展**全部建议放在结算审核助手验证之后，避免知识库建设成本失控。
4. 所有功能均不改变"三个数字由结构化规则裁决"的核心边界。

# 五、辅助填价功能 PRD 建议

**生成日期**：2026-07-03  
**基于版本**：造价智算 v5.3.7  
**性质**：外部建议，供 Codex 后续消化吸收，不直接污染当前 PRD

---

## 5.1 功能定位

### 一句话定位

辅助填价是在**待复核行**上，把知识库、经验池、历史项目、同类记录、规则说明中的**候选价格或候选系数组织成结构化建议**，由**用户在"本项填价窗口"中人工确认后写入**输出 Excel 副本的辅助能力。

### 它是什么

- ✅ 候选组织器：把散落在多个数据源的候选值收拢到一个窗口
- ✅ 证据展示器：每个候选带来源、匹配理由、相似度、风险提示
- ✅ 人工确认写入器：用户点确认才写值，全程留痕

### 它不是什么

- ❌ 不是"AI 自动填价"：大模型不产生候选数字，不裁决写入哪个候选
- ❌ 不是第一层规则的替代：第一层已命中的绿色行不需要辅助填价
- ❌ 不是放宽主匹配：主匹配仍守 A/B 两档，辅助填价的"相似候选"只出现在候选列表里

### 与三层判断体系的关系

| 层级 | 现状 | 辅助填价介入点 |
|---|---|---|
| 第一层标准规则（绿） | 自动写值 | **不介入** |
| 第二层经验提示（黄） | 自动写值 | 可选介入 |
| 未命中/待复核（红） | 填"待复核" | **主要介入点** |

---

## 5.2 用户场景

### 场景 1：待复核行快速处理（核心场景）

造价员转换完 100 行，其中 8 行标红"待复核"。点击待复核行的"辅助填价"按钮，窗口列出二维库里最接近的 3 条相似记录、经验池同类均值、上个项目同要素的填值。他对比后选择一条，点"确认写入"，该行变为"人工确认"状态并留痕。

### 场景 2：多候选冲突裁决

某行匹配到 2 条知识库记录但价格冲突。辅助填价窗口把两条候选并排展示，用户判断后选择一条确认写入。

### 场景 3：第二层经验值人工改判

某行第二层填了黄色经验值 1.0，但经验池同类记录均值是 1.2。用户打开窗口选择经验池候选，确认写入。

---

## 5.3 核心流程

```text
1. 用户在结果预览中定位到待复核行（红色）或想改判的行
2. 点击该行的"辅助填价"入口
3. 弹出"本项填价窗口"
4. 窗口上方显示：本行要素1-5、单位、当前值、待填字段、匹配状态、匹配说明
5. 窗口下方列出候选项（按可信度排序）
6. 用户选择某候选（或手工输入自定义值）
7. 点击"确认写入"
8. 后端写入输出 Excel 副本（复用现有单元格写回接口）
9. 预览刷新，该单元格显示"人工确认"标识
10. 操作记录写入填价操作日志
11. （可选）用户点击"重算公式"刷新汇总和 Word 报告
```

| 入口 | 位置 | 触发条件 |
|---|---|---|
| 主入口 | 结果预览表格行级操作区（与行级 AI 按钮同区） | 该行存在待复核字段或用户主动点击 |
| 待复核清单入口 | 填价工作台"工作状态"模块的待复核数字 → 待复核清单 | 转换完成后有待复核行 |
| 风险卡片入口（进阶） | 风险卡片上的"去处理"按钮 | 风险报告增强完成后 |

## 5.6 候选来源

| 来源 | 说明 | 生成方式 | 前提 |
|---|---|---|---|
| 知识库-相似 | 二维库中 A/B 未命中但"高相似"的记录 | 复用归一化后按要素前缀/单要素差异计算相似度 | 单位一致为硬条件 |
| 经验池同类 | 经验池 A/B 匹配同类记录及均值 | 复用经验池预警找同类逻辑 | 经验池有同类样本 |
| 历史人工确认 | 过往辅助填价/人工修改中确认过的同要素组合值 | 读取填价操作日志 | 有历史确认记录 |
| 第二层经验提示 | 知识库 J-M 列经验数（对系数字段） | 复用现有第二层逻辑 | 知识库唯一匹配且经验数可解析 |
| 规则说明参考 | 规则表中相关条目（对技术费系数） | 读取规则表相近条目 | 规则表有相近技术类别 |

**重要边界**：模式 C（前缀匹配）在本功能中**只用于生成候选列表**，永不自动写值。

---

## 5.7 候选排序规则

按以下优先级排序（结构化规则排序，不用大模型排序）：

1. **来源可信度**：知识库-相似 > 第二层经验提示 > 经验池同类 > 历史人工确认 > 规则说明参考
2. **相似度**：同来源内按相似度降序
3. **样本量**：经验池候选按样本数降序
4. **新近度**：历史确认候选按时间降序

---

## 5.8 候选可信度分级

| 级别 | 标识 | 条件 | UI 表现 |
|---|---|---|---|
| 高 | ★推荐 | 单位一致 + 仅 1 个要素差异 + 该差异为近义词/包含关系；或经验池样本≥5 且离差≤10% | 绿色标识，默认排最前 |
| 中 | 可参考 | 单位一致 + 2 个要素差异内；或经验池样本 3-4 条 | 默认样式 |
| 低 | 谨慎 | 前缀匹配仅命中要素1-2；或经验池样本≤2；或候选间价格离差>20% | 灰色 + 风险提示前置 |

---

## 5.9 风险提示规则

每个候选必须生成结构化风险提示（规则生成，非大模型生成）：

| 风险类型 | 触发条件 | 提示文案示例 |
|---|---|---|
| 要素差异 | 候选与本行存在要素差异 | "要素4不一致：本行'黏性土'，候选'黏土'" |
| 样本不足 | 经验池样本 < 3 | "仅 2 条历史样本，均值代表性有限" |
| 样本离散 | 经验池样本离差 > 20% | "样本间最大离差 35%，均值可能失真" |
| 候选冲突 | 多个高可信候选价格不一致 | "存在 2 个高可信候选但价格不同，请核对要素口径" |
| 偏离经验 | 选中值偏离经验池均值超过预警阈值 | "该值高于经验池均值 23%（高风险阈值 20%）" |
| 无依据 | 自定义输入 | "自定义值无来源依据，已要求填写备注" |

---

## 5.10 人工确认写入机制

1. **写入前校验**（复用 `/api/preview/cell` 现有校验）：公式单元格、合并单元格非左上角、隐藏行、系统生成列拒绝写入。
2. **写入内容**：值写入输出 Excel 副本对应单元格；单元格底色改为"人工确认"色；写入批注（原值、候选来源、确认时间）。
3. **留痕**：写入独立的辅助填价日志（建议与 `preview-manual-edits.json` 统一 schema），记录：sheet、行号、列、原值、新值、候选来源、匹配理由、用户备注、时间。
4. **匹配说明列同步**：若开启匹配报告，该行"匹配说明"追加"人工经辅助填价确认，来源：XX"。
5. **汇总刷新**：写入只做快速写值，公式汇总与 Word 报告由用户手动点"重算公式"。

## 5.11 与右侧 AI 助手的关系

# 六、结算审核助手 PRD 建议

**生成日期**：2026-07-03  
**基于版本**：造价智算 v5.3.7  
**性质**：外部建议，供 Codex 后续消化吸收，不直接污染当前 PRD

---

## 6.1 核心判断：审核为主，还是填价为主？

### 结论

**审核为主。第一阶段不做自动裁决，不做自动审减定案。**

### 判断依据

1. **业务性质决定**：结算审核的本质是"发现问题 + 组织证据 + 形成意见"，最终审减金额必须由人签字定案。
2. **项目原则决定**：本项目核心原则是"结构化规则裁决，大模型解释辅助，人工复核兜底"。
3. **资产现状决定**：当前已有经验池预警（偏离比对）、待复核口径（异常标注）、风险报告（问题汇总）、跳转定位（问题定位）——全部是"审核发现"型能力。
4. **填价能力另有归属**：结算场景中如需"这项应该是多少钱"的参考，应复用辅助填价模块。

---

## 6.2 三种模式比较

| 维度 | 模式 A：风险预警型 | 模式 B：自动审减 | 模式 C：审核工作台（推荐） |
|---|---|---|---|
| 核心动作 | 比对结算表与依据，输出风险预警清单 | 重算"应审定价"，自动算审减额 | 模式 A + 问题组织 + 意见草稿 + 复核留痕 |
| 复用现有能力 | 高 | 中 | 高 |
| 技术复杂度 | 低-中 | 高 | 中 |
| 风险 | 低 | **高**（违反项目边界） | 低-中 |
| 业务价值 | 中 | 表面高、实际危险 | **高** |
| 与项目原则契合度 | 契合 | **冲突** | 契合 |

**推荐模式 C，并以模式 A 作为其第一阶段 MVP。**

---

## 6.3 业务定位

结算审核助手是造价智算在**结算审核场景**的审核工作台：把结算书与合同价格清单、控制价、知识库标准、经验池历史进行**结构化比对**，发现单价、工程量、计算和范围类问题，组织成**风险卡片**和**审核问题清单**，辅助审核人员生成**审核意见草稿**，最终**由人工审核确认定案**。

一句话：**它是审核员的"问题雷达 + 证据整理员 + 草稿秘书"，不是"审减计算器"。**

---

## 6.4 核心用户

| 用户 | 使用方式 | 关注点 |
|---|---|---|
| 审核人员（主用户） | 上传结算资料，逐卡片处理问题，导出意见草稿 | 别漏问题、依据可查、草稿省时 |
| 复核/管理人员 | 查看风险分布和处理进度 | 审核质量、留痕完整 |
| 送审方造价人员（间接） | 参考问题清单自查 | 问题描述清楚、依据明确 |

---

## 6.5 适用资料与输入资料清单

### 第一阶段适用范围

**长输管道勘察测量类项目的结算审核**——与现有知识库、规则表、经验池同域。

### 输入资料清单

| 资料 | 必需性 | 用途 |
|---|---|---|
| 结算书 Excel（送审结算表） | 必需 | 核查对象 |
| 原控制价 / 合同价格清单 Excel | 强烈建议 | 单价一致性比对基准 |
| 委托方确认工作量资料 | 可选 | 工程量核对参考 |
| 二维知识库 / 规则表 | 内置 | 标准参考值计算 |
| 经验池 | 内置 | 历史偏离比对 |
| 合同条款关键参数（人工录入） | 可选 | 取费口径、下浮率等 |

---

## 6.6 核查对象与风险类型

### 核查对象

1. 结算单价（vs 合同清单单价 / 控制价单价 / 知识库标准参考值）
2. 结算工程量（vs 委托确认工作量 / 控制价工程量）
3. 行级金额计算（单价 × 数量 × 系数是否算对）
4. 汇总金额（分项之和、税率计算）
5. 项目范围（结算表中出现而合同清单中没有的"合同外新增项"）
6. 系数使用（实物/技术工作费调整系数 vs 规则表口径）

### 风险类型定义（结构化规则判定）

| 风险类型 | 判定规则 | 默认等级 |
|---|---|---|
| 单价高于基准 | 结算单价 > 合同/控制价同类项单价 | 偏离≤5% 低 / >5% 高 |
| 单价偏离标准 | 结算单价 vs 知识库标准参考值偏离超阈值 | 同上（阈值可配） |
| 工程量增加 | 结算工程量 > 基准工程量 | 按偏离率分级 |
| 行级计算错误 | 程序重算行金额 ≠ 表内金额（超容差） | 高 |
| 汇总计算错误 | 程序兜底计算汇总 ≠ 表内汇总（超容差） | 高 |
| 合同外新增项 | 结算行在合同清单中无 A/B 同类记录 | 高 |
| 系数异常 | 系数与规则表口径不符或超经验池偏离阈值 | 按偏离率分级 |
| 经验偏离 | 复用经验池预警逻辑（5%/20% 阈值） | 低/高 |
| 无法比对 | 要素无法对齐、单位不一致 | 提示级 |

## 6.7 风险卡片结构

```
┌──────────────────────────────────────────────┐
│ [高风险] 单价高于合同清单                        │
│ 位置: 表4 第18行  钻探/黏性土/30m以内  单位: m   │
│ 结算单价: 156.00   基准单价: 128.00 (合同清单)   │
│ 偏离: +21.9%      涉及金额影响: 约 +8,400 元     │
│ 依据: 合同清单第37行；知识库序号214 参考值128     │
│ 建议动作: 核对该项是否存在签证或价格调整依据        │
│ [跳到结算表] [跳到基准行] [标记处理] [写入意见]    │
└──────────────────────────────────────────────┘
```

字段 schema：

```text
RiskCard {
  id, type, level(高/低/提示),
  sheet, row, elementSummary, unit,
  currentValue, baseValue, baseSource(合同/控制价/知识库/经验池),
  deviation, amountImpact(结构化计算，标注"影响估算"),
  evidenceRefs[](可跳转定位),
  suggestion(规则模板文案，大模型仅可润色),
  reviewStatus(未处理/已确认问题/已排除/挂起), reviewNote
}
```

**边界**：`amountImpact` 是算术展示，界面必须标注"影响估算，非审减定案"。

## 6.8 审核问题清单结构

| 字段 | 说明 |
|---|---|
| 问题编号 | 自动生成（按类型分组编号） |
| 问题类型 | 同风险类型 |
| 位置与项目特征 | sheet/行/要素摘要/单位 |
| 问题描述 | 规则模板生成 + 人工可改 |
| 核对依据 | 证据引用（基准来源 + 行号 + 标准出处） |
| 涉及金额影响（估算） | 结构化计算，标注估算 |
| 送审值 / 核对参考值 | 只列事实，不写"审定值" |
| 处理建议 | 人工填写或从模板选择 |
| 状态 | 待沟通 / 已确认 / 已排除 |

## 6.9 审核意见草稿结构

```text
一、审核概况：项目名称、送审金额、核对范围、资料清单
二、核对方法说明：比对基准、匹配口径、阈值设置
三、发现的主要问题：按类型分组，逐条列出
四、建议：逐条处理建议 + "以上意见为初步核对意见，最终审定结论以人工审核为准"
页眉/页脚：显著标注【审核意见草稿-待人工审定】
```

**硬性边界**：
- 草稿全文不得出现"审定金额为 X""审减金额为 X"的定案表述
- 大模型只润色问题描述的语句通顺度，金额、行号、依据引用全部由结构化数据填充

## 6.10 与其他模块的复用关系与边界

### 与经验池预警模块

- **复用**：找同类逻辑（A→B→D）、偏离率分级、阈值配置、"跳到表格"定位。
- **边界**：审核助手的比对基准扩展为"合同清单/控制价"。

### 与辅助填价模块

- **边界**：审核助手回答"这项**有没有问题**"；辅助填价回答"这项**该填多少的候选**"。

### 与右侧 AI 助手

- AI 可以：解释某风险卡片的判定规则和依据、总结审核进度、润色问题描述。
- AI 不可以：判定风险等级、计算审减金额、决定问题成立与否。

**生成日期**：2026-07-03  
**基于版本**：造价智算 v5.3.7（大尾巴主题 / Navattic 极简 SaaS 基线）  
**性质**：外部建议，供 Codex 后续消化吸收，不直接污染当前 PRD

---

## 9.1 UI 总体诊断

### 总体结论

**当前 UI 基线是健康的，不需要重做，只需要"结构性补强"。**

v5.3.x 的 Navattic 极简收口成效明显：白底、1px 分割线、扁平面板、克制选中态、三栏工作台均已落地，整体观感已达到"企业级 SaaS 工作台"水准。

当前的短板不在视觉风格，而在三处**结构性缺口**：

1. **流程感缺口**：模块之间是"页面切换"关系，不是"任务推进"关系。
2. **处理闭环缺口**：系统会"发现问题"，但界面没有给"处理问题"留位置。
3. **右侧 AI 信息形态缺口**：AI 侧栏承载了大量"过程叙述文字"，纯文本流密度过高。

### 诊断计分卡

| 审查项 | 现状评价 | 结论 |
|---|---|---|
| 首页信息密度是否过高 | 填价工作台适中偏低；经验池预警页和右侧 AI 流偏高 | 局部过高 |
| 模块层级是否清楚 | 一级清楚，二级待强化 | 待强化 |
| 各模块主次关系 | 主次对，衔接弱 | 需要"下一步"引导 |
| 右侧 AI 是否过重或过弱 | 内容形态过重、价值感偏弱 | 需要消息卡片化 |
| 是否需要主流程进度条 | 旧进度条已删除是对的，但轻量指示确有缺口 | 需要轻量形态 |
| 是否需要本项填价窗口 | 当前无候选组织交互 | **需要** |
| 是否需要风险卡片抽屉 | 预警明细是大块红底文字卡 | **需要** |
| 表格预览是否需要重构 | 不需要重构，需要工具条升级+列头优化 | 优化非重构 |
| 是否适合演示/评委 | 业务人员可用；评委缺"一键样例+讲解引导" | 需演示模式 |
| 窄屏分辨率是否拥挤 | 1366×768 下中间区局促 | 有风险 |

## 9.2 当前界面主要问题（按优先级）

| # | 问题 | 影响 |
|---|---|---|
| P1 | 右侧 AI 流"过程叙述"密度过高：连续 5-8 条长文本气泡 | 用户找不到重点；评委看不出 AI 价值点 |
| P2 | 经验池预警明细是大面积红/橙底色块+密排小字，不可操作 | 风险信息可读性差；"发现→处理"断链 |
| P3 | 缺少全局任务进度指示 | 新用户和评委的流程感弱 |
| P4 | 结果预览表格列头长文本 + 预警细节列截断 | 宽表扫读效率低 |
| P5 | 待复核/风险行缺少"处理动作" | 闭环缺口 |
| P6 | 填价工作台三处同源数字展示轻微冗余 | 可接受但可精简 |
| P7 | 窄屏（1366×768）预判：中间不足 800px | 演示用普通笔记本时观感下降 |

左侧"极窄图标栏 + 当前模块列表 + 底部状态仪表盘"、中间单模块工作区、右侧可折叠智算侧栏——**这套三栏骨架不动**。

Word 报告

### 新增两个全局层

| **风险卡片抽屉** | 从右侧滑出的全局抽屉 | 结构化风险卡片列表（预警+待复核+未来审核风险），筛选、跳转、处理入口 |

## 9.4 首页（填价工作台）布局建议

现状布局保持，建议做 4 个增量：

1. **顶部加任务上下文条**：未上传时显示"未开始 · 请上传标准 Excel"；转换后显示"【文件名】· 101 行 · 已转换 · 预警未运行"。
2. **工作状态区加"下一步建议"动作位**：
   - 已转换且有待复核 → `处理 3 条待复核 →`
   - 已转换未预警 → `运行经验池预警 →`
   - 已预警 → `查看风险卡片(5) →` / `生成 Word 报告 →`
3. **精简冗余数字**（P6）：工作状态内小环形图改为纯色条+数字（低优先级）。
4. **欢迎空态强化评委自解释**：未上传时加一行产品定位副标 + `加载演示样例` 按钮。

## 9.6 右侧 AI 助手优化建议（解决 P1）

四条建议：

1. **过程消息卡片化+可折叠**：多段过程叙述合并为一条可展开的过程卡，默认只显示最终态摘要。聊天流长度立即下降 60% 以上。
2. **风险摘要消息结构化**：大段文字改为迷你风险卡（等级色点 + 一行摘要 + 两个动作），与风险卡片抽屉数据同源。
3. **区分"叙述"与"回答"两种气泡权重**：系统过程通知用更淡的样式；只有 AI 回答用标准气泡+头像。
4. **快捷指令随当前模块动态排序**。

**边界**：不给 AI 增加任何写值/确认按钮。

## 9.7 三个新界面的 UI PRD

### 7.1 本项填价窗口

- **形态**：模态 Dialog，宽 720-840px，高 ≤ 80vh；浮层允许阴影；内部禁卡片套娃。
- **结构**：三段式（上下文区只读 → 候选列表可滚动 → 底部确认区固定）。
- **候选行视觉**：单选 radio + 候选值 + 来源标签 + 可信度标识（★推荐用主题绿；谨慎用琥珀）。
- **交互**：未选中时"确认写入"禁用；自定义输入时备注必填；确认成功后窗口关闭，目标单元格闪烁。

### 7.2 结算审核助手（审核工作台模式）

- **入口**：左侧导航新增"结算审核"模块。
- **页面结构**：任务上下文条 + 上传/设置区 + 风险总览条 + 风险卡片列表 + 底部动作条。
- **风格约束**：卡片列表区扁平无阴影；等级只用色点+文字标签，禁止整卡红底铺色。

### 7.3 风险卡片（全局组件 + 抽屉）

- **卡片本体（两种密度）**：
  - 列表态：`[色点] 风险类型标题 位置摘要 数字对比 [跳到表格] [详情]`，白底 1px 边框，左侧 3px 等级色条。
  - 迷你态（AI 聊天流内）：一行摘要 + 两个文字动作。
- **抽屉**：右侧滑出宽 400-480px，顶部筛选，中部卡片流，底部"导出清单"。
- **等级色**：高风险=红、低风险=琥珀黄、提示/无法比对=中性灰蓝。

## 9.8 表格预览优化建议（P4，优化不重构）

1. **列头降噪**：去掉与数据重复的后缀语义；两行长列头改一行+悬浮完整名。
2. **长文本列策略**：截断列增加"点击弹出只读详情浮层"。
3. **状态列 chip 统一**：预警参数列 chip 与风险卡片等级色点同源。
4. **工具条升级**：左侧 Sheet chips，右侧 搜索 · 状态筛选 · 列设置 · 重算公式 · 导出。**新增"状态筛选"是重点**——一键只看待复核行/风险行。
5. **人工修改状态反馈**：有未重算修改时，"重算公式"按钮加小圆点+文案。
6. **行级操作区预留**：固定 AI 列扩展为"行操作"列（AI 解释 + 辅助填价 + 标记复核）。

---

## 9.9 演示模式 / 评委模式 UI 建议

1. **入口**：欢迎空态放 `加载演示样例` 按钮；或右上角"页面设置"内放"演示模式"开关。
2. **一键样例**：点击后自动加载预置 100 行样例并完成转换。
3. **步骤引导**：演示模式下任务上下文条变为 5 步 chip：`① 上传 → ② 转换 → ③ 预警 → ④ 问答 → ⑤ 输出`。
4. **讲解点高亮**：绿/黄/红三色行、经验池偏离卡、依据追溯各有一次性脉冲高亮。
5. **脱敏提示**：演示模式页脚固定小字"演示数据，非真实价格"。
6. **克制约束**：不引入新视觉语言，不加动效轰炸。

---

## 9.10 视觉风格建议

**总原则：不换风格，守住现有基线。**

1. 延续 Navattic 极简 SaaS：白底、1px 边框、无常驻阴影、克制选中态、深蓝主按钮、Inter+等宽数字——**全部保持**。
2. **明确禁止**：不做国企数字大屏、不用霓虹/泛光/强蓝光/粒子/扫光动效、不做深色科技风主界面。
3. 状态色纪律强化：绿=第一层、黄/琥珀=第二层与低风险、红=未命中与高风险、蓝=知识库调用与人工修改；**不允许整卡/整行铺红**。
4. 密度基调：表格区高密度，说明区中密度，AI 区低密度。

## 9.12 给 Codex 的 UI 实现关键路径

1. 新组件一律走 `daweiba-*` 命名空间
2. 顺序：RiskCard 列表态组件 → 任务上下文条 → 表格工具条状态筛选 → 抽屉 → 演示引导层 → FillAssistDialog → 结算审核页
3. 每步只跑 `npm run frontend:build` 验证
4. 状态色、间距、字号从现有 CSS 变量取值
5. 窄屏策略：`≤1440px` AI 默认折叠、`≤1280px` 一级栏收为图标态

## 9.13 UI 验收标准

1. **零逻辑破坏**：build 通过
2. **AI 流降噪**：首屏消息条数 ≤ 4 条
3. **风险卡片**：经验池预警页以卡片列表呈现，无整卡红底
4. **任务上下文条**：三种状态文案正确
5. **表格**：状态筛选可用，重算按钮有标记
6. **演示模式**：加载样例到满屏结果 ≤ 15 秒
7. **窄屏**：1366×768 下三栏不溢出
8. **风格纪律**：新增界面无卡片套娃、无常驻阴影

## 10.3 如何判断哪些建议适合吸收

### 适合吸收的信号

1. **用户明确要求**
2. **PRD 已有待开发条目**：如"经验池治理"
3. **当前版本计划已提及**：如"演示模式"
4. **高价值低复杂度且用户认可**：如"知识库质量检测"

### 不适合吸收的信号

1. 用户未要求且不在版本计划内
2. 复杂度高且业务验证不足
3. 与项目核心原则冲突
4. 需要大量新资产建设

- **不要把 Claude 建议原文复制到正式 PRD**

## 10.11 如何保证不破坏当前主流程

### 开发前

1. 读现有 PRD，确认功能边界
2. 读现有代码，确认复用点的真实函数边界
3. 设计复用方案：新业务逻辑放新文件

### 开发中

1. 只读不改核心模块
2. 复用归一化与匹配模式
3. 复用写回与留痕

### 开发后

1. 全量回归测试：`python -m pytest backend/tests -v`
2. 答案表一致性：100 行样例输出与答案表逐行一致
3. 主流程验收
4. 颜色状态验收
5. 经验池预警验收
6. 评委版与 Tauri 壳验收

## 10.12 最后提醒

1. **Claude 建议不是命令**：Codex 应自主判断哪些建议值得纳入正式 PRD。
2. **不要把所有建议都做**：优先做高价值低复杂度的功能。
3. **不要跳过用户确认**：每个功能立项前必须确认需求、范围、优先级。
4. **不要污染当前 PRD**：Claude 建议保留在 `【Claude】/`，正式 PRD 在 `00-PRD/01-模块PRD/`。
5. **守住项目核心原则**：结构化规则裁决，大模型解释辅助，人工复核兜底。
6. **与 Claude 建议冲突时以现状为准**。
7. **记录差异与待确认项**。
