# 功能点和开发成本怎样建立联系

功能点方法把软件需求转化为可比较的功能规模，再结合生产率、人员成本和项目条件进行测算。阅读相关资料时，先确认功能点类型、计数规则、边界和质量要求，再看工作量和单价的来源。功能点数量本身不能直接等同于项目金额。

计数前要划清系统边界，识别输入、输出、查询、内部数据和外部接口等功能对象。需求文档不完整时，计数结果会随假设变化。对于通用平台、配置项和定制开发，还要说明哪些功能属于复用，哪些需要重新开发。

从功能规模到开发成本，通常还要经过生产率、团队构成、技术难度、质量要求、交付周期和管理投入等环节。不同项目的生产率来源可能不同，不能把某个软件行业基准数据直接当成当前团队的承诺。

复核记录应保留边界说明、计数表、假设、数据来源和调整理由。若采用区间估算，应同时说明区间产生的原因。需求变更、接口增加或质量标准提高后，相关功能点和工作量也要重新检查。

功能点结果还应与实际交付物对应。需求说明、原型、接口清单和验收范围可以帮助确认计数是否遗漏。若同一功能被平台复用或多次部署，要记录复用规则和部署工作，不能简单重复计入规模。

本文用于说明功能点测算的阅读路径。正式估算应按项目需求、当前依据和专业复核完成。
