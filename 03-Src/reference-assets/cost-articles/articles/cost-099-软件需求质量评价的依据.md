# 软件需求质量评价的依据

2025行业基准资料的业务需求质量评价案例指出，立项需求较简单、后续变更及验收资料显示需求模糊，会影响交付功能对业务需要的满足程度。该内容是案例分析，不是所有项目通用的固定扣分公式。

实际核对需求质量时，应将早期需求、后续变更、交付功能与验收记录对应起来，区分需求新增、原需求澄清与实现缺口。单凭预算偏差或最终工作量较大，不能确定需求质量有问题；也不能把开发方交付不足一概归为用户需求变更。

## 核对要点

- 保存需求版本、边界和可验收的功能描述。
- 对变更记录注明原因、批准时间及对规模的影响。
- 将交付功能与原需求逐项比对，保留验收证据。

案例适合帮助形成复核问题，不能据此直接调整合同价或给项目套用未经依据的质量系数。
