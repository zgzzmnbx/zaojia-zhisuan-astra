# 软件生产率和功能点单价怎样使用

软件生产率通常表示单位时间完成的功能规模，功能点单价表示完成单位功能规模所对应的费用。阅读行业基准数据时，先确认指标定义、统计单位、项目类型和质量条件，再判断它能否用于当前项目。两个指标不能脱离数据来源单独使用。

生产率会受到技术平台、团队经验、复用程度、需求稳定性、质量要求和交付方式影响。功能点单价还会受到地区、人员成本、管理方式和合同范围影响。一个项目的功能点数量乘以一个行业数值，只能得到初步参考，不能直接形成正式预算。

测算时应把功能边界、复用功能、外部接口、开发与实施范围写清楚。若生产率和单价来自不同样本或不同时间，应说明口径差异。项目包含硬件、许可、培训或运维时，也要把这些内容从开发指标中分开。

复核记录应保存指标版本、单位、样本条件、项目假设和调整理由。可以使用区间或多情景结果，但每种情景都要说明条件。后续拿到实际工期和成本后，应将实测结果与基准分开记录，不能回填成原始依据。

还要确认功能点计数和生产率计算使用同一边界。若一项指标按开发阶段统计，另一项包含实施和管理，换算前必须拆出差异。只有在定义、阶段和质量要求能够对应时，比较结果才有参考意义。

文章只说明指标的使用边界。项目预算仍须依据真实需求、有效资料和人工复核确定。
