# 正式运行与发布保护

唯一比赛入口是项目根目录的 `启动造价智算3-Astra.bat`。`npm start` 也调用同一启动器。不要直接启动回滚副本或历史工作树。

| 位置 | 用途 | 操作边界 |
| --- | --- | --- |
| 项目根目录及 `03-Src/`、`tools/` | 开发源码 | 保留原目录结构，定点修改；不得覆盖未提交工作 |
| `runtime/astra-service/` | 正式运行副本，含独立 .venv、构建、配置、业务数据 | 由启动器选中；禁止当作临时文件清理 |
| `runtime/astra-service/03-Src/engine/Codex-Temp/runtime/` | 正式数据库、上传、Excel、Word、复核状态 | 即使包含 Codex-Temp 字样也属于业务数据，禁止清理 |
| `runtime/astra-service/runtime/dependency-guard/` | 依赖恢复副本、清单、检查与恢复日志 | 独立于 .venv；不得自动重建或删除现有基线 |
| `runtime/backups/20261029-v0.11.27/`、`20261029-v0.11.28/` | 本次完整回滚副本 | 只作回滚依据；禁止直接启动，避免双平台重复接收 |
| `Codex-Temp/feishu-diagnosis-20261029/` | 本轮排查脚本、日志、验收记录 | 保留故障证据与迁移清单 |

`runtime/` 已由 .gitignore 排除，防止业务数据和个人配置进入源码提交。Git 忽略不代表可删除。

## 启动验收

- bat 冷启动后核对正式健康接口的 workspace、版本和来源哈希；再次启动复用原进程。启动互斥防止连续双击创建第二个宿主。
- 启动器保留端口归属检查，不抢占其他服务；通过 .NET 计算来源哈希，避免依赖 PowerShell 模块自动加载。
- 启动器和宿主均拒绝从 `.codex/worktrees` 启动正式服务。迁移期间使用 `.migration-in-progress` 阻止提前启动。
- 宿主启动前检查全量依赖文件是否存在及变化，每60秒检查、每15分钟完整哈希检查；仅从按包 RECORD 校验的本地副本补回缺失文件。已有内容改变或恢复副本损坏只报警，不覆盖现有文件。
- 检查状态及日志位于 dependency-guard 的 `status.json` 和 `events.jsonl`；该日志记录发现和恢复时间，不伪称记录了删除者身份。

## 发布和清理

1. 先读取启动配置，核实实际运行目录、进程、版本、待处理队列和未提交工作。
2. 修改源码后完成测试与构建；按本轮明确文件清单备份、同步源码和构建，保持来源哈希一致。
3. 保留正式配置、数据库、上传、历史成果和已有个人偏好。不得通过整目录覆盖或镜像删除发布。
4. 宿主与双平台接收器切换前验证旧实例已停止；迁移数据库须核验全部表和行，成果文件核验哈希。
5. 清理仅限本轮明确产生的临时文件。禁止对项目根目录、`.venv`、`runtime/`、业务数据或备份目录执行递归删除、`git clean -fdx`、reset/clean/强制覆盖。
6. 未来需要升级依赖时，先备份旧基线，按依赖锁定版本校验后显式建立新基线，不自动接受损坏环境。

比赛现场只使用根目录 bat；不要切换到开发服务器或历史副本，不清理目录、不升级依赖。构建和本机验收不能替代现场网络与接收端验收。
