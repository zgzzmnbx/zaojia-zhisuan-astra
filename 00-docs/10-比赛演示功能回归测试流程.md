# 比赛演示功能回归测试流程

版本：2.0.0（流程） / 1.0.0（测试工具）｜更新：2026-11-10

本流程以大尾巴提供的《造价智算_总决赛1.0_录音原话与时间轴_41段.txt》为功能依据，覆盖录音第09—36段的系统操作，并补充更新后容易出现的异常、状态恢复与模块隔离检查。录音全长9分54.6秒，系统部分约7分19秒；比赛目标是系统演示7分钟，PPT另计。

## 一、以后更新完怎样测试

1. 确认要验收的版本已经按项目发布流程部署。测试只读取正式目录 `runtime/astra-service`，不会把工作区尚未发布的改动当作正式版本。
2. 在项目根目录双击 **运行演示回归测试.bat**。也可以从 PowerShell 运行 `runtime/astra-service/.venv/Scripts/python.exe tools/demo-regression/run.py --open`。
3. 等待浏览器自动完成操作，报告自动打开；检查报告顶部的程序版本、用例结论与执行门禁。
4. 自动项全通过时，表示这台电脑上、隔离环境中的录音功能主链已通过。报告仍保留六项实际接收端/现场验收，按随报告附带的 `manual-checklist.md` 完成并录入证据。
5. 有失败先查看该项截图、错误和日志，确定是程序、环境还是定位器变化；修复后跑新一轮，保留旧证据。不能跳过失败后宣布完整通过。

入口是独立测试工具，没有增加正式系统菜单或更改业务逻辑。正式5189服务可以继续使用；自动测试在5197/18770运行，端口冲突就停止，不结束其他服务。正式资料及历史标准答案保持只读，副本内才转换、保存候选、改因子和生成报告。

## 三、为什么要保留六项实际验收

脚本能检查发送前的选择与确认、回执接口的隔离规则，但“API成功”不能证明手机端实收；HTTP到达控制台也不能证明Watch扬声器发声。浏览器预览成功不能证明Word最终分页和Excel在Office中的重算结果。比赛的手机热点和人的操作节奏更不能用后台脚本耗时替代。

六项人工验收是本流程的组成部分，未做就显示“未全部验收”，不会自动补绿。详细操作与证据要求见 [人工验收清单](../tools/demo-regression/manual-checklist.md)。外部平台发送由执行人核对明确的本人账号后主动操作，自动脚本不发送任何真实消息。

数字化采用指定历史演示项目的数据库只读备份，实际验证段落/功能点联动、52FP规模、因子1和1.21的两次计算、工作量和费用及版本一致性。本轮不调用外部模型，不能据此宣称任意新文档的模型识别质量已通过。勘察测量的单行解释、报告和知识固定题按当前演示预设验收；普通题的实时模型能力、WeKnora远程服务也须另行联调。

## 四、固定口径和独立答案

- V3.1：100项清单、99项填入，表2 H5=50000、H6=3203。
- 两项风险：表2第5行基价50000对4274；表3实物工作费系数1.3对1.15；一高一低。
- 原答案的H5为500000。只在每轮独立参考副本改为50000，同时独立计算S5同一风险行的数字，不改原答案、不放宽其他单元格比较。报告与Excel可采用不同显示精度，数值依据相同。
- Excel检查1254个目标单元格，并强制公式、填色、状态、隐藏行、全表值均零差异；不再沿用“隐藏行和全表差异只输出、不影响通过”的旧门禁。
- 数字化：2ILF×7 + 1EIF×5 + 6EI×4 + 1EO×5 + 1EQ×4 =52FP。阶段因子1：388.544人时、94641.37元；1.21：470.13824人时、114516.06元。依据为这份已人工确认的演示清单，不宣称教材标准答案。

## 五、怎样读报告

退出码0：全部必需自动项、流程门禁和人工项通过；退出码1：至少一项失败；退出码2：尚有未执行/未验收项目。首次纯自动运行即使24项全部通过，也通常返回2，因为六项人工实收不能自动判定。

报告目录：`Codex-Temp/demo-regression/<时间-随机标识>/`。`latest.json` 指向最新轮次。保留HTML/Markdown/JSON、版本哈希、真实Excel/Word、逐格差异、浏览器截图和trace、数字化计算响应、接口回归日志。失败明细用于定位，不能把测试定位器超时直接写成程序业务缺陷。

程序更新后必须新建测试轮次。人工证据记录程序会核验正式源码和数字化发布版本是否仍与本轮一致；变化后拒绝给旧报告补验收。完整技术说明见 [工具说明](../tools/demo-regression/README.md)。

## 六、与之前 Terra 测试的关系

已阅读 `【测试-Terra】测试用例` 聊天（01a183ce-fc52-7942-a34b-a486dfff81e5）。其2026-10-29记录验证了当时版本的V3.1核心链、100/99、两项风险、1254目标单元格和报告预览。它不是当前全部录音功能的验收：飞书未发送，WeAct没有完成实际复核回执，Office/WPS未正式验收；知识图谱、候选保存、数字化完整计算及刷新/视图保持也不能用那次结果补齐。

旧 `tools/verify_astra_v31.py` 保留供专项排查；其固定输出目录和旧输入口径不能替代新的一键流程。本流程以实际部署副本、当前用户样例、完整浏览器操作和独立验收状态为主记录。

## 七、7分钟目标与优化建议

具体420秒分配见人工清单。录音中的系统部分约超目标19秒，建议主要压缩说明重复，而非省掉重要的风险依据和回执。双平台复核、知识问答、报告预览是等待风险较高的环节：排练时分别记录首次加载及重复操作耗时，提前确认接收端在线和本地同案例录像可播放。

后续优先优化测试入口易用性和可观察性：固定演示样例与答案清单、失败时一键查看证据、区分预设与实时模型、明确公式重算状态。新功能上线后先增加对应录音用例，再判断是否满足演示稳定性。任何优化只在已授权的副本中实施，不能为了测试绿灯修改正式业务结果。
