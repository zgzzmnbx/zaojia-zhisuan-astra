# v0.11.20 · 欢迎页沙盘预加载与首次聚焦优化

日期：2026-10-28。状态：用户授权后已发布至本地主线及正式 5189，运行 v0.11.20。

## 改动

- 工作空间恢复完成后，欢迎页等待 500ms 并利用现有空闲调度挂载正式沙盘。完整准备 V11 主模型、两份几何、贴图、信息碑与集团 Logo；进入时复用同一画布、WebGL 上下文及模型 owner。
- `baked-mode.mjs` 分段预热普通画面、四射灯/阴影/选择性 Bloom、临时装配材质，使用当前安装 Three.js 的 `compileAsync`。有限准备使用 `scene-preparation.mjs`，在后台等待恢复，销毁时取消后续阶段。
- 临时装配提前计算，但不领取入口资格，也不推进时间；实际可见首帧才开始播放。遵循减少动效，返回欢迎页保留场景并暂停，重新进入不重播。
- 直接进入及跳过欢迎页共用上述加载流程；工作空间尚未恢复时不创建临时会话的沙盘，避免随后更换真实会话而重复加载。
- 模型、材质参数、冻结资产、业务任务和个人保存方案未改写。新版本更新 package/lock、README、PRD、AGENTS、CHANGELOG；日志只保留最近五版，v0.11.15 移入历史归档。设计系统仍为 1.1.38，宿主仍为 0.9.16。

## 浏览器验收

本轮使用独立 Chromium、1754×956 CSS 视口、DPR 1，关闭 GPU 着色器磁盘缓存。候选静态文件仅在独立测试浏览器中以同源响应拦截提供，GET API 读取真实工作空间，其余 API 请求禁止写入。测试没有发送通知或运行计算。

| 项目 | 证据及结果 |
| --- | --- |
| 欢迎页准备 | `prepared=true`、`frames=0`、`pending=false`，装配 elapsed=0；停留后仍为 0 |
| 场景复用 | 进入前后画布对象相同；主模型、两份 `.buffer`、信息碑、集团 Logo 各请求一次；日夜切换不增加模型请求 |
| 首次放大 | 原版实测最长帧间隔约 2669ms、主线程长任务 2673ms；候选普通模式约 33ms、减少动效约 50ms，均无长任务记录 |
| 其余六栋建筑 | 逐一聚焦，最长帧间隔约 33–50ms；智能填价记录到一个约 50ms 任务 |
| 进入时残余开销 | 欢迎页准备完成后，候选进入样本最长帧间隔约 150–217ms；普通模式记录一个约 214ms 任务。不能宣称完全零停顿 |
| 立即进入 | 延迟主模型后直接点击进入；仅一次模型请求，准备完成后从首次可见帧开始装配 |
| 失败重试 | 主模型首次返回 503，收起对话后点击原有“重试画面”，第二次请求恢复；新 owner 成功准备 |
| 跳过欢迎页 | 直接进入后返回欢迎页，保持同一画布；再次进入不重播，主模型仍仅请求一次 |
| 真正后台 | 独立原生 Chromium + CDP `noDefaults:true`，核实 `document.hidden=true`；后台资源到达后仍不执行准备阶段，动画帧数/elapsed 冻结，回前台恢复 |
| 日夜画面 | 减少动效、同参数同机位的白天全景、聚焦、夜间画布分别与原版 SHA256 完全一致 |

以上为本机样本，不能推广为所有机器的固定耗时。立即进入仍需等待未完成的准备；欢迎页会提前占用这一套沙盘的 CPU/GPU 资源，后台完成后不维持沙盘 RAF。
