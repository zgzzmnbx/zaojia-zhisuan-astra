# 普通知识问答模型接通 · UI v0.9.38

## 原因与修复

用户反馈除前四道预设题之外，回答都是固定的“本地检索原文摘录”。现场核查发现活动 Astra 的 DeepSeek / 硅基流动均未启用、没有密钥引用，模型名误留为 `ui-draft-not-saved`；因此宿主有意走 `evidence_only`，普通问答此前没有完成模型验收。

用户明确指定 Obsidian 笔记的“DeepSeek官方”小节，并授权重启当前 Astra。

- 活动配置只保存授权笔记路径及 `#DeepSeek官方` 小节引用；读取限定到该标题及下一同级 / 上级标题，只有唯一密钥才通过。不复制密钥、不显示密钥、不修改原笔记。保存其他连接设置时保留该引用格式。
- DeepSeek 官方 `/models` 实际返回 200，可用 `deepseek-flash` / `deepseek-v4-pro`；本轮使用 `deepseek-flash`，替换测试占位名。配置仅写现有活动 worktree 的忽略文件，未移动运行库。
- 独立真实回归发现默认思考模式可能耗尽旧 1800 token 上限而没有回答正文。知识问答在 Astra 适配层显式关闭思考模式，使用当前请求的输出上限快照；不修改冻结引擎、其他 AI 场景或模型偏好。接口依据：[DeepSeek 官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。
- 空正文、达到输出上限及网络错误明确失败，不将摘录冒充已生成答案。未配置时明确“尚未生成答案”并提供“配置问答模型”按钮。
- 引用中的 HTML 表格及被截断的标签转成可读文本，保留清单编码、数值、字段与原来源。新回答及历史卡片均适用；不改原知识资料。
