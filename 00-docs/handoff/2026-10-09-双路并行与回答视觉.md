# 双路并行与回答视觉

日期：2026-10-09。UI v0.9.48，设计规范 1.0.24。

前端原本通过 Promise.allSettled 同时发起原知识问答和 WeKnora，请求各自完成时发布自己的回答。排查发现冻结引擎的 async 知识处理器内部执行同步检索与模型网络 I/O，会阻塞宿主事件循环，使另一条流等待。本轮仅在 Astra 的知识问答入口通过 asyncio.to_thread 隔离旧处理器，在线程内运行其协程及模型上下文；冻结引擎未修改，原机械检索 / 模型配置 / 错误语义保留。WeKnora 流继续使用独立异步客户端及原中间件旁路。预设问题仍按原规则只走本地预设，不重复调用模型。

停止 / 切换会话后前端继续丢弃晚到结果。线程中的同步模型 HTTP 请求不能被 AbortController 强制终止，仍按原网络超时收尾；此次修复保证主事件循环和取消入口可响应，不声称取消会立即中断上游计算。

回答卡片标题旁增加小型浅主题色 Phosphor Duotone 图标作为装饰：模型 brain、WeKnora graph、本地检索 book-open-text、预设 list-checks，使用 aria-hidden 避免重复朗读。表格使用主题浅色表头、横向细分隔、圆角、轻斑马纹和悬停行强调，数字采用 tabular-nums。保持原数值 / 表头 / 来源、横向滚动与折叠出处。

验证：

- 两工作区各 182 项前端测试、6 项后端模型测试和生产构建通过；保留既有大 chunk 提示。
- 两项新增受控回归覆盖同步模型和同步检索等待，事件循环中的独立回调可在等待期间执行；模型请求上下文在线程内可用且不泄露到调用上下文。测试使用替身，不发起付费模型请求。
- 当前 /api/health 的 server.py 已加载哈希与活动源码一致，UI / 构建版本 0.9.48、PID 11124；标准启动器确认当前 Astra 服务健康。检测期间旧 PID 已退出，未对其他服务执行停止操作。
- 实际浏览器 1742×956，原系数回答表格、四类装饰图标、项目信息侧栏和亮暗主题通过；多行表格偶数行具有主题浅色背景，数字样式为 tabular-nums，浏览器错误日志为空。
- 本轮没有额外发起真实双模型问答，未测量外部供应商响应耗时；并行修复由受控回归及实际加载源码核验支持。
