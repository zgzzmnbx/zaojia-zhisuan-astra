# v0.26.0 办公室人物直拖与自然动作

日期：2026-11-15。Astra 前端 v0.26.0 / host v0.14.3；办公室资源基线保持上游 v0.7.0、模型 v0.6.7。

## 使用与边界

直接抓取 3D 小人拖到右上角当前成果卡，卡片高亮后松开。姓名标签与普通选人按钮保留。小人拖动时跟随鼠标，完成、落空或取消后回到原工位；不修改真实工位数据。

所有目录人员都可分配。石萌仍经原桥接校验进入左侧复核卡，用户确认后按原流程发送。其他人员仅进入沙盘的当前项目演示分配，任务、候选及成果卡明确标注“演示”，不会产生宿主选人消息、收件人变更或平台请求。项目上下文改变即清除演示分配，布局切换保留；未新增跨刷新持久化。

点击人物打开浮层，可查看当前审核项目、工种与擅长审核。现有目录仅有人员姓名与账号，工种/专长显示“待补充”；没有捏造真实职工信息。已有示例项目继续标注演示。

人物使用原创简化几何，逐工位根据椅位与显示器方向就座，双手按实际键盘位置定位。打字、看屏、呼吸仅改变视觉姿态，不推进业务状态。画面设置中的“人物动作”可关闭；系统减少动效、页面隐藏及离屏时暂停，不追赶后台时间。

## 变更范围

- `public/office-twin/viewer/host-people.js`：朝向、坐姿装配、人物浮层、动作时钟。

- `person-pointer.js`：实体命中、指针捕获、拖动目标高亮、取消与上下文/版本保护。
- `person-assignment.js`、`host-client.js`：石萌原选人路由和其他人员本地演示分配分离。
- `viewer.js`、`astra-review.css`：生命周期、原生 Popover 和 Astra 样式；SOURCE 清单更新。
- 原 `OfficeReview.tsx`、`office-review.ts`、`review-flow.ts`、发送接口与后端业务源码未修改。没有修改独立办公室项目或替换 GLB。
