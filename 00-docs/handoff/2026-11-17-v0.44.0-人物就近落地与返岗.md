# v0.44.0 办公室人物就近落地、返岗与复位

日期：2026-11-17。正式 UI 0.44.0，宿主 0.16.1，原进程继续运行。

## 行为

- 松手时在当前楼层寻找最近空闲落点；会议室内避开长桌、椅子和其他人员，楼外、核心井区和家具上自动吸附到可连通通道。
- 会议室外落地停留约2秒，然后沿静态通路返回分配工位，转身、坐下并继续打字/看屏幕。空闲人员也可沿房间和走廊活动。暂停人物动作/系统减少动效时，回工位直接完成。
- 从多人复核区拖出，或在区内使用“回到工位”，取消该人的本次候选选择；不撤销已发送的复核任务。
- 工具栏“所有人复位”恢复全部人员的工位与姿态，清理会议室内对应候选；不清除通过其他复核入口选中的工位人员。
- 临时位置不写入工位配置。动作暂停、拖动取消、隐藏停算、上下文校验与宿主选人权限保持。

## 实现与验证

连续楼板是 H1_F09_Office 的并列节点，旧落脚检测遗漏它，导致走廊不通。现在同时采样连续楼板、房间地面与实际家具，使用空间桶加速碰撞检查，缓存0.2m网格并保留最大连通区。绕开核心区、外墙和家具；仅返岗最后一段允许进入本人椅子范围。路径在动作起点/受阻重试时规划，不增加持续绘制对象。

- npm test：527项通过；其中办公室56项，新增转向/避障/暂停/坐回原位、堵路重试与最近落点检查。
- npm run build：从正式0.43.0来源构建候选，通过。
- 实际GLB：15608个连通导航采样点（数据点，不是绘制对象）；67个可分配工位从会议室返岗模拟全部完成；428个会议室落点均能找到离场路线。离线网格构建约0.37秒，最长模拟返岗约67秒，均非性能承诺。
- 内置浏览器隔离预览：石萌拖入会议室后同步人选、拖出立即取消、沿通道回到SW_08并恢复看屏幕；安冉通过菜单入区、全部复位清空对应演示人选；核心井区拖放吸附到通道；Escape取消拖动；亮/暗显示与控制台无错误。
- 正式页面：模型就绪，九楼按钮及所有人复位可用；健康接口、426项构建来源和398个既有资源校验通过。30个文件部署；人员配置SHA256保持不变；未发送外部消息。
