# 聊天 AI 填价与双系数辅助填写

日期：2026-10-09。最终 UI v0.9.62，设计系统 1.0.30。v0.9.61 的平台持续监护改动保持不变。

## 交付行为

- 表格两个行操作合并为带文字的 AI 填价入口；表头、空行、合计行不显示。
- 点击后恢复左聊天右表格并定位聊天卡开头，保留 Sheet、草稿与当前任务。
- 卡片切换基价 / 单价、实物系数、技术系数，展示最多前三个不同数值；不足三项按实际数量，不凑数。重复数值保留同值来源说明。
- 候选加载完成自动调用已配置模型，正文标明真实模型状态，支持停止。切换字段 / 行 / 会话丢弃晚到结果；刷新历史不自动调用模型。
- 按候选按钮明确确认，仅写对应物理列。候选与成果 SHA、版本、对话和来源摘要绑定，旧候选拒绝覆盖。写后保留待重算状态。
- 详细打开原生 dialog：计价库 / 规则、经验池分别展示最低 / 中位 / 均值 / 最高与真实直方分布，查看数值排序、来源文件 / Sheet / 行号和匹配记录。超过200条明细明确标注，统计使用全量匹配记录。

## 业务来源与适配

冻结 `03-Src/engine` 不修改，2.0 原目录只读。价格沿用 `build_fill_assist_candidates`；系数复用原 `ai_matching.orchestrator._candidate_snapshot` 的规则判定与计价库经验层，经验池使用原 `ExperiencePoolMatcher` 的同类匹配。规则优先，经验均值 / 观察次数作为人工复核依据，不当作模型置信概率。

原单行入口未清理“成图比例”版式标记，本次在适配层调用批量引擎同一清洗函数，使经验池匹配一致；定位系数时优先已确认 `column_mapping`，排除说明、批注、经验和信息抓取列。读取详情 / 模型分析不占全局写锁；实际写回仍使用原串行保护。
