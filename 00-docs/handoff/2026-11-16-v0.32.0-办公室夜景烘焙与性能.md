# 办公室夜景烘焙与性能

UI v0.32.0，2026-11-16。用户批准可旋转、缩放、进入九楼的夜景预计算方案，目标接近60 FPS；不把整幅画面预渲染成固定图片。

## 实现

原 v0.31.4 夜景是白天贴图叠加逐片元灯光，再完整绘制场景一次提取发光遮罩。保留可调材质角色，新增两部分：

1. 静态地面夜间光照：在隔离 Blender 5.2.2 工厂场景导入原 v0.6.7 GLB，保留办公室1415个静态对象，选取20个实际地板受光面及原UV。根据既有灯位计划生成32盏面积灯，64 samples、4 bounces、3 diffuse bounces，烘焙直接/间接 diffuse；分隔墙仅在烘焙场景延伸为2.8m高的遮挡体，不修改显示几何。CPU烘焙约37.1秒，Blender合成器去噪。输出2K/16bit PNG，Standard sRGB编码后由GPU解码为线性光，不重复套用AgX。烘焙仅包含室内灯光，环境底色、灯光增益及屏幕照明仍可分别调节。材质和祖先节点双重限定，只用于原办公室地板图集；主楼楼板、室外地面和白天图集不替换。
2. 单次场景绘制：WebGL2 MRT同时输出场景颜色与发光信息，使用同一深度和透明alpha维持遮挡/展开渐变。保留MSAA抗锯齿，辉光从发光附件做降采样、模糊和合成，正常墙面、看板文字不进入辉光。关闭辉光直接绘制，切回白天释放夜间目标；人物动作及原隐藏/离屏暂停逻辑保留。

不是全模型物理夜间GI：地面使用真实静态烘焙，家具、墙面、人物仍使用既有可调近似照明；原模型、白天效果、v0.31.4局部黑边修复、个人保存值及复核业务保持。图片加载失败自动使用原动态地面照明，不阻断办公室载入。

## 性能证据与边界

同一台Windows机器、Edge、同一场景与默认参数，1600×1000窗口，实际绘制1525×942；每个条件预热1.6秒、采样6.5秒。采样强制连续绘制，避免把静止时按需停算误当低帧率。

| 场景 | 原版FPS | 新版FPS | 原/新绘制调用 | 原/新P95帧间隔 |
| --- | ---: | ---: | --- | --- |
| 白天九楼 | 60.00 | 60.00 | 791 / 791 | 16.8 / 16.8ms |
| 夜景九楼 | 54.31 | 59.84 | 1660 / 839 | 33.3 / 16.8ms |
| 夜景整楼 | 50.77 | 59.85 | 1414 / 716 | 33.4 / 16.8ms |

1920×1440窗口补测（绘制1845×1382）每条件10秒，九楼/整楼分别约60.00/60.00 FPS；正式5189页面同窗口开启自动旋转，10.019秒平均59.987 FPS、显示60 FPS、839次绘制。正式测试通过应用实际完成帧数计数，不以独立requestAnimationFrame回调替代渲染帧。

以上是本机短时实测，不能等同所有显卡、4K、多屏或长时间运行的帧率保证。MRT增加两张半浮点附件及MSAA显存开销，主要收益是减少重复几何提交；关闭辉光/转白天释放这些目标。未宣称减少所有GPU内存。
