# 办公室自动旋转恢复修复 v0.44.5

2026-11-17；正式UI0.44.5，宿主0.16.1。

## 原因与修复

用户当前5189内置浏览器仍载入0.44.3：展开九楼、画面设置打开，旋转enabled=true、paused=false、active=true，却一直running=false。viewer的canRun将展开设置作为永久阻塞条件，是本次现场复现的直接原因。

另查到旧cameraHeld仅依赖本iframe pointerup/cancel、blur、dragend，缺少宿主chat-pointer回传与lostpointercapture/隐藏清理，存在跨窗口或中断拖拽后的残留风险。

移除设置面板永久阻塞；所有面板内实际指针操作暂停，滑块输入、滚轮、键盘重置空闲计时。统一记录活动指针，多指全部结束才恢复；接入宿主结束/取消、捕获丢失、失焦、页面隐藏和场景隐藏。默认空闲5秒，仍沿用已保存等待时间和原旋转速度/角度。

保留工位编辑保护、手动暂停、减少动效、离屏停算。人物拖拽、动作、选人及发送业务代码未改，24项批准画面默认值和所有模型/贴图未改。

## 验证

- npm test：530/530；办公室59项，新增回归覆盖原生up/cancel、捕获丢失、宿主up/cancel、失焦、隐藏/恢复、多指、HTML拖动、指针按钮恢复及手动暂停。
- npm run build：从实际正式0.44.4基线构建候选，不带入工作区其他未提交功能；426份来源、399份既有静态资源逐项核对。
- 隔离浏览器5243：整楼、展开、九楼均观察到running=true和相机位置变化；画面设置保持展开仍旋转。实际按住滑块5.5秒保持停止，松手5.5秒恢复。
- 手动暂停后切整楼，超过5秒仍paused=true/running=false；主动恢复后重新旋转。
- 实际将安冉拖入左侧对话：成果卡出现人物标签、dragging=false、人物继续打字，5.5秒后旋转恢复。该次浏览器走原生捕获松手，宿主chat-pointer单独由回归测试覆盖；未发送真实平台消息。
- 浏览器后台限帧，本轮不据此声明帧率提升；运行状态及相机变化用于验证旋转恢复。渲染质量与既有材质不调整。
