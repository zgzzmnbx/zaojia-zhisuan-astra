# 办公室加载与九层入场

正式 UI v0.28.0 / host v0.14.3，2026-11-15。本轮只改办公室入口、渲染准备和镜头展示，原复核业务校验、收件权限和确认发送仍由原组件负责。

## 用户可见行为

- 点击“多人复核”立即打开浮动对话与办公室画面，不再等待复核资料读取结束才打开。载入时使用现有智算 LoadingLogo，真实 WebGL 首帧就绪才收起；桥接 DOM 的 ready 不再被误当成渲染就绪。
- 正常动效：整栋楼停留约 0.85 秒 → 九层伸出并同步靠近 → 展开完成停留约 0.65 秒 → 进入九层办公室。两段空间过渡各约 1.05 秒，以实际显示帧推进。
- 根据用户追加要求，展开阶段围绕九层取景，尺度为最终办公室视图的 1.3 倍，不再按展开后的整栋楼缩小取景。1600×1000 实测时，九层占主要可见场景一半以上，后方大楼仍保留；重置展开视角使用同一规则。
- 手动选视图、拖动镜头可接管入场；隐藏停算，不追赶后台时间。减少动效直接进入办公室。返回后复用相同 iframe / WebGL 实例；已结束的入场再次播放，中途隐藏则继续。

## 首次加载处理

宿主先绘制 Logo，再挂载 iframe。查看器分批上传纹理，使用 scheduler.yield（不支持时 setTimeout 回退），并在同一个 WebGL 上下文预编译普通和楼层淡出材质。场景材质准备之间主动让出执行，几何包围盒复用已有结果。

本机旧查看器曾观测到首帧附近约 875ms 长任务；新版把纹理与程序准备分散到 Logo 显示阶段。模型仍需下载、解析和显卡准备，不能承诺任意电脑冷启动零停顿或瞬间完成。预编译会增加准备阶段工作量，以换取揭幕后的连续入场。
