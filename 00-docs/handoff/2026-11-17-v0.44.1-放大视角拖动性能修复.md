# v0.44.1 放大视角拖动性能修复

2026-11-17，正式 UI 0.44.1 / host 0.16.1，原宿主进程复用。

## 原因与修改

在用户当前放大页面采样，主要重复开销为静态场景世界矩阵更新：Scene根自动更新向全部后代传播强制刷新，Floor节点又在每帧标记变化；人物定位另刷新整栋楼。另有落点标签交错读取布局，以及镜头拖动期间人物悬停命中检测干扰事件。

- 缓存静态根与模型局部变换；每次楼层移动显式提交矩阵，人物骨骼和动态辅助标记仍实时更新。
- 人物定位仅更新楼层祖先，不遍历整栋楼；落点标签复用本帧视口尺寸。
- 镜头拖动时跳过悬停检测；空闲悬停33ms限频，按下选人仍精确即时检测。
- 模型、材质、分辨率、日夜光照及多人复核业务不变。
- 正式浏览器复查发现旧模块缓存导致新增导出缺失；为 static-batches 与 person-placement 显式增加0.44.1导入版本，重新构建并复查已有缓存浏览器。

## 验证

528项npm测试及正式0.44.0基线构建通过。实际GLB共3724节点，在100个静态帧中世界矩阵乘法为0次；整楼→九楼位移→整楼的全部对象世界矩阵与预期一致，人员锚点相同。

同一内置浏览器、1205×662画布、DPR1.25、九楼默认方向放大三档；每组5秒，右键拖动相同输入路径，拖动期间镜头与可见三角面随阻尼变化，因此不是逐帧像素一致的GPU基准。

| 样本 | 0.44.0 | 0.44.1 |
| --- | ---: | ---: |
| 静止但人物持续活动 | 43.2 FPS | 50.6 FPS |
| 拖动视角 | 40.0 FPS | 46.0 FPS |
| 拖动帧间隔P95 | 33.5 ms | 33.5 ms |

拖动平均帧率提升约15%；仍未稳定60帧，不能把静态矩阵优化表述成解决全部GPU/主线程负担。首次误用5214端口，与另一任务预览冲突而加载0.43.1，该组样本全部作废。最终使用Windows独占端口5237/5238，核对UI版本、iframe资源版本，最终before/after-metrics.json仅保留有效样本。

真实浏览器：整楼/展开9F/9楼切换、人物入区选人、实拖离区取消、通道返岗后打字、日夜外观、控制台无错误通过；不发送外部消息。正式页面资源与健康检查通过，保留用户人员配置及运行数据。
