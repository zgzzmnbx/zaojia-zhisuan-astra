# 办公室玻璃配色与参数对齐

正式 UI v0.31.0 / host v0.14.3，2026-11-15。本轮只改办公室宿主表现层。

## 操作与默认

画面设置首项为“主楼窗玻璃”的两个原生单选：原有白色 / Astra 蓝色。蓝色选中时“玻璃蓝色浓度”滑块可用，0% 为原白色表面，100% 为 Astra 基准蓝。用户在实施中要求颜色淡一些，最终默认 55%，不是默认 100%。此滑块只影响白天玻璃，不改变夜间窗灯和室内蓝光。

保存、重载和恢复默认沿用原机制。新字段自动补充默认值；不覆盖已有个人参数。恢复默认先预览，点保存参数后持久化。浓度 0、实时阴影 false 和白色选择均是有效值。

## 配色来源与适用边界

读取的是正式运行 V11 资源和 defaults.ts / baked-surfaces.mjs / night-city.mjs / night-bloom.mjs；未采用工作区其他线程尚未部署的参数，也未用旧 Blender 研究样板冒充当前颜色。

基准蓝来自正式知识建筑的窗玻璃烘焙区域：`public/sandbox-v11/model/texture-01.png`，SHA256 `540374340b162c829b29cef84a7f5a2dc4246d2706f8674c44b755b435af2a52`。在归一化图像区域 `[0.545, 0.426, 0.636, 0.548]` 中筛选 9294 个玻璃像素取中值，sRGB `#0b78a6`，解码线性 RGB `[0.003346535763899161, 0.18782077230067787, 0.38132601143253014]`。`astra-lighting-profile.js` 保存来源和配色。着色仅作用于 window 角色，保留办公室原烘焙明暗，并在白色与蓝色之间混合。

这里复用实际玻璃配色基准；不同建筑的面朝向、烘焙阴影和曝光会产生不同屏幕像素，不能把“同一配色”称为两栋楼逐像素相同。

## 参数核对

| 项目 | 正式 Astra | 办公室最终处理 |
|---|---|---|
| 主体 / 办公室亮度 | 145% | 同为 145% |
| 背景、周边、地面亮度 | 105% | 同为 105% |
| 背景色 | #ffffff | 保持一致 |
| 地面底色 | mist / #f5f7fa | 新增独立地面颜色，默认一致 |
| 额外主体提白 | 无 | 65% → 0%，保留源烘焙层次 |
| 输出颜色 / 色调映射 | sRGB / NoToneMapping | 烘焙模式对齐；实时预览仍保留其 AgX 路径 |
| 实时阴影 | 默认关闭 | 默认关闭，增加独立勾选项 |
| 夜间主体与周边轮廓 | shell 25% | 保持 25% |
| 夜间主楼窗灯 | core 120%，RGB (.18,.43,.65) | 保持相同基准；大面积幕墙的原占用率/面积衰减保留 |
| 周边窗灯 | context 110%，冷暖混合 | 保持相同数值与颜色 |
| 辉光 | halo 120%，110 × halo / 100 | 保持同一增益；色调改为 (.055,.36,1)，混合 .72 |
| 浓度 | 主沙盘贴图自带蓝色 | 用户最新要求覆盖为可调，默认 55% 淡蓝 |

周边白度 100% 是办公室对原模型灰色材质的校正，用来适配 Astra 专用城市白色烘焙，不能与主沙盘不存在的“白度”参数做数值等同。室内灯、显示器光、人员动作、前向视角限制及按模型包围盒取景是办公室专属配置；没有照搬河流、输送带、建筑坐标距离等无对应参数。自动环游仍复用 Astra 的同一运动算法和宿主设置。

夜间主楼曾试验取消大面积幕墙衰减，实景整栋楼泛光过强，已保留原面积适配；同色同增益不等于把空间适配系数全部删除。本轮没有重烘焙：原贴图已有光影，颜色混合保留其明暗，也不增加实时灯光、纹理或渲染循环。
