# v0.27.0 办公室光影对标与参数

日期：2026-11-15。Astra UI v0.27.0 / host v0.14.3。模型保持上游 v0.6.7，未修改 GLB 或原始贴图。

## 对标依据与差异

以实际正式运行的 v0.26.0 智算沙盘为参照，读取其 `defaults.ts`、`baked-surfaces.mjs`、`night-city.mjs` 和真实浏览器状态，并分别留日夜截图。

| 项目 | 原办公室 | 正式智算参照 / 本轮处理 |
| --- | --- | --- |
| 日间背景 | 写死 `#cbd2d3` | 采用 `#ffffff`，背景亮度 105%，可改颜色与亮度 |
| 主体亮度 | 仅统一曝光，无独立控制 | 主楼/办公室分别调节，初始各 145% |
| 周边建筑 | 与主体混调，保留旧灰色调 | 独立亮度 105%、白度 100%；中性白模保留表面明暗 |
| 地面 | 原烘焙灰色 | 独立亮度，保留遮蔽细节并柔白处理 |
| 周边夜景 | 旧节点匹配漏掉合并群楼，窗灯未正确覆盖 | 识别真实 `ContextWeb_Buildings` 与其渲染子节点；道路/地面单独分类，避免地面出现窗灯 |
| 夜间颜色与层次 | 群楼与主体共用偏青颜色 | 沿用正式 studio 冷蓝 `[.055,.17,.27]` 和少量暖色 `[.24,.14,.065]`；主体、周边轮廓各 25%，周边窗灯 110% |
| 大面积玻璃 | 全片统一发光，容易泛白 | 宽玻璃保留低亮蓝色，标识/屏幕保持局部亮点；主楼窗灯可单独调节 |
| 参数保存 | 旧曝光/蓝色自动保存 | 即时预览，显式保存；恢复默认不覆盖已保存记录 |

这是针对不同模型进行的视觉对齐，不是把另一沙盘的灯位、米制尺度或烘焙贴图直接套用。保留 sRGB 贴图解码与线性计算，未靠二次色调映射抬亮。实现依据见 [Three.js 色彩管理](https://threejs.org/manual/pages/color-management.html)。

## 操作与默认值规则

办公室顶部 **画面设置** 打开浮动面板。日间显示主楼、办公室、周边、地面亮度，主体/周边白度、明暗层次、背景亮度/颜色；夜间显示主楼与周边轮廓、室内照明、主楼/周边窗灯、屏幕蓝光、灯光辉光。蓝色点缀和整体曝光通用。滑块支持鼠标和方向键/Home/End，输出值与可访问名称同步。

- 拖动只预览；**保存参数** 写入当前浏览器本机偏好，刷新后沿用。
- **恢复默认** 回到内置对标参数，需再点保存才改变下次启动值。保存/恢复不影响项目、人物任务或复核卡。
- 默认配置集中在 `public/office-twin/viewer/lighting-settings.js`，默认版本 `astra-office-studio-2026-11-15`；本机键 `astra.office.saved-lighting.v1`。
- 用户以后说“把现在的参数设成默认”时，读取其实际使用页面的 `window.officeTwin.getState().pictureRecord` 或同一浏览器保存记录，核对日间、夜间全部数值，再更新集中默认配置、测试和发布。不得拿测试浏览器参数、当前文件旧值或猜测值代替用户快照。
- 旧版本已有的曝光、蓝色偏好保留迁移；日常调节不会改变程序内置默认值。原“人物动作”开关独立保留。
- “明暗层次”调节现有烘焙阴影的显示对比，不伪称新增真实重烘焙或改变光源方向。
