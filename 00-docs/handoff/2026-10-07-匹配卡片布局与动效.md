# 匹配卡片布局与动效 · UI v0.7.3

2026-10-07。仅修改 Astra 独立 worktree；原智算 2.0 输入与引擎保持只读。

## 修复

1. 上传此前会 `open(mapping)` 进入大预览。现在进入大聊天，在当前输入卡中编辑项目名、工作表、参与处理、表头行；字段映射与匹配范围按需展开，历史卡不操作新任务。转换后仍留在聊天，用户点击表格才切换双栏大预览。
2. 项目卡此前仅接受已手动归组会话。现在真实结果通过 conversation / project scope / job 三项校验后，未归组也可显示当前任务；名称优先取真实任务。不会按文件名合并项目，不自动创建项目分组。匹配完成在桌面显示摘要并回到顶部；用户已主动切换的内容不被晚到结果抢走。
3. 一般环图 220→180px，项目摘要 136px，柱条 18→10–12px；摘要减少重复标题与进度图，保留金额、构成、匹配 / 复核统计、风险状态、操作。长项目背景、阶段与复核说明展开查看；聊天结果仍保留金额明细表。
4. 入场被自动滚动打断后，原实现仍标记已播放。现在取消未完成动画时重新允许可见入场，已完成的不随草稿 / 主题重播。卡片 520ms、面板 560ms，图标轻缩放 650ms，环图描绘 1100ms、柱条生长 1000ms；减少动效仅 180ms 淡入。

## 验证

- `npm test`：112 项通过。补充未归组真实任务、跨会话隔离、任务名称与分组区分、上传保持聊天及手动切表格测试。
- `npm run build`、`npm run build:frontend-debug`：类型检查、正式与调试构建通过，最后恢复正式构建。
- 使用原工程 `08-测试与演示/【项目例子】【测试输入】可行性研究勘察测量控制价计算 -v3.1【演示】 .xlsx`，在新的独立验收会话完成上传、转换、批量匹配。未手动关联项目，右侧自动显示当前任务；聊天和项目卡金额一致：含税 2,672.85 万元，不含税 2,521.56 万元，增值税 151.29 万元。
- 上传 / 转换仍为大聊天；显式点击项目卡“表格”进入大预览，关闭返回摘要。刷新恢复真实任务。另验收工作表切换、字段值调整 / 还原和输入设置刷新恢复。
- 1478×993、1366×768 项目摘要可用高度和内容高度均 607px，默认摘要无纵向滚动，柱图无横向溢出。桌面亮暗截图已检查。390×844、320×740 上传卡无横向溢出并保留聊天；窄屏纵向正常滚动。
- 浏览器实际捕获 11 个正在播放的摘要动画，包含环图 circle、柱条 i、项目图标和面板；上传卡和图标分别捕获 520ms / 650ms。草稿输入不触发新动画；减少动效不含位移 / 缩放。
- 本地证据在 `Codex-Temp/matching-layout-*`、`matching-motion-*`、`matching-input-mobile.*` 和 `matching-settings-*.png`，不入 Git。
