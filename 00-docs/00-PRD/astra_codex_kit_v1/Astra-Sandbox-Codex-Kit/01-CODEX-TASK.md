## 二、实现的视觉结果

在保持原建筑位置、模型比例、七个业务节点、真实数据和 UI 布局的情况下，做到：

1. 建筑顶面、朝光立面、背光立面和楼板下方能看出层次；白色清爽而不过曝，凹槽有遮蔽但不脏。
2. 储罐是可读的圆柱，管道和弯头有连续高光带、清楚的法兰和接触阴影；整体仍以白色涂层为主，局部可有浅银色连接件。
3. 地台比主体略冷、略灰，保持哑光；外围浅灰背景平静，不出现大面积镜面倒影或背景云朵光斑。
4. 蓝色继续承担现有业务强调、窗面和水道语义。不要新增无业务含义的霓虹、灯带或满场描边。
5. 当前“聚焦辉光”仍能标识焦点，但不吞掉被选建筑的形体。

不从参考图复制金额、比例、文本、版本号、节点状态或模型变形；不隐藏业务卡片、不改变默认机位来伪造同图效果；不把图片铺到 canvas 上冒充可交互 3D。

## 三、采用确定的技术路线

以当前 **离线 Cycles 照度 + 本地 HDR/PMREM + PBR 材质 + 实时方向光与缓存阴影 + 单次场景渲染** 为主线。v0.10.56 已有这些能力，不重复建设。

先在现有结构上校准增强日间的主辅光比例、曝光、冷白基色和阴影；再按可靠部件角色细分建筑、管道和储罐表面。保留 1024 阴影为第一轮基线，优先检查阴影视锥和 normalBias。只有实际对照证明必要且性能允许，才评估 2048；不默认上 4096。

本次不引入全画面 Bloom、SSAO/GTAO/N8AO、实时路径追踪、R3F/drei 或 WebGPU 迁移。外部项目用于学习光照与材质关系，不直接移植其渲染架构。若主路线仍有不足，应先查曝光、材质串改、法线、UV、烘焙和阴影范围，不能顺手扩建技术栈。

## 四、必须处理的代码细节

- 重点文件：`scene.mjs`、`materials.mjs`、`lighting-materials.mjs`、`lighting.mjs`、`building-paint.mjs`，以及有需要时的烘焙/材质标记工具。详细职责见技术方案。
- 绝不能根据 `Porcelain white` 名称，把建筑与所有管道一起设成金属。角色须来自可信资产语义或验证过的面级映射。
- 新角色必须保留原始基底材质语义，继续参与原来的冷白、夜航、任务染色、区域隔离与装配着色器组合。不要覆盖已有 `onBeforeCompile` 链。
- 增强关闭、日夜切换、装配开始/结束以及销毁时，要恢复所有被此次修改的材质属性。不能只恢复 roughness 而遗留 metalness、法线或环境强度。
- A/C 调优主要作用于增强日间。夜航保留现有行为；日间烘焙在夜航和悬浮装配期间强度为 0，落成后沿原 450ms 时序淡入。
- `astra.sandbox.enhanced` 与 `astra.sandbox.bloom` 继续分别表示“质感增强”和“局部聚焦辉光”。保存的 false、原色、隐藏等均有效，不重置偏好，不另造同义开关。
- 管罐角色语义、隔离性与诊断证据必做。当前审阅基线尚无专用角色实现，预计需要派生资产；先检查当前 GLTFLoader 实际结果，若更新后的代码已有可信角色则复用，不重复导出。
- 保持原 GLB 与 `lighting-v1` 可回退。确需新资产时，使用独立、版本化的派生目录；不能覆盖原 Blender 工程。只给完整原刚性组件分配角色，保持局部属性、zone、UV、真实装配位移与时序，不能只验静态外形。
- 保持单一调度与按需 RAF、静止停帧、后台/离屏停算、装配阴影逐帧更新、资源释放及异步取消。参数调整不应生成持续新帧或重复 PMREM。
- 如新增参数模块，建议放在现有 `project-sandbox` 根目录；当前构建逻辑逐项读这个目录，贸然新建子目录可能导致构建失败。

`specs/look-proposal.json` 是未实测的第一轮候选，不是机械照抄即能过关的配置。实际画面结果优先于某个固定数值。
