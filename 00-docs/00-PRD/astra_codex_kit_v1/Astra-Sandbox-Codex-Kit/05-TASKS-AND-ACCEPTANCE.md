# 分阶段任务与验收

本文件把视觉要求转成开发顺序。先完成当前阶段的具体产物，再进入有依赖的下一阶段；不为每个微小参数建立一套形式化审批或重复全量测试。

## 1. 任务顺序与退出条件

| 阶段 | 输入与操作 | 产物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| P0 当前基线 | 读当前指令/HEAD/工作树；看 A/C；运行现有版本；记录真实机位与设备 | before图、当前参数/资产/偏好、初始性能、差异记录 | 确认实际运行的是目标工作区；已存在问题单列 |
| P1 整体光照 | 复用现有增强链路；一次改一组主辅光/阴影参数；第一轮保留基色与曝光 | 同机位候选图、最终光照配置与原因 | V01/V02/V05/V07有可见改善；无基础功能回归 |
| P2 表面语义 | 检查并验证当前角色；缺失时读取发布GLB与只读源工程，完整组件赋role并派生 | 角色证据/诊断；实际改资产时附GLB、manifest、组件/UV校验 | 无歧义误染；已有可信角色可复用；新资产保真 |
| P3 材质接入 | baseName兼容；按状态覆盖roughness/法线；完整恢复；有新资产则补有界回退 | 实际管罐近景、状态矩阵检查 | V03/V04/V08/V11/V12通过，日夜/装配不串状态 |
| P4 收口 | 同条件性能、资源生命周期；项目测试/构建；当前构建浏览器验收 | 测试构建结果、性能表、截图/交互记录 | 本节硬性行为检查与目标视觉通过；限制明确 |
| P5 交付 | 填模板、整理改动与资产来源、按现有项目规则记录版本 | 可运行本地修改、证据、回退说明 | 用户能复查实际效果；未测项未冒充完成 |

主视觉V01—V07使用日间+增强开+冷白+未聚焦+现有全景的可恢复测试状态，before/after同条件；其他偏好组合验功能与恢复，测试后还原保存设置。角色语义与诊断必做；当前基线预计需派生，但如更新后已有可信角色，不为满足阶段名称重复导出。

P2 不以“重新建一个相似沙盘”完成。若源对象与发布GLB不匹配，继续完成 P1 等独立工作，定位差异；未解决的 C 局部目标必须保留为未完成。

## 2. 必须保持的行为

| ID | 操作/设置 | 通过判定 | 证据形式 |
| --- | --- | --- | --- |
| F01 | 增强开→关→开 | 基底物理属性及本轮改动的灯位/环境方向等完整恢复；同一挂载内开启重用资源；不换模型/controls/聊天实例 | 属性快照+实际画面 |
| F02 | 冷白↔原色、日↔夜 | 原偏好有效；夜航恢复原灯位/方向及旧增强行为；白天恢复新profile | 状态矩阵记录 |
| F03 | 日间首次装配 | 悬浮时GI强度0、辉光隐藏；实时影与组件同帧；完成后450ms至新终值 | 关键帧+实际强度 |
| F04 | 装配途中点击/导航、减少动效 | 正确结束，原geometry/shader/depth恢复；不残留或重播 | 操作记录+资源检查 |
| F05 | price→table→risk→全景 | 不串楼染色；焦点/辉光同步；快速切换无残留 | 真实交互 |
| F06 | 任务推进/完成/取消 | 原paint范围与业务含义保留；任务结束保留原taskTarget逻辑 | 样例/隔离测试 |
| F07 | 关闭flow/autoOrbit，等待稳定1秒 | frames增量0、pending=false、shadowDraws不增长 | 两次诊断快照 |
| F08 | 页面隐藏/离屏后恢复 | 停算且不把后台时间一次补进动画 | 前后快照/操作 |
| F09 | 同场景增强切换10次，退出再进入 | 同次挂载中首次加载后资源量稳定、开关不重复PMREM；销毁无晚到资源挂回；新挂载可重新创建环境 | 数量记录+控制台 |
| F10 | 刷新/切换视图 | 保持原持久化规则：保存的false/hidden/original及相机elevation/zoom/distance有效；切视图保护原草稿/任务/布局；不新增任意拖拽姿态跨刷新持久化要求 | 实际UI |
| F11 | 模型下载/解析/结构验证失败 | 若新增v2加载链，逐候选释放并有界回退；abort不重试；全失败原错误入口可用 | 可恢复失败注入 |
| F12 | 任一照度/HDR/法线加载失败 | 沿原基础画面回退；无部分资源泄漏；off→on可重试 | 可恢复失败注入 |

F07 的测量前须排除合法动画驱动并等待焦点、染色和有限渐变稳定；测试后恢复用户设置。信息流或环游主动开启时连续渲染是预期行为。

`lighting.lightmapped` 只计绑定贴图，不代表当前照度有效。F02/F03 应读取真实材质 `lightMapIntensity`，或通过只读诊断暴露的强度范围 / activeLightmapped。夜航时“lightmapped非零”本身不算失败。

有新资产链路才新增 F11 对应解析/验证回退实现；不能声称基线已经支持损坏GLB自动回退。

## 3. 资产与装配的硬性检查

仅实际修改资产时完整执行 A01—A08；若复用当前可信角色，记录适用项及证据，不生成无必要的新资产。以 `GLTFLoader` 实际载入的原v1与新派生模型为准，不能只检查 Blender 导出前对象。数值比较沿用技术方案所记录的容差；原局部属性与组件量化关系以直接保留为原则。

| ID | 检查 |
| --- | --- |
| A01 | 原GLB、v1资源与源工程未被覆盖；记录全部输入/输出SHA256 |
| A02 | 8个规范化光照区身份、每区有向世界三角形多重集合、法线、UV0/UV1匹配；已识别land可缺省ground，七栋建筑父zone不得丢失；允许接缝顶点复制，不允许几何移动 |
| A03 | role有基底语义、来源primitive与原组件证据；未命中/歧义/混合组件明确列出 |
| A04 | 每个新primitive只包含自身实际引用的完整顶点属性；不保留整楼未引用POSITION产生“幽灵组件” |
| A05 | 原节点层级/局部矩阵与局部坐标量化焊接关系保真；不只比较世界外形 |
| A06 | 按原算法实际得到的zone bounds、组件边界、aAssemblyMotion世界位移和start、每楼end及总total一致 |
| A07 | 输出导入后原组件既未拆开也未合并；如有旋转节点拆批导致AABB变化，保持该primitive不拆并另行解决 |
| A08 | v2复用v1贴图时，UV指纹与贴图依赖明确；改UV则整组新GLB/贴图一起通过非空、有效UV岛与哈希检查 |

A06 特别重要：原算法对每个mesh使用默认 Box3 再合并。旋转/缩放节点拆成多个mesh后，即使世界三角形一致，包围盒计算也可能变化，影响装配所有组件。必须比较实际算法结果。

## 4. 测试与真实构建

项目已存在 `sandbox-lighting.test.mjs`、`sandbox-materials.test.mjs`、`sandbox-view.test.ts`、`project-sandbox.test.ts` 等相关测试。本轮只为真实新增风险补必要测试：

- 同一基底下不同role及不同zone互不串改。
- 加强后关闭能恢复本轮修改的所有属性，日夜/装配覆盖顺序正确。
- 新基底身份不破坏原paint与entrance shader组合。
- 新资产组件/UV/zone保持，以及新增候选加载对解析错误/abort的处理。

不要新建大量“参数等于自己配置值”的镜像测试。旧测试中确有 .055/.85 断言，参数集中管理后可相应调整，但必须保留关闭恢复、区域隔离、450ms时序和不持续渲染等行为断言。

在仓库实际环境按其指令运行：

```bash
npm test
npm run build
```

记录命令、退出码、日期及真实输出摘要。构建后核对浏览器加载的版本标识、`astra-build.json` 与新资产URL/哈希，避免看的是旧服务/旧构建。版本号按当前仓库规则从实际下一版本产生，不能把 UI 文本硬编码成参考图里的 v0.10.56。

不得为通过验收清理用户工作树、覆盖运行配置、清空 04-Output 或中断已有业务服务。测试失败先区分既有失败与本轮回归，再针对风险修复和复测。

## 5. 性能测法与目标

**本包没有实测任何设备。** 仓库旧验收文件中的约60FPS属于短时历史样本；不得复制到本轮报告。

### 测量条件

before/after 同设备、系统、浏览器、CSS视口、DPR/renderer上限、当前任务快照、聊天与右卡片、光影/信息流/环游状态一致。注明刷新率与是否录屏。主建议视口1920×1080、缩放100%；无法设置时实报当前尺寸并同条件比较。

加载/编译稳定后，取一段约20秒的连续旋转/聚焦操作，采样实际渲染帧间隔；不要把按需渲染静止时的长时间不出帧算进交互FPS。静止停帧单独用 F07 判定。

记录平均FPS、渲染帧间隔P95、超过100ms的明显长帧、draw calls/triangles/textures、初次加载时间与资产字节数。没有测GPU耗时就写未测，不能把RAF间隔称为GPU渲染时间。

### 预先设定的候选门槛

- 同条件桌面稳定交互目标：**平均≥50 FPS，帧间隔P95≤33.3ms**。
- P95比基线劣化超过15%时，触发具体原因检查；只在噪声或边界需要时补一次同条件采样，不反复跑到得到最好结果。
- 不出现本轮引入的持续卡顿、黑屏、context丢失或无法恢复的GPU错误。
- 资源首次加载后趋稳；稳定辉光依旧单场景pass、无新增后处理renderTargets；静止不续RAF。
- 角色拆批的draw-call增量和装配阴影成本单独记录；不承诺原60个材质组/绘制数一定不变。

若基线本身低于目标，给出新旧实测和增量，不能改称已达到目标。没有目标硬件时完成当前机器可验证项并明确设备验收范围。

若画质提升但性能未过，优先撤回试验性2048/额外贴图分辨率、减少无收益的材质拆批；保留已有效的光比和粗糙度关系。不能截图时用高档、计时却偷偷关闭增强或降低DPR。

## 6. 最终完成标准

相关 V01—V12、F01—F12、A01—A08有真实证据；不适用项写理由。测试、构建和本轮浏览器加载都已核对，性能按记录条件判定。

必须交付：

1. 实际代码差异、配置/资产清单与来源；没有业务范围漂移。
2. 同机位before/after、储罐/管道近景、原辉光聚焦图、小窗口图。
3. 真实交互录屏，或日志与关键帧。
4. 完整验收报告，包含偏离候选值的原因、测试/构建、性能和局限。
5. 可回到原视觉的配置/资产恢复方法，保护新旧业务数据和用户偏好。

如果只有编译通过、没有实机图，只能称实现待视觉验收。缺设备、角色映射未完成或某项失败时，列出剩余内容与复现步骤，不能写“全部完成”。

达到目标后停止额外审美试验；硬性回归未解则继续定位或交代明确阻塞，不用“已自检”替代证据。
