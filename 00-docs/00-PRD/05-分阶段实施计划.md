原计划 v0.2.0 · 2026-10-05；状态核对更新：UI v0.6.4 · 2026-10-07。用户已授权编写计划、PRD 并逐步实施。已交付 UI 基线与独立机械主线，后续依据本计划推进；普通可逆开发无需反复请求授权。

## 完成的定义

最终交付为独立运行的智算Astra：原造价智算已实现的能力全部保留，交互改为对话主导、右侧专业成果，规则与数字不因界面变化而变化。只有操作级覆盖清单全部核销、正式业务样本通过、故障与恢复验证完成，才能宣布迁移完成。

## 正式实现结构

- 通用外壳：项目 / 会话导航、消息、附件、输入、计划卡、人工确认、成果容器、Gork 状态。
- 专业定义：AgentDefinition 注册工具白名单、提示策略、知识范围、规则资产、成果类型。首个是造价，其他智能体目前只是配置示意。
- 动作协议：Action 含 taskId、attemptId、artifactVersion、输入、权限边界、幂等键；高影响动作需要明确输入和确认，不能凭自然语言模糊匹配直接写入。
- 事件协议：TaskEvent 区分待执行、运行、等待确认、成功、失败、取消。消息卡、Gork、进度使用同一真实事件；不把定时动画当后台状态。
- 成果协议：Artifact 含类型、版本、来源、读写能力和下载地址，renderer 只负责展示；右侧切换不销毁左侧会话、草稿或未保存编辑。
- 适配层：以原 React + TypeScript 前端和 FastAPI 接口为复用对象。当前原型使用原生模块验证视觉，不直接把字符串模板堆成正式业务平台。
- 框架选择：assistant-ui 负责候选会话结构，CopilotKit 参考动作与人工介入；避免同时引入多个相互竞争的状态容器。Open Canvas 只借鉴成果编辑 / 版本交互，其归档状态已记录。

## 不丢功能的落实方法

1. 以原 README、27 个模块 PRD、App 路由 / 事件、API 与设置配置为证据，建立操作级编号；当前能力矩阵只是总纲。
2. 每项记录原入口、前置条件、输入字段、读写资产、输出、Astra 入口、API、验证样本、验收结果。原系统未实现的能力单独注明，不能冒充已有功能。
3. 成果区保留可直接操作的专业工具，不能强迫所有表格编辑、字段选择和批量操作都改成自然语言。
4. 基价 / 单价、实物系数、技术系数逐字段记录来源和确认版本。人工编辑使相关旧确认失效；取消与新运行隔离晚到事件。
5. 全量盘点结论出现差异时先补矩阵和实现，不以换名称、隐藏入口或截图演示核销功能。

## 环境与数据隔离

所有源码、依赖、运行库、缓存、输入副本和输出留在 Astra 目录。原项目仅作为只读参照；不使用连接目录绕过隔离，不复用原可写 SQLite、经验池或输出目录。独立服务采用显式配置端口，启动前查冲突；不重启原 8000 / 5174。

阶段 B 记录需要复制的资产与来源哈希，区分可重建索引和不可丢失运行数据。密钥不进入仓库、截图、日志或导出包。外部平台默认禁用发送，只有用户已指定受众和目的的动作才实际联调。

## 验证与交付证据

- UI：1440×900、1366×768、768×1024、390×844；明暗主题、字号、键盘、草稿、局部表格横滚、3D 降级和释放。
- 业务：使用原 `测试-V3.1-260802` 输入以及 Excel、Word 双答案；区分数值、公式、来源、风险与版式。实际差异形成报告，不能改规则迎合答案。
- 故障：模型超时 / 失败、服务中断、缺资产、多个候选、取消后回包、手工修改后旧结果、重复提交、协同失败和知识范围错误。
- 回归：原模块专项测试 + 新适配协议测试 + 真实浏览器主线；构建成功不替代业务验收。
- 每阶段更新 README、当前版本计划、CHANGELOG 和覆盖矩阵；保留可重现命令、输入版本与输出位置。当前阶段不部署、不推送、不替换原系统。
