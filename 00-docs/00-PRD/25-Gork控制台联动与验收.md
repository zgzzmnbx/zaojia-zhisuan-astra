# Gork 控制台任务联动

版本：Astra v0.6.2 / Gork PC v0.20.26-dev，2026-10-06。

## 需求与范围

用户要求通过 Gork 机器人控制台让 Gork 追踪 Astra 任务。复用现有任务哨兵、机器人连接、桌面表情和提醒队列；Astra 不新增 BLE 客户端，不修改价格 / 系数规则，不刷写 Watch。

- [已完成] Astra 对话指令「连接 Gork 机器人」「任务追踪」及专业工具、工作室说明打开右侧联动面板。
- [已完成] 只读检测控制台版本、机器人连接、当前任务来源与跟踪状态；旧后台明确提示重开，不能仅端口可达就显示正在跟踪。
- [已完成] Gork 任务哨兵支持「原版造价智算 / 智算 Astra」两种来源；自动跟随或指定项目内的真实任务，沿用桌面 / Watch / 两端与声音设置。
- [已完成] 来源与开关持久化；原偏好无 source 时保持原版，已关闭的哨兵保持关闭。仅在明确应用时写设置。
- [已完成] 身份核验失败或任务不属于新来源时不替换当前配置；切换撤销旧请求、清除旧来源记录、重建基线。首次接入不补播旧事件，后续节点去重。
- [待验收] 正式 Gork 后台重开、启用 Astra 与实际 Watch 提醒；截至本轮检查，8766 仍运行 v0.20.24-dev，机器人已连接但任务哨兵关闭。已向用户询问是否现在重开并启用，尚未代为改变。

## 使用路径

1. Astra → 输入区「专业工具」→「Gork 机器人联动」，或「工作室说明」→「查看联动状态」。任务协作模式下也可以说「连接 Gork 机器人」。
2. 打开本机 Gork 控制台，进入「造价助手 → Gork 任务哨兵」。
3. 任务来源选「智算 Astra」，选择自动跟随或指定任务，选择显示 / 声音位置，开启并应用。
4. 继续在 Astra 执行任务。转换、匹配、预警、明确生成的最终风险报告、协同发起与实际送达沿用真实业务事件。协同发起不等于送达；过程 Word 更新不等于最终报告生成。

来源选择只影响任务哨兵；控制台下方原知识查询和项目浏览仍使用原版造价智算，界面已说明。暂不支持同时追踪两个来源。

## 架构与数据边界

```text
Astra 工作室 → 同源 /api/astra/gork/status → Gork 8766（只读状态）
Gork 任务哨兵 → 身份校验 → Astra 5189 /api/task-monitor/current
                               └─ /api/tasks/{task_id}/monitor
             → 既有 TaskMonitor 去重与优先级 → 桌面 / Robot / 固定声音
```

- 两个客户端严格分别接受 `guankanzhisuan` 与 `zhisuan-astra`；不放宽为任意服务，不允许远程地址、凭据或跳转。
- 运行态取既有 attempt 与锁、真实阶段事件；不按登记状态 `processing` 推断正在运行，不解析聊天内容猜进度。
- 来源项目列表具有请求序号和来源校验；旧来源晚到列表不覆盖新来源选择。工作台控制权保护仍生效。
- Astra 前端 CSP 保持同源；后端仅访问固定本机 8766 的健康、能力、哨兵状态接口。不读取密钥、不替用户取得 Gork 控制权，不直接发出设备命令。
- Gork 设置仍保存在其原 `sentinel.local.json`。这属于现有机器人控制台的个人持久偏好，不复制进 Astra 配置或 Git。Astra 不保存第二份哨兵设置。
- 用户此次明确授权接入 Gork，因此最小修改 Gork 控制台适配器与来源选择。原造价智算保持只读；原 Gork renderer、Watch 固件与设备网络配置不改。既有未提交修改保留。
