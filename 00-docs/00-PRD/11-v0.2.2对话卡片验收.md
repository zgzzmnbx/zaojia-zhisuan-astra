# v0.2.2 对话卡片验收

日期：2026-10-06。修改仅在智算 Astra 独立目录，原造价智算与 Gork 工程未写入。

## 实现与交互

- 新增通用 `ConversationCard` 数据模型、业务回执适配器、React 卡片与局部样式。消息正文负责解释，卡片负责确认、状态、依据和成果，不把普通解释全部装进边框。
- 资料卡：实际 Excel 名称、候选工作表、结构核对、编制步骤、可展开的识别快照。
- 执行 / 结果卡：真正的转换与匹配回执，处理 / 命中 / 原值 / 复核分别显示，不以加总推测意义。
- 风险卡：来自风险接口的事项和工作表 / 行号，点击定位右侧计算表；完整依据仍在右侧。
- 成果卡：只为实际已返回的 Excel / Word 生成入口，打开同一任务的专业成果区。
- 依据 / 修改卡：候选只读，人工修改附位置、前后值与修改依据，待重算后可继续执行。
- 能力 / 失败卡：明确机械模式与尚未接通的自由问答，失败时展示真实原因。
- 执行状态卡：真实忙状态与 Gork，不定进度，不展示虚构百分比。
- 操作绑定输入会话与任务；旧输入不能操作新文件，完成的转换 / 匹配不能重复确认。回执作为当次快照保留。
- 修复匹配、预警等业务回执后预览表头偏好未重新应用的问题，只调整 UI 预览刷新，不改变价格与输出语义。

## 真实浏览器流程

独立验收任务：`27093e3e4ba642e5b7d3b46f057814ef`，项目名“对话卡片验收 · V3.1”。输入为宿主提供的正式样本独立副本。

1. 从资料卡确认结构并转换，12 行待处理；旧确认按钮锁定。
2. 从执行卡批量匹配：12 行处理、11 行价格命中、1 行保留原值、0 行待复核；真实生成 Excel / Word。
3. 从结果卡检查经验池，返回 2 项风险；卡片展示表2第5行高风险、表3第6行低风险，点击前者打开对应表格。
4. 点击表格第5行依据，聊天出现来源卡，实际返回 8 项基价候选，均尚未采用。
5. 通过原有编辑弹窗核对并保留工程量 26，填写验收依据，保存人工记录；出现 26 → 26 的修改卡与待重算状态。
6. 从修改卡重算，宿主返回 Excel 公式已重算，预览 / Word 报告刷新；重算按钮锁定。
7. 从成果卡打开实际 Word；全屏 / 恢复、菜单收起 / 展开后，7 张卡片与输入草稿保持。
8. 刷新后恢复独立任务，出现真实成果恢复卡，并明确“原聊天未保存”，不伪造聊天历史。
9. 普通能力询问显示当前已接通能力和未接通边界。单独将样本表头行设为 0，显示“这一步未完成 / 表头行必须是大于 0 的整数”；改回 4 后可继续识别。
