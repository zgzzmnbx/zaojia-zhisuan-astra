## 实施方法

先建立“源已实现操作 → Astra 实际入口 → 输入/接口 → 业务效果 → 成果/状态 → 验收证据”的完整矩阵。要覆盖路由、按钮、二级操作、设置字段、失败和取消路径，不只比较接口数量；基线取真正原工程，不仅取 Astra 中已经复制的部分。

保留现有计价引擎、规则资产及已迁的专业模块；优先共享业务适配器和受控桥接，不复制整套旧 UI，也不把大型 App 主文件再完整重写。业务逻辑与新视觉解耦。确实更好的新实现可保留，但必须证明信息、操作、权限、来源、版本和输出都等价或更好。

按 T00—T22 及新增缺口推进。依赖表示必要的代码/契约前置，不表示某个外部实机验收受阻时，所有离线工作都必须停下；必要时把工作包拆成代码、契约、在线/实机三个子任务。每完成一项，更新 JSON 状态和操作矩阵，记录修改文件、样本、测试命令、结果、日志/截图、输入输出哈希和剩余风险。允许把本报告的判断修正为已完成，但要给出当前代码与验收依据。

不要在每个阶段重复问我是否继续。对代码、独立测试和现有明确授权内的工作自主推进。遇到缺凭证、指定受众授权、设备、Office 或外部服务条件，列出具体阻塞和解除条件，标 blocked_external，继续其余可做任务；不得绕过权限、寻找别人的密钥、伪造回执或将模拟测试当实机完成。
