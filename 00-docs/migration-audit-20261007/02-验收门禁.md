# 验收门禁和最小测试集

所有用例初始状态：未执行。本文件给出要验证的行为，不是测试通过报告。

## 1. 证据分层

A：静态代码/契约证据。B：本次离线自动化。C：本次浏览器实际交互。D：本次真实服务/Office/硬件。历史仓库摘要单列 H，不冒充本次 B/C/D。

完成一次迁移必须证明：入口可达、输入/设置完整、状态/权限正确、原业务结果不退化、产物真实可恢复、必要的失败/取消语义不丢。核心业务不能只用 A/B 核销需要 C/D 的项。

## 3. 必须实际运行的验证类别

先读取仓库当前脚本，选择本地正确虚拟环境，在隔离的测试运行库执行。已知入口包括 `npm test`、`npm run build`、`npm run build:frontend-debug`、Python 宿主测试、原专项测试以及 `tools/verify_astra_v31.py`。这些是入口，不保证当前环境已经安装依赖或这些命令能全部成功。

Windows 项目文档记录的 V3.1 入口为 `.venv/Scripts/python.exe tools/verify_astra_v31.py`。运行前确认脚本只用独立测试目录；不要在原工程目录运行会写缓存/运行库的测试。结算 builder 要迁入真实资源，不用假的 `frontend/src/App.tsx` 或空 fixture 迎合路径断言。

报告至少分开列：收集数量、通过、失败、跳过及理由、未运行、外部阻塞。`npm test` 不包含所有后端/专项；编译通过不是金额验证；DOCX 文本对照不是 Office 页面验收；预设风险回答不是真实模型证据。

## 4. 关闭规则

A. 功能覆盖：原已实现操作全集均完成或有证据等价替代，无未知去向。
B. 数值正确：三数字、单位、公式、阈值、费用、报告事实以及任务/成果版本无未解释差异。
C. 可靠性：取消/重试/恢复、人工修改、并发、附件与项目隔离通过必要用例。
D. 外部门禁：真实模型、知识服务、Office、双平台、硬件及独立助手分别记录；需要实测的没有用 mock 顶替。
E. 边界：原项目零写入、无生产密钥复制、无未授权外发/部署/固件操作。

所有可执行任务处理完但 D 存在阻塞时，可以交付本地完成部分与精确阻塞记录，不能勾选“全量迁移验收完成”。源文件迁移前已经缺失的历史数据应保留缺失声明，不能通过生成新文件假冒旧成果消除。
