# 造价智算 → 智算 Astra 功能迁移审计

审计日期：2026-10-07。本文用于代码迁移和验收交接，不代表已经替用户实施迁移。

## 一、结论

Astra 已经不是“只迁了几个模块的 UI 原型”。专业编制、工作量、经验池、结算、知识与记忆、协同表单、地图、Task/Skill 等大量能力通过冻结业务引擎和专业工作区保留。真正需要优先处理的是：新主会话路径绕开已有业务适配器、入口上下文丢失、设置没有沿全链路传递、运行宿主与源码状态不一致，以及没有关闭的真实环境门禁。[E05][E09][E17][E18]

因此，不应把旧模块整套再搬一遍，也不应把接口数量或旧版“待接入”标签当作剩余工作量。迁移单位应是一次完整业务操作：从当前任务的正确入口出发，使用正确输入和配置，运行原业务逻辑，生成同一版本的真实成果，并保留失败恢复、来源及人工确认语义。

本包提出 23 个工作包 T00—T22；它们包含审计、6 类确定或明确路径级缺口、业务回归和环境验收，不等于发现了 23 个未迁移模块。执行时发现额外真实缺口必须继续追加。

## 三、六类明确应优先修复/补接的问题

### 1. 主聊天指令语义退化，问句有触发业务副作用的风险（T02，P0）

旧 `detectZhisuanCommand` 先排除“怎么、如何、为什么、依据、来源”等问句，再识别八类业务命令。Astra `send` 使用另一套更宽泛的关键词顺序分流。以下是代码分支判断，不是用户机器上的浏览器复现记录：[E01][E02]

| 输入（任务模式） | 原指令语义 | Astra 当前可定位分支 |
| --- | --- | --- |
| 怎么运行经验池预警？ | 不判为业务执行命令 | 有结果时可能调用 warning |
| 复核到哪了 | 查询复核进度 | 命中泛“复核”，可能调用 warning |
| 执行批量匹配 | 批量匹配 | 未命中只接受特定完整文本的新规则 |
| 费用洞察 / 图表分析 | 费用分析 | 未命中新图表关键词组合 |
| 生成AI审查摘要 | 风险报告 | 不命中原对应的专门命令 |
| 输出Excel | 下载 Excel | 不命中“报告/导出/下载”的泛分支 |

处理：共享原业务命令语义，先分提问和执行；按钮、快捷项与文字指令共用执行器。不要用模型猜测用户要不要进行写操作。对应阴性用例必须证明业务写接口调用数为 0。

### 2. 批量匹配的丢响应恢复“代码复制了，主入口没接”（T03，P0）

旧 `requestBatchMatch` 会在 POST 响应丢失后查询后台状态，区分结果未知与确定失败，不自动重复提交。同一 Git blob 保留在 Astra professional 中，但 studio 主 `match` 直接调用普通 `api` POST，没有使用它。[E03][E04][E05][E06]

处理：将现有 helper 作为共享适配器，覆盖所有入口。模拟服务器已成功而浏览器没收到响应，必须恢复同一成果且 POST 只有 1 次。后台仍在执行时不能显示确定失败并诱导重复上传。

### 3. 主表同一行 AI 操作与专业工作区上下文没有闭合（T04，P1）

旧已实现表格有结构化候选和行级 AI 入口。新表只有“依据”动作，来源页再转 `analysis`；桥消息没有选中行/字段/成果版本，因此缺少可靠的同一行衔接。[E07][E08][E09][E10]

处理：新增受控 RowContext，确保 conversation、job、run/attempt、artifact version、sheet、Excel 行号和字段一起传递。可以使用新的紧凑操作菜单，不必复刻旧双按钮外观。候选确认、写回、留痕、待重算、主表刷新必须完整，且不能把旧行晚到建议写进新任务。

### 4. 新主入口未统一使用完整业务设置（T05，P1）

studio 的转换固定机械模式和“数量”过滤，风险报告只传 job；宿主对该请求默认按 DeepSeek 检查，而独立配置可以选择其他提供商。仅配置 SiliconFlow 时，这条主入口仍可能按错误提供商拒绝生成报告。主表与专业模块也有不同的偏好读取来源。[E05][E06][E08][E11][E12]

处理：逐设置列出保存位置、读取方、有效值和作用域，建立共享解析层。机械/AI 选择必须与任务快照一致；模型参数贯穿问答/风险/AI；过滤列不能无说明地固定为“数量”。不强制改默认模式，也不认为原 AI 模块没有迁。

### 5. 快捷指令自定义偏好未补齐（T06，P2）

原 `enabledIds/customPrompts/autoHide` 是不同于常见问题列表的能力。新快捷集合固定；后续记录也明确该项仍待迁。18 条常见问题编辑已经做了，应保留，不重复开发。[E13][E14][E15][E17]

处理：用 Astra 设置控件恢复启用项、自定义 prompt 和展开/收起偏好，仍经过统一安全指令层，并保存到独立作用域。

### 6. 健康接口与真实代码/连接状态不一致（T07，P0）

FastAPI 声明宿主 0.9.0，health 返回常量 0.7.0；部分兼容状态接口始终表示未连接/关闭。不是说当前新顶部状态全部错误，而是系统中仍有不一致的状态来源，无法只凭 health 200 证明当前接口已加载。[E12][E20][E24]

处理：统一构建/服务身份与能力探测；区分 configured、enabled、reachable、verified 和实际送达。启动器不能因为旧实例健康就把它当新版本。先确认活动 worktree，再做受控重启/在线新接口复验。

## 五、历史数据必须单独看

2026-10-07 导入记录表明：278 项目、310 运行、565 成果引用、823 模型调用审计已经导入；导入后总数为 290 项目、322 运行、601 成果引用。这是当时快照，不是本次实时查询。[E19]

52 条旧成果引用所指的源文件已经失效，另有 5 个过程文件引用缺失，共 57 个不同缺失路径；34 份地点档案全部为 proposed；旧协同库和队列没有被导入。不能把这件事描述为“历史项目完全没迁”，也不能声称“所有旧文件都已齐全”。缺失文件只能从真实备份恢复；旧协同记录最多按只读历史查询处理，不能恢复成待发送队列。

更重要的是，这批数据导入的是活动交接 worktree 的独立 runtime，不是当然存在于 D 盘 main。启动位置切换前必须先核查数据和配置归属。[E19][E20]

## 六、不必重复迁移，及本轮明确排除

已有且应保留：确定性计价引擎、工作量/经验/结算专业模块、文章和二维关系、已接 WeKnora、知识记忆表单、双平台复核表单、项目看板/地图、Task/Skill、原架构图、Gork 原角色、新主题、新会话与附件版本隔离、新公文组件。它们仍需按操作验收，但不再以“未开发模块”重建。[E09][E15][E16][E17][E18]

Astra 可以继续采用更好的四形态布局、紧凑 Sheet、引用卡、持久会话、来源区和主题，不必照搬旧导航、旧 Dock、旧标题/按钮位置或 CSS。用户业务目的、字段、风险与版本语义才是等价判断依据。

以下不混入旧功能漏迁：通用多智能体编排、自动将共享附件/项目背景全部索引并送模型、超过原 50 行预览的全量分页、原本未完成的正式地图能力，以及已经暂停归档的 Tauri。旧 PRD 中标为待开发的项目参数卡、前期资料完整性、额外专项规则等，必须先核源码；确实未实现的放新需求 backlog，而不是扩大本次迁移目标。[E17][E22][E23]

## 七、执行顺序与交付判断

先 T00 保护基线/数据，再 T01 建立全集，同时修 T02/T03/T07 三个主路径问题；随后 T04/T05/T06 补操作与参数，T08/T09 固化金额正确性，推进 T10—T21 各业务及外部验收，最后 T22 关闭总目标。

外部阻塞不能吞掉其他任务：缺模型凭证也要继续机械/表格/路由测试；没有实际发送授权也可以完成受控表单和离线回执契约。反过来，离线全部通过不能把真实平台、Office 或实机门禁改成已完成。

见 01-任务清单.md 获取每项实现方法/验收条件；见 03-Codex目标模式提示词.md 直接交给执行模型。所有任务初始状态为 todo，因为本包没有修改业务代码，也没有本次本地测试通过记录。
