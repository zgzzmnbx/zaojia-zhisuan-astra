## 4. 如何判定结果

始终使用**本次输出的目录**。`Codex-Temp/demo-regression/latest.json` 可辅助定位，但并发线程可能更新它；不要误读另一轮。不得拿上次24项通过的报告回答本次请求。

```powershell
# 将这里替换成这次 REPORT_DIRECTORY 输出的完整路径。
$demoRunDir = 'D:\Codex-Temp\260613-【智算Astra】\Codex-Temp\demo-regression\本轮目录'
$demoReport = Get-Content -LiteralPath (Join-Path $demoRunDir 'report.json') -Raw -Encoding utf8 | ConvertFrom-Json
$demoManifest = Get-Content -LiteralPath (Join-Path $demoRunDir 'manifest.json') -Raw -Encoding utf8 | ConvertFrom-Json
$demoReport | Select-Object status,counts,missing_gates | ConvertTo-Json -Depth 6
$demoManifest | Select-Object suite_version,ui_version,build_time,source | ConvertTo-Json
$demoReport.gates | ConvertTo-Json -Depth 8
$demoReport.cases | Where-Object status -ne 'passed' | Select-Object id,name,status
```

准备阶段失败可能没有manifest；读取已存在的报告与 `gates.runner` 即可，缺文件本身不得算通过。进程尚未结束时，初始报告可能仍是“全部未执行”；等结束后再判定。

| 结果 | 正确解释 |
|---|---|
| `passed` / 退出码0 | 所有必需自动层、执行门禁及六项人工证据均通过 |
| `incomplete` / 退出码2，D01—D24全通过、六项M用例未执行、全部门禁通过 | **自动演示功能回归通过；六项人工验收待完成**。这是正常的纯自动运行结果，不要为消除退出码2反复重跑 |
| `incomplete`，但有D用例未执行或 `missing_gates` 非空 | 自动流程未完整执行；列出缺项，不能说“自动全部通过” |
| `failed` / 退出码1 | 至少一个用例或执行门禁失败；即使用例表看起来全绿，也要检查门禁 |

本版本必需门禁为：`harness`、`api`、`contracts`、`browser`、`formal_preserved`、`module_isolation`，退出码均需0。某些外层执行工具把非零退出码统一显示为1，优先结合本轮 `DEMO_TEST_EXIT`、JSON状态及门禁判断，不能把人工待验收直接称为程序故障。

不手工修改JSON将失败改成通过，不降低断言，不把实际输出直接抄成期望答案。50000口径、1254目标单元格、52FP及两轮因子费用等基线见 [工具说明](../tools/demo-regression/README.md)，修改基线须有明确业务依据。

## 5. 失败时的最小排查路径

| 失败位置 | 先看什么 | 如何处理 |
|---|---|---|
| 准备/启动 | `gates.runner`、`host-server.log`、`digital-server.log` | 区分端口占用、缺环境、缺固定项目、构建来源不一致；不要启动/覆盖正式程序来掩盖问题 |
| API业务/标准答案 | `api.log`、`api-Dxx-error.txt`、`excel-comparison.json`、实际Excel/Word | 列出实际值与期望差异；原答案只读，不能绕过50000口径和全表差异门禁 |
| 浏览器 | `browser-results.json`、对应 `browser-Dxx.png`、失败DOM/iframe文本；必要时 `browser-trace.zip` | 区分按钮改名、任务尚未就绪、环境加载和真实业务异常；不要把超时一概认定为算法错误 |
| 接口/工具 | `contracts.log`、`contracts.xml`、`harness.log` | 工具自检会故意注入错误，结合最终测试总结果与门禁看，不能只检索单词failed |
| 文件保护/隔离 | `gates.formal_preserved`、`gates.module_isolation` | 标明哪些文件发生变化或模块退出后何处不可用；停止扩展测试，保留证据，不自动覆盖/回滚其他任务改动 |

先完成只读诊断和报告。用户另外授权修复时，按项目隔离和发布约定处理；单纯“执行完整功能测试”不等于允许修改业务程序、升级依赖或发布。修复后新建一轮，保留旧失败报告。没有新改动或明确环境恢复原因时，不反复全量重跑来碰一个绿灯。
