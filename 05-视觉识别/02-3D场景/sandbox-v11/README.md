## 启动

在仓库根目录执行：

```sh
npm ci
npm run dev:sandbox-v11
```

浏览器打开 http://127.0.0.1:5189/sandbox-v11.html 。端口冲突会停止，不会抢占其他服务。必须通过 HTTP 访问，不支持直接双击 HTML。

正式生产构建也包含此独立页面：`npm run build`，然后 `npm run preview` 并打开上述地址。`/` 仍是原工作室入口；独立预览服务不提供正式业务后端。模型通过同源 HTTP 加载，没有外部 CDN 或登录依赖。

独立开发配置只扫描沙盘入口，避免当前主线普通 Vite dev 的 MapLibre worker 依赖预优化问题；没有为此修改正式地图代码。

## 两种模式

- **V11 白色烘焙**：使用冻结的 Cycles 光照与独立渲染器。外围配景可整组关闭，微缩景深可单独关闭和调节；清晰模式保留同一烘焙颜色。
- **主线原效果**：调用 `03-Src/studio/project-sandbox/scene.mjs` 的真实 `mountSandbox`，使用主线原模型、材质和光照链路。不是给 V11 模型补几盏灯，也不是主线的“纯色棚拍”主题。此模式不增加 V11 景深。

这里只复现上述主线提交的源码默认设置，不沿用或改写用户正式工作室的个人偏好，不声称与用户设备上未知的当前设置完全一致。默认值来自 `defaults.ts`、`approvedLighting()` 和 `waterDefaults`，包括日间冷白、已确认棚灯参数、原实时水体普通档。正式主线个人设置及业务状态不受实验页切换影响。

“原效果”指模型与渲染基线，不是完整工作室 UI 的复制；独立页未接入 React 工作室的业务标签、详情和闲置自动环游调度。

两模式的场景、材质和渲染状态分开，只有当前模式活动。相机位置和目标可近似共享；正交与透视、视野和轨道范围不同，切换后不保证逐像素同机位。做画面基线验收时，请分别对照每模式自己的固定机位。

首次访问默认 V11 烘焙、配景开、景深开、强度 40%；主线原模式的新增配景默认关。各模式分别记住配景选择，切换返回时恢复本次页面内各自的相机姿态；首次进入另一模式才尝试近似对齐。

实验页仅在 `astra.sandbox-v11.preview.v1` 保存模式、两套配景开关、V11 景深和强度，不读写正式 `astra.sandbox.*` 偏好。可用以下地址固定对照条件；查询参数会更新实验页自己的保存设置：

- V11 微缩景深：http://127.0.0.1:5189/sandbox-v11.html?mode=baked&city=1&dof=1&strength=40

## 包含什么

- 7 座原始业务主体建筑，名称与分区保留；配景沿用 V09 布局。
- 139 栋外围城市建筑、35 个街区、22 段街道，以及人行道、原场地、独立地面。
- 银白管线与冷白 / 科技蓝细节；实际 Cycles 静态烘焙。
- 标准 glTF 2.0：11 个语义节点 / mesh、20 个渲染 primitives / 材质、214,968 个三角形，11 张 PNG，2 个几何数据块。
- 旋转、平移、缩放、7 区聚焦和模式切换；V11 保留俯视、远景透视、截图及可关闭的深度感知微缩景深。原模式沿用主线相机和交互约束。

目录：

- `public/sandbox-v11/model/`：V11 冻结烘焙模型、几何、贴图和逐文件 / bufferView SHA256 清单。
- `03-Src/studies/sandbox-v11/`：独立双模式预览、主线渲染适配与 V11 景深源码。
- `03-Src/studies/sandbox-v11/mode-controller.js`：互斥活动、加载竞态与每模式相机恢复；`viewer-settings.js`：隔离偏好与查询参数。
- `03-Src/studies/sandbox-v11/original-mode.js`：`createOriginalMode(host, options)` 复用原主线渲染器；`originalFactoryOptions()` 取得源码默认设置，`createOriginalContext()` 生成独立实时配景副本。
- `sandbox-v11.html`：显式访问入口，不自动进入或修改业务状态。
- 本目录 `verification/`：冻结模型清单、7 区几何身份核验、拆分无损核验与交付验收记录。
- `tools/sandbox-v11/pack-baked-model.mjs`：可独立运行的无损 GLB → glTF 拆包器。

资产包约 38.48 MB，未做几何简化、贴图缩小或传输压缩。2 个 bin 分别为 12,369,840 与 10,148,112 bytes；它们是完整几何，不是 Git LFS 指针。没有另存一份重复 GLB 或巨大的 Blender 工程。效果图是离线烘焙模型参考，不是浏览器截图。

## 原模式适配接口

`createOriginalMode` 返回 `ready` Promise 以及 `setActive`、异步 `setContextVisible`、`focusZone`、`reset`、`zoom`、`getViewPose`、`setViewPose`、`capture`、`state`、`dispose`。`focusZone` 接受 `zone_*` 或空值；`capture` 返回 `Promise<Blob>`。`ready` 表示原模型与请求的光照已就绪或进入原有降级，不代表 GPU 视觉验收。

相机姿态包含 `position`、`target`、`fov`、`viewHeight`，并带 `projection`、`zoom`、`selected`、`focus` 供页面同步；`setViewPose` 不改变选中态或材质。跨模式只近似取景，仍受原 OrbitControls 范围限制。

正式 `scene.mjs` 增加可选第十参数 `extensions`，以及配景、相机、截图、resize 接口；原 `ProjectSandbox.tsx` 调用未改，未传扩展时保留原行为。实验传入独立开场门禁与 `rememberPose:false`，不占用生产实例的开场或相机缓存，不读写正式偏好。

原模式配景只从共享 V11 模型复制 `background_city` 和 `background_street` 的几何与世界变换，私有副本移除顶点色并换成无贴图的 `MeshStandardMaterial`，不引入 `background_ground` 或主体。配景加载失败保留原场景，可以再次开启重试。切换时保留已载入实例但停用非活动模式；销毁时先解绑配景，再释放私有资源，不释放另一模式共享的烘焙资源。

## 来源与颜色契约

原始几何来自同一仓库 main 的 `05-视觉识别/02-3D场景/lighting-v2/sandbox-surface.glb`：

- 原始资产 SHA256：`b96216c89edcb285b90c15aeb787b82c151e6bf4c6e2ad7418322cbb80ef5df2`。
- 最终冻结 GLB：`Astra-Context-v11-baked-clean.glb`，38,455,656 bytes。
- 最终 GLB SHA256：`9e3805133c5ebe77c15389ed416460ac7f2b923e0eb3f4f1067a5a8ce33bc45f`。
- Blender 4.3.2 / Cycles CPU；V01–V09 增加城市配景，V10/V11 制作和修复烘焙。
- V09 → V11 的 7 区坐标、拓扑和世界变换不变，主体共 122,532 个三角形；仅拆分材质和细面 corner color。核验记录不等于生产动画兼容性承诺。

所有材质使用 `KHR_materials_unlit`。大面使用经过 AgX +0.30 展示转换的 sRGB PNG；细小面使用采样所得的同一光照结果，在线性 `COLOR_0` 中保存，材质白色且不另乘纹理。此混合编码修复小于 texel 的 UV 岛产生的黑斑，不能删除顶点色或再次应用色调映射。

运行设置必须保持 `NoToneMapping`、曝光 1、输出 sRGB，不追加 AO、阴影、雾或第二套光照。景深是运行时深度后处理，不烘进纹理；关闭时直接渲染清晰模型。

上述颜色契约只适用于 V11。主线原模式保留它自己的色调映射、光照与水效，不应改成 V11 的 unlit 输出。新增城市在原模式下采用不带 V11 烘焙颜色的独立几何和实时材质；关闭新增配景后才是接入前原主线的完整画面基线。

## 配景开关与残影边界

V11 的配景开关共同控制 `background_city`、`background_street`、`background_ground` 三类角色。关闭时隐藏城市、街道和带城市阴影的烘焙大地面，显示干净纯色地面；七座 `zone_*` 主体和 `hero_site` 场地保留。

这会移除被隐藏大地面上的城市残影，但不会重新计算已经烘进主体或保留场地中的间接光、阴影和遮蔽。完全无城市的物理一致光照需要另一套烘焙，不能只靠隐藏 mesh 获得。配景开关也不等于逐栋编辑。

## 明确边界

本版是冻结光影视觉候选，不是完整生产功能迁移：

- 独立页不接正式业务状态；七区点击只是视觉聚焦，不触发业务。主线原渲染器本身拥有的能力不等于此预览已接通生产任务、染色、装配或夜航 UI。V11 不叠加原实时射灯或夜航链路。
- 光照方向、间接光与遮蔽固定，隐藏外围城市不会重新烘焙主体光照。
- V11 水面反射和高光为静态近似，不等于主线原模式的实时 water.4 水效。
- 139 栋配景在烘焙时合并为城市 mesh，不承诺逐栋编辑 / 业务拾取。
- 目前不是性能优化包。首次加载、GPU 纹理内存和景深成本需在目标桌面设备上实测。V11 静止停帧；原模式有水体等启用动效时按主线规则绘制，离屏、后台和非活动模式停算。
- 原始中间 Blender 场景和采样缓存未放入 Git。此分支可运行和审查最终成果，但不能从 main 一键重新烘焙。拆包器仅需原始冻结 GLB，可无损重新生成发布结构，不是完整建模 / 烘焙流水线。

## 后续接入生产前的门禁

1. 保持 7 区原业务身份，并逐项设计染色、装配与烘焙材质的隔离或回退，不直接替换主线 GLB；装配等几何变化优先临时回到完整原主线路径。
2. 对日间 / 夜航、任务失败 / 取消、连续聚焦、几何归位和水效开关分别验证。
3. 验收真实 WebGL 画面、景深 shader、目标 GPU 内存 / 帧率、冷加载和释放。构建 / CPU 测试通过不能代替 GPU 验收。
4. 只有显式确认后才选择默认启用或合并，本分支不会自动合并 / 部署。
